# 移动端 UI、交互与家族视觉规范

RadishLedger 的手机工作面以快速记账、流水解释、可信同步和可恢复数据为主。交互组织吸收私人记账参考中的有效经验，整体视觉采用 Radish 家族“现代界面骨架 × 纸墨印色气质”。本篇是本项目 UI 规格来源，采用决定见 [ADR 0003](../adr/0003-ui-family-and-private-references.md)。

## 1. 来源与优先级

| 来源 | 提炼范围 | 本项目处理 |
| --- | --- | --- |
| [产品范围](../product-scope.md)与[领域模型](../domain-model.md) | 能力、金额、余额、退款和报表口径 | 决定真实功能与内容，视觉不改变账务语义 |
| 私人记账 UI 参考 | 录入效率、按日分组、账户选择、月统计下钻 | 仅保留抽象的布局 / 交互规则，不保存个人内容或参考图 |
| RadishX 的 `docs/design/family-ui/`，版本 `v26.7.3` | Profile、颜色、字体、间距、组件、状态、动效和移动转译 | 采用 Workbench；本地定义 Ledger 映射，不形成运行依赖 |
| 家族规范的参考 UI | 摘要与列表的比例、中文设置分组、浮层层级 | 观察后独立重排，不复制截图、品牌或页面组合 |

家族规范不替产品分配颜色；本项目主动采用其灰玉品牌 / 墨蓝操作参考方案。规范更新时审阅差异再升级，不自动读取兄弟仓库或覆盖本地决定。MVP 仍为单人、单账簿、CNY；参考中的多账簿、预算、年度专门报表、附件和付费功能不进入首版。

## 2. 私人参考与金融隐私

- 私人截图仅用于明确授权的本地 UI 观察；不得复制、移动或链接进仓库，不加入 Git，不进入发行包、公开设计稿、官网、Issue / PR、文档附件或公开演示。
- 原图、裁剪、缩略图、拼图、重命名副本、描摹、遮挡后的版本及含原数据的 OCR / 文本导出同受约束；打码不自动取得展示或公开授权。
- 不上传云盘、设计协作平台、生图 / 图像编辑服务，不用于模型训练或其他未授权用途。参考材料的读取授权不扩展为保存、转发或分析个人财务的授权。
- 不记录个人账户名、身份、金额、日期与交易组合、备注、截图文件名、指纹或可回溯原图的索引。本文只记录一般 UI 结构，不以真实金融内容形成例子或测试。
- 原型、截图、视觉验收和后续公开示例全部重新构造合成数据，可使用领域模型中的既有合成基线，并明确标注；不能通过替换姓名继续使用原流水。
- 私人素材保持在仓库之外。忽略规则和源码归档排除仅作误操作保护，不视为允许导入的材料目录；禁止通过 `git add -f` 绕过。

## 3. 参考经验的转译

| 值得借鉴的关系 | Ledger 的设计规则 |
| --- | --- |
| 类型、分类、账户、日期和金额键盘集中录入 | 保留一屏主路径，次要字段按需展开；明确本机保存结果 |
| 月摘要之后进入按日流水 | 使用紧凑摘要 + 日期分组列表，日期标题可扫读，金额列稳定 |
| 账户选择与余额并列 | 选择面板保留账户类型、名称和余额；使用自有通用图标，不复制银行 / 平台标识 |
| 月份选择、统计概要与明细相连 | 固定月份上下文，分类排行可下钻，返回保留筛选与滚动位置 |
| 纸质记录的段落感和数字层次 | 通过暖纸底、墨字、发丝分隔与排版转译；工作面不使用撕边、条码或贴图 |
| 日期定位与分组阅读结合 | 日期筛选按需展开，默认优先真实流水；不加入连续记账打卡或满屏热力装饰 |

最终页面的导航、组件和字段由本项目闭环决定，不以“替换颜色后的参考页面”作为交付。

## 4. 信息结构与页面职责

底部为「流水、统计、记一笔、账户、设置」五个可访问入口，其中「记一笔」是中央新建动作，其余四项为导航。新建打开编辑页，退出返回原入口并保留上下文；不建立空白的记账 tab，也不再叠加第二个常驻悬浮加号。

| 页面 | 主要结构与动作 | 必须状态 |
| --- | --- | --- |
| 模式与连接 | 本地 / 官方 / 自部署，实际目标检查 | 未开放、离线、TLS / 协议错误、需要认证 |
| 初始化与解锁 | 创建账库、恢复资料、第一账户 | 口令错误、密钥不可取、恢复入口 |
| 流水 | 月份与搜索 / 筛选 → 月摘要 → 日期分组明细 | 空、含未同步、冲突、导入范围 |
| 记一笔 | 类型、金额、分类、账户 / 日期、备注、金额键盘与提交 | 无效金额、归档引用、提交中、已保存本机 |
| 详情 | 完整金额与类型 → 字段 / 账户变动 → 编辑 / 复制 / 删除 | 另一端修订、删除冲突、整笔转账影响 |
| 账户 | 净资产 / 资产 / 负债摘要 → 按类型分组账户 → 明细 / 对账 | 负余额、含未同步候选、需重新对账 |
| 月统计 | 月份 / 筛选 → 收入 / 净支出 / 结余 → 分类排行 → 明细 | 无数据、负净支出、候选影响 |
| 设置 | 显示 → 分类 / 数据 → 同步 / 安全 → 生命周期 / 关于 | 禁用原因、不可用能力、危险操作影响 |
| 数据管理 | CSV、归档、恢复、迁移的分步说明与核对 | 文件错误、空间不足、目标非空、中断恢复 |

不展示未实现的账簿切换、资产行情、贷款 / 报销管理、广告位或会员推广。纯本地模式不需要头像、官方账号或“登录后记账”的前置页面。

## 5. 录入与明细

### 5.1 记一笔

- 支出、收入、转账、退款有明确类型入口；选择类型不只改变颜色，金额方向、字段与分类范围同步改变。退款属于首版规定类型，不被隐藏成收入。
- 默认字号的基准手机屏上，金额、常用分类、账户、日期和保存路径可直接发现。金额键盘打开即可使用，分类区可独立滚动，不用大标题 / 装饰挤出提交区域。
- 分类采用文字 + 线性图标网格，按可用宽度重排，优先常用项；两级分类层级清楚，选择态使用 action 柔底与标记，不给全部分类铺满强色。
- 账户和今天日期始终可见，标签写明含义；点击打开单一选择面板，返回不清空已输入金额。首版不展示附件、标签、优惠券或原消费关联字段。
- 金额输入显示 CNY / 人民币语义与分精度。普通事件输入正金额，类型决定方向；空值、零、大额溢出、超过两位小数和不明确格式说明错误，不截断或转零。
- 第一版金额键盘以数字、小数点、退格和提交为主，不借参考添加未设计的算术表达式、隐藏手势或交易拆分。
- 「保存」与「保存并再记」明确区分。重复点击不能重复提交；失败保留输入并定位原因。连续录入可保留账户 / 日期，清空金额 / 备注，分类默认策略需试用验证。
- 转账同时展示转出 / 转入账户并校验不同账户；信用卡还款归转账。普通退款显示实际收款账户与支出分类，不承诺原消费累计上限检查。
- 本地事务提交成功即显示「已保存到本机」，后续同步独立反馈，不等待服务器才结束保存。

### 5.2 流水与详情

日期组标题显示业务日期及清楚的日收支口径，不能把转账、期初或差额调整混入日常收支。单条内容按「类别 / 类型与摘要在左，金额在右，账户 / 备注在次级行」组织；标题与金额先可读，备注可展开。

收入、支出、退款用类型文字与资金方向辅助识别；转账展示双向账户关系和交易金额，不用单一正负符号伪装成收入或支出。数字右对齐、分位稳定，详情保留完整值；大金额不能用省略号或仅用“万”等缩写替代。

日期分组通过留白、浅分区和弱边框表达，一组一层容器；不做每条流水再套大卡片。默认不放封面大图、庆祝条幅或小票装饰。

删除 / 恢复转账时说明双方账户影响；冲突候选单独展示，不能将两个候选同时当作新增流水。返回列表保留月份、筛选与位置。

## 6. 账户与月统计

账户摘要显示净资产、资产和负债，全部遵循领域模型。账户行显示通用类型图标、名称、余额及必要状态；负余额保留真实符号，不自动变零，也不因信用卡正常欠款一律渲染错误。

账户 / 分类管理默认使用分组字段行，新增、排序与归档入口清楚。期初余额和差额调整作为专门流程，显示对账影响，不把“直接改余额”作为常规输入。

统计首屏使用一个紧凑摘要区呈现月收入、月净支出和结余，退款及毛支出可作为口径说明展开。选择月份与分类下钻共享日期、账户及类型筛选，明细合计须能解释摘要。

分类排行优先采用可带符号的水平条与金额明细，首版不依赖多色环图解释账务：净支出含退款后可能为负，负数需要真实零轴与方向，不能截零或转绝对值；占比仅在口径、分母和数值允许时显示，否则给出原因。图表必须有文字 / 明细替代，不以“颜色越多”区分类别。

本轮不增加年度专门图表、预算、日均评价、连续打卡或“支出越少越好”的趋势奖励。以后进入产品范围再设计其口径，不能从截图推定已有能力。

## 7. 家族色彩与 Ledger 语义

流水、录入、统计、账户和设置统一采用 Workbench；欢迎与关于可以少量使用 Brand 表现。大面积背景为暖纸色，主文本为墨色，品牌标记为灰玉，保存 / 确认 / 激活为墨蓝；无照片封面、玻璃胶囊悬浮导航、艳色渐变或大面积彩色分类图标。

以下是本项目采用的主题值，不表示家族强制分配。背景亮色取 Workbench 覆盖，暗色取家族 semantic.dark；其余保留对应语义。

| --- | --- | --- | --- |
| 页面底 | `bg-app`，Workbench / dark | `#f7f4ee` | `#1a1713` |
| 工作表面 | `bg-surface`，Workbench / dark | `#fffdf8` | `#23201a` |
| 次级分区 | `bg-muted`，Workbench / dark | `#f3eee5` | `#2b2721` |

| 辅助说明 / 可读占位 | `text-secondary` | `#6a5c4f` | `#b8ab9a` |
| 品牌标记 | `brand-primary` | `#5d6c57` | `#8fb3a5` |

### 用色与对比纪律

- 金融金额默认使用主文本色；收入 / 支出 / 退款 / 转账不借 success / danger 表达。消费不是失败，退款不是登录或同步成功。
- 同屏强强调色最多两组；工作面优先墨蓝操作 + 赭石图表，灰玉品牌只作小标记。必要状态色保留语义并减小面积，常态标签不滥用彩色 chip。
- 选中与状态背景使用家族 action / state 柔底，边框使用 border-soft / border-strong，状态文字使用可读的主 / 次文本并附图标。不得直接把浅 success / warning 实色作为小字号正文色。
- 暗色主操作底提亮后，按钮使用深墨字；不机械沿用家族参考的白色 `text-on-accent`。本项目基础组合的理论对比：亮色正文约 13.97:1、次文本 6.34:1、主按钮 6.84:1；暗色分别为 12.99:1、7.22:1、6.52:1。
- 参考 `text-muted` 不用于需要阅读的日期、金额、占位或状态说明；具体组件仍需按实际背景、透明度、字重和焦点检查。正文 / 字段 / 按钮至少按 4.5:1 目标检查，依据 [WCAG 对比要求](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)，计算阈值不向上取整。
- 跟随系统、亮色和暗色有完整主题映射，首屏不闪错主题；隐藏金额状态与焦点可见性不因切换丢失。

主题值通过本项目的 Flutter 主题与必要的主题扩展集中实现，组件使用语义角色，不散写原始色值，也不引用 CSS 或读取兄弟仓库作为运行依赖。引入实现时建立单一机器来源和映射验证，不能维护多份独立手填主题。

## 8. 排版、密度与组件

本节是手机逻辑尺寸基线，不能将桌面 px 或 screenshot 物理像素直接搬入 Flutter；文本必须支持系统缩放。

| 角色 | 本项目基线 | 规则 |
| --- | --- | --- |
| 页面标题 | 20–24，字重 600 | 工作面无衬线，标题不抢金额与操作空间 |
| 分区 / 日期标题 | 16–18，字重 500–600 | 日期与统计口径可分行 |
| 正文 / 字段 / 分类名 | 15–16，常规 400 / 强调 500 | 中文阅读优先，行高约 1.5 |
| 次信息 | 13–14 | 可读对比，不用极淡字隐藏关键状态 |
| 录入金额 / 关键摘要 | 28–36，字重 500–600 | 只强调当前金额，长值重排而非截断 |
| 列表金额 | 16–18，字重 500 | 等宽数字特性、右对齐、单位与精度清楚 |

- 无衬线用于全部 Workbench 内容；衬线仅可用于欢迎 / 关于的展示标题，不进入金额、表单、列表或按钮。优先系统中文字体，不新增网络字体依赖。
- 基于家族 4 / 8 / 12 / 16 / 24 / 32 间距阶梯，页面左右 16、面板内 12–16；以留白与明度组织层级，不堆卡片。
- 控件圆角 8，独立分区 / 选择面板 8–12；胶囊仅用于短筛选或状态，不把所有按钮、账户行和底栏做成胶囊。
- Ledger 的触控命中区至少 48×48 逻辑尺寸，图标可小于命中区；普通列表行基准 56–64，长文本 / 大字号允许增高，不锁死行高。
- 图标沿家族 24 网格、1.5–2 描边与圆角端点；采用一套可授权的通用图标，不从截图裁剪金融机构 / 支付品牌图标。
- 摘要与列表通常无阴影或极轻暖影，浮层才使用明显层级；禁止卡片套卡片、双层强边框、大白框套完整卡片。
- 每页一个主要动作，secondary / ghost 为低强调，danger 仅用于真正破坏性动作。禁用原因写在相关字段 / 状态区，不依赖悬停提示。
- 家族纹样在 Workbench 默认禁用；欢迎、空态、关于可用极弱自有装饰。首版不添加纸张图片、小票锯齿、条码、动画吉祥物或庆祝动效。

## 9. 选择面板、响应式与动效

账户、分类、日期和筛选使用单一底部面板或平台合适的选择页，标题、关闭 / 返回、当前选项与确认关系明确；一次只打开一层主选择，不堆叠多个抽屉。涉及未保存输入时，返回 / 手势关闭保留已有输入或说明丢弃影响，不借此增加未设计的持久化草稿系统。

以 390×844 手机逻辑视口作为普通字号设计基线，补查 320×568、横屏、放大字号、屏幕阅读器、软键盘和安全区。金额键盘、底栏和提交区不遮挡最后一条内容，底部滚动余量包含安全区与固定控件高度；滚动 / 重排优先于缩小文字。

本项目手机优先，不因家族桌面参考增加 Web / 桌面 / 平板产品承诺。较宽窗口可限制阅读列宽、适度重排已有区域，不复制桌面三栏工作台；支持矩阵仍按产品与 M0 证据冻结。

反馈 / 选择 120–200ms、面板进出约 320ms，沿用家族缓动语义。金额和余额不使用滚动计数动画，保存不放庆祝动画；尊重系统减少动效，状态在无动画下仍完整可读。按各平台实际键盘、返回和辅助技术行为验证。

## 10. 本地、同步与危险操作反馈

| 可见状态 | 视觉与动作 | 必须表达的事实 |
| --- | --- | --- |
| 已保存到本机 | 简短确认 + 流水立即更新 | 本地事务成功，不等于远端已经确认 |
| 等待同步 | warning 柔底 / 时钟 + 待处理数 | 本地可继续使用，保留未同步事实 |
| 正在收发 | info / 小进度 + 当前动作 | 不阻塞本地录入，不猜测完成百分比 |
| 已完成收发 | success 图标 + 最近完整同步时间 | 仅用于实际确认完成，不隐藏候选 / 隔离状态 |
| 需要处理冲突 | warning 或阻断时 danger + 入口 | 保留双方候选，解释所选版本及余额影响 |
| 连接 / 授权失败 | 对应原因 + 明确下一步 | 保留可读本地数据，不清空列表或默认换端点 |
| 只读 / 归档 / 迁移冻结 | neutral 标签 + 原因 | 操作受限但数据事实仍可解释 |

重要失败和恢复信息不能仅靠自动消失 toast。普通保存提示不占据整屏；错误要定位到字段或实际失败步骤，重试不重复产生交易。

新设备明确区分服务登录与账库解锁，说明管理员不能找回解密材料；恢复资料明确不能代替数据备份。换服务器显示实际源 / 目标和核对结果，输入地址不自动迁移。

删除 / 清本机 / 删远端 / 注销分别显示目标、影响、未同步事实和可恢复性。财务数值为负不自动使用 danger；只有真正失败、破坏性操作或阻断状态进入危险语义。

锁定或进入后台时遮挡敏感任务切换预览。隐藏金额覆盖摘要、列表、账户、图表 / tooltip 与辅助技术输出，避免通过另一条通道泄露；该选项只是展示保护，不能称为加密。默认不把秘密复制到剪贴板，也不自动生成分享图。
