# 许可与分发策略

RadishLedger 延续 Radish 应用中的源码可见策略，同时把个人免费自部署写成直接授予的权利，避免“自部署优先”产品却要求每个用户先申请许可。具体授权以[根 LICENSE](../LICENSE)为准。

## 1. 明确允许的个人使用

个人可以获取源码、私有复制、构建、安装、使用、自部署和为自己的实例私有修改，不需要申请、支付、官方账号或在线激活。为自己的实例购买 VPS / NAS 不等于对外提供商业服务。

许可证不按个人的设备或账簿数量收费。产品当前只有一个账簿是功能范围，不是许可席位限制。个人就业 / 自营活动的私人记账仍属允许使用。

## 2. 独立授权范围

商业托管、为其他人提供受管部署、组织共享记账、代码 / 二进制再分发和修改版公开分发需单独授权。家庭共享等后续产品功能进入范围时同步评审许可，不能把规划功能当成已授予服务权。

该授权不是开放源码许可证，不以“开源”宣传。源码可阅读与开放源码不是同一含义，参见 [Open Source Definition](https://opensource.org/osd)。

## 3. 数据与互操作

用户自己的账务数据可以自由备份、导出、迁移和独立处理。软件许可不限制数据所有权。

公开同步与归档规格，允许根据公开格式独立实现互操作；这不等于复制本项目实现代码、使用商标或重新发布整个文档获得授权。

协议、数据格式和源代码是不同授权对象。以后独立发布 SDK / schema 若采用其他许可证，需要显式文件，不推定整个仓库改变许可。

## 4. 第三方与贡献

第三方原有许可证和 notices 保留，不能用本项目许可证重新限制它们。具体 RustCrypto、SQLCipher、Flutter 组件和打包资产在引入依赖时核对。

贡献许可沿用根许可证，提交者须有权提供内容；外部贡献与再分发权限分别处理。安全反馈不提交真实账单或秘密。

## 5. 官方客户端与服务

官方可以分发由项目所有者发布的客户端和自部署包，来源、签名、版本和依赖 notices 可查。非官方修改不得冒充官方产品。

官方托管计费、商标、支持和隐私条款在公开运营前形成独立文件；个人自部署和数据迁出不通过官方订阅激活。商业化决定不静默改写已有版本授予的个人使用权。
