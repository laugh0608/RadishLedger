# MVP 路线图与验收

按可持续使用的用户流程推进，先验证高风险边界，再扩展页面。R01–R12 的完整功能定义以[产品范围](product-scope.md)为准，本文件定义顺序与退出条件。

## 1. 里程碑

| 阶段 | 交付重点 | 退出条件 |
| --- | --- | --- |
| M0 设计与风险验证 | 账务、同步与密钥规格；移动端双端最小接入；UX 主流程 | 边界可评审，Android / iOS 核心调用、加密库和系统密钥真实可用 |
| M1 本地可用 | Android 日常录入、账户分类、流水月报、本地加密、CSV 和独立归档 | 离线持续使用；杀进程与重启不丢；空目标恢复金额一致 |
| M2 双端与自部署 | iOS 完整客户端、Go 后端、双端 E2EE、冲突、设备 / 会话及自部署运维 | 两部真机完成正常与故障同步，独立服务器备份恢复 |
| M3 第一版公开 MVP | 官方邀请制端点、迁移、密钥泄露处理、删除、升级、发行和试用 | R01–R12 全部有对应证据，官方与自部署分别验收 |

M0 的验证实现、工具链变更和设备操作分别按对应任务授权执行。M1 不代表只保留 Android 产品：iOS 工具链与关键 native 依赖在 M0 就要验证，完整页面在 M2 接通。

官方端点尚未可用不阻止独立验收 M2 自部署，但 M3 的公开双端点承诺必须两侧分别完成。不能把两个合成服务叫作官方与自部署均已交付。

## 2. M0 工作包

| 顺序 | 成果 | 需要关闭的问题 |
| --- | --- | --- |
| M0-A | 账务与 UX 规格 | 金额、日期、退款、对账、空状态与恢复路径 |
| M0-B | Android / iOS 最小核心接入 | FFI 所有权、线程、异常、release 打包与依赖许可 |
| M0-C | 加密与系统密钥验证 | SQLCipher 真正启用、WAL / 临时文件、KDF 耗时、密钥失效 |
| M0-D | 同步事务规格 | envelope、CAS、幂等、域隔离、恢复代次和删除 |
| M0-E | 数据可迁移规格 | CSV、认证归档、恢复暂存与新端点身份 |

移动桥接方式、具体依赖版本、最低系统、KDF 参数、HTTP schema 和备份格式在上述验证后通过 ADR 冻结。方向已确认不代表这些细节可以跳过验证。

工作包按实际依赖安排，不将设备等待转换为无限追加实验工具。可在保留 M0-B / C 真机缺口的同时，推进不依赖该结果的 M0-D / E 语义、共同样例与验证设计；依赖未决平台 / 密钥结论的字段和方案不得提前冻结。每次开发应完成一个有明确行为、失败处理和验证依据的功能或规格成果，再安排下一项；工作包有进展不等于 M0 已退出。实际顺位只在 current 维护。

M0-A 的复核材料路由为[首笔记账与关键状态规格](design/mobile-experience.md#12-首笔记账与关键状态规格)、[共同账务样例](validation/accounting-cases.md)和[两端核心验证矩阵](development/mobile-core-validation.md)。本批规格退出要求为：正常 / 取消 / 失败 / 结果未定路径可复核，数值预期有单一来源且已独立复算，后续两端风险验证有动作、停止线和证据要求。设计稿走查和实现验证分别记录，不能从文字齐全推定录入体验或核心已通过。

## 3. 用户流程与阶段归属

| 流程 | 主要阶段 | 发布前证据 |
| --- | --- | --- |
| 新用户本地记第一笔 | M1 | 无账号、无网络完成 |
| 账户转账和退款后的月报 | M1 | 合成账务结果逐项一致 |
| CSV 导入、重复提示和批次中断 | M1 | 不误删合法重复，不发布半批次 |
| 独立加密归档恢复 | M1 | 原手机 / 原服务器不可用也能恢复 |
| 两端离线修改后同步 | M2 | 新增合并、修改冲突与删除不复活 |
| 自部署安装、备份和恢复 | M2 | 干净实例与独立恢复目标 |
| 同包连接官方和自部署 | M3 | 实际目标、账号隔离和凭据隔离 |
| 更换服务器、升级和密钥重建 | M3 | 可中断恢复，未同步事实保留 |
| 注销与旧服务器备份恢复 | M3 | 删除要求重新应用 |

## 4. 发布验收场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| T01 | 飞行模式记账后立即结束进程 | 重启后流水与 outbox 同在，余额一致 |
| T02 | 服务端提交成功但响应丢失 | 原操作重试，只有一次业务效果 |
| T03 | 两端同时改同笔金额 | 双方候选保留，可解决且最终余额一致 |
| T04 | 删除与修改并发，旧设备重连 | 不静默复活或丢修改；恢复是明确新修订 |
| T05 | 转账写入 / 编辑 / 删除中崩溃 | 无单边转账，投影可重建 |
| T06 | 跨月普通退款与信用卡还款 | 符合领域口径，不重复计支出 |
| T07 | 设备时间偏移与旅行换时区 | 不影响冲突胜负，历史业务日期不变 |
| T08 | 解锁 / 备份口令错误、密钥损坏 | 明确失败，不展示为空账簿或生成新钥覆盖 |
| T09 | 生物识别失效、系统密钥不可取 | 可用独立解锁材料恢复本机未同步数据 |
| T10 | 撤销会话和密钥泄露重建 | 后续新密钥数据隔离，旧设备不直接写回 |
| T11 | 抓包、DB、WAL、缓存与日志检查 | 无非预期账务明文或秘密；篡改认证失败 |
| T12 | 极端 envelope、KDF、批次与压缩尺寸 | 有界拒绝，不无限资源消耗或部分应用 |
| T13 | 账号 / 账库跨域访问 | 每个路径均拒绝越权，不以 E2EE 代替访问控制 |
| T14 | 切换实例时旧响应迟到 / ID 相同 | 不串凭据、密钥、队列、游标与删除状态 |
| T15 | 旧备份恢复导致服务端回滚 | 代次变化被识别；待同步事实保留并进入对账 |
| T16 | CSV 重复、错误、中断与受限撤销 | 结果有预览；撤销不清除后续引用或修改 |
| T17 | 空白设备从完整归档恢复 | 笔数、余额、关联、候选与删除状态核对 |
| T18 | 迁移中断、源失联、目标非空 | 不双写、不覆盖；明确不完整副本范围 |
| T19 | 服务 / 客户端版本不兼容 | 阻止不安全远端写入，继续本地使用 |
| T20 | 官方服务下线 / token 过期 | 本地与兼容自部署可用，无静默 fallback |
| T21 | 注销后从旧运维备份恢复 | 删除控制记录重应用，旧账号不重新开放 |
| T22 | 新实例安装与升级失败回退 | amd64 / arm64 分别验收，数据版本匹配 |
| T23 | 锁定、后台与大字号 | 敏感预览遮挡，关键按钮可用，状态准确 |

R06 / R07 主要由 T01–T05、T14–T15 验证；R08 由 T08–T12 验证；R09 / R10 由 T16–T18 验证；R11 / R12 由 T13、T19–T22 验证。R01–R05 同时需要真实两端主流程和数值验收。

## 5. 质量与试用

阶段门槛包含账务规则、状态机、真实 PostgreSQL 事务、两端构建、真机密钥行为和恢复演练。加密协议与生命周期在公开发布前安排专项安全评审，严重余额错误、丢账、越权、明文泄露或不可恢复升级未关闭不得发布。

性能目标引用产品范围，不复制数值。测试记录要包含设备型号、系统、构建、协议 / schema / 密钥版本、服务器与网络条件；模拟器与真机结论分别标明。

邀请试用以“能否作为主力账簿、是否理解同步状态、能否独立备份恢复”为重点。收集经用户确认的脱敏诊断和反馈，不以真实账单做默认埋点。

M0 结束后根据验证结果和实际投入重新估算工作量。功能后置优先选择多账簿、预算、年度图表和专用导入；不以暂时明文、删除恢复路径或静默覆盖冲突缩减工期。
