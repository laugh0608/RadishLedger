# 产品规划与范围

RadishLedger（萝卜账簿）是一款面向个人的本地优先记账产品，提供 Android / iOS 官方客户端、官方同步端点和自部署后端。目标是让用户长期掌握账务事实，并在离线、换手机、换服务器或服务停止时仍能使用和迁出数据。

## 1. 用户、问题与价值

首要用户是已有日常记账习惯、关心隐私与数据归属的个人。自部署用户可能使用 NAS、家庭服务器或 VPS；官方托管服务面向希望省去服务器维护的人。

优先解决的问题依次为：

1. 流水不丢、余额正确且能够解释。
2. 日常录入足够顺手，离线也能保存。
3. 多端修改可靠收敛，冲突不被隐藏。
4. 数据可导出、可验证恢复，服务商可替换。
5. 自部署能够安装、连接、备份、升级和退出。

第一版不承担企业会计、报税、银行账务或投资交易系统职责。家庭共享是后续独立产品能力，不从个人同步顺带扩展。

中文移动端流程、可靠的恢复与迁出、同包选择端点是需要通过真实试用验证的差异。已有自部署财务产品可作为研究对象，不能据此宣称 RadishLedger 已具有独有功能或市场优势。

## 2. 产品模式与术语

| 模式 | 身份与网络 | 数据路径 |
| --- | --- | --- |
| 纯本地 | 无需注册或联网 | 加密本机账库与用户独立备份 |
| 官方同步 | 在官方实例认证 | 本机账务 + 官方密文服务 |
| 自部署同步 | 在用户选择的实例认证 | 本机账务 + 自部署密文服务 |

首次进入可以先本地使用，之后显式启用同步。已经解锁过的本地数据在离线或登录失效时仍可使用；认证与远端下载需要网络。

固定术语：

| 名称 | 含义 |
| --- | --- |
| 登录账号 | 某服务器实例上的访问身份 |
| 账库 Vault | 数据、密钥与同步隔离容器 |
| 账簿 Book | 账库内的记账空间；第一版只有一个 |
| 资金账户 Account | 现金、银行卡、钱包、信用卡等账务对象 |
| 服务实例 Instance | 实际连接的后端身份，不等于 URL 字符串 |
| 同步域 Sync Domain | 实例内一份账库的同步身份与代次 |

每台客户端同时只有一个活动账库，一个账库只有一个活动同步端点。不同时向官方和自部署双写。退出或切换可保留隔离的本地档案，不提供多账号并行聚合。

服务端目标支持多个独立账号，每个账号拥有独立账库；个人客户端不提供用户间共享。自部署可默认关闭注册，仅使用一个用户，但代码与数据库授权边界不能以全局单用户 token 代替。

## 3. 长期产品目标

| 方向 | 目标 |
| --- | --- |
| 个人账务 | 快速录入、可靠余额、分类与清楚的收支口径 |
| 多端 | Android / iOS 等价能力，未来按需求扩展桌面 |
| 隐私 | 本地加密、默认 E2EE、最小化元数据、无广告追踪 |
| 数据自主 | 公开格式、完整恢复、服务器迁移与生命周期删除 |
| 自部署 | 独立运行、可信 HTTPS、可重复部署与升级恢复 |
| 托管服务 | 同协议的省心运维、备份与支持 |
| 后续增强 | 多账簿、预算、附件、周期记录与受控共享 |

Ledger 独立于其他 Radish 产品。未来跨产品联动须有明确用户需求与数据授权，不共享业务数据库、主密钥或默认外发权限。AI 若进入产品，只能提供建议，不自动改变账务事实。

## 4. 第一版公开 MVP

公开 MVP 是 M3 完成后的产品，M1 本地版与 M2 自部署测试版不能替代完整承诺。首版固定为单人、单账簿、人民币 CNY；资金账户可有多个。

| 编号 | 必需能力 | 边界与完成含义 |
| --- | --- | --- |
| R01 | Android 与 iOS 官方客户端 | 手机优先；两个平台完成真实发行构建与主路径验收 |
| R02 | 三种模式与端点连接 | 同包运行时选择；身份、TLS、能力检测；旧响应不污染新域 |
| R03 | 基础账务 | 支出、收入、转账、普通退款、编辑、删除与恢复；单笔单分类 |
| R04 | 账户与分类 | 多个资金账户、期初余额、差额调整、归档、两级收支分类 |
| R05 | 流水与月统计 | 本地日期 / 金额 / 类别 / 账户 / 备注查询；月收支、分类排行、净资产 |
| R06 | 本地可靠性 | 原子写入与待同步队列；离线、杀进程、重启后事实保留 |
| R07 | 多端同步 | 增量、幂等、条件更新、删除防复活、冲突候选与处理入口 |
| R08 | 隐私与加密 | 本地加密、默认 E2EE、锁定、生物识别、独立恢复材料、密钥泄露处理 |
| R09 | 导入导出 | 通用 CSV、映射预览、明确错误、重复提示、批次恢复与受限撤销 |
| R10 | 完整数据恢复与迁移 | 独立加密归档、空白设备恢复、空目标服务器迁移和结果核对 |
| R11 | 服务交付 | 自部署 + 官方邀请制端点；权限隔离、备份恢复、版本升级和兼容说明 |
| R12 | 生命周期与运维边界 | 退出 / 清本机 / 删远端 / 注销区分；删除记录与运维备份生命周期 |

退款是实际到账时发生的独立冲销事件，减少当期相同分类净支出；原消费关联、累计退款上限、自动报销联动和跨对象并发约束后置。详见[账务模型](domain-model.md)。

分类可自定义和归档；第一版不做分类合并、标签体系、自定义封面上传或拆分交易。CNY 的精度为分，格式仍保存币种和精度；不能通过改币种符号重新解释历史金额。

## 5. 后置范围与演进顺序

| 顺序 | 能力 | 进入条件 |
| --- | --- | --- |
| 优先增强 | 钱迹等来源的专用导入 | 有获得授权的脱敏导出样本，映射与恢复可信 |
| v1.1 候选 | 多账簿、月预算、年度专门图表、周期模板 | 首版持续使用与同步 / 恢复稳定 |
| 后续独立设计 | 附件、复杂关联退款、借贷和报销 | 独立评审事务、同步、加密与生命周期 |
| 后续独立设计 | 家庭共享 | 权限、成员撤销与群组密钥方案重新评审 |
| 需求驱动 | 多币种、桌面 / Web、自动记账、银行连接、AI | 明确用户价值和可维护的平台边界 |

上述为排序方向，不是日期承诺。首版不读取短信、通知或无障碍数据，不引入支付 SDK、广告、插件市场、投资行情或复杂订阅系统。

未来多账簿的默认方向为独立账户和分类；在明确跨账簿账户去重与资产口径之前，不把多个账簿余额直接累加为个人总资产。

## 6. 日常使用闭环

首次打开 → 选择本地或同步模式 → 创建 / 解锁账库 → 创建资金账户并确认期初余额 → 记第一笔 → 查看流水与余额 → 创建独立备份。

常用记账 → 金额键盘直接可用 → 选择类型和分类 → 使用可见的默认账户及今天日期 → 本地保存 → 显示“已保存到本机” → 解锁且在线时异步同步。

同步设置、恢复资料和备份不应妨碍每笔录入。安全操作通过独立流程完成，不能把“隐藏金额”或“服务登录成功”显示为数据已经安全加密或同步。

## 7. 非功能目标

下列是待实测目标，发布前需固定 release 构建、基线设备、网络和服务器配置。

| 维度 | 目标 |
| --- | --- |
| 录入 | 熟悉流程后，常见支出约 5 秒完成；默认值可见且可修改 |
| 本地反馈 | 常规保存 P95 ≤ 200 ms，不包含首次解锁 |
| 数据规模 | 5 万笔合成交易，月统计与常用查询 P95 ≤ 1 s |
| 前台同步 | 双端已解锁、RTT 约 100 ms、服务正常时，普通单笔变更 P95 ≤ 10 s |
| 离线可靠性 | 至少连续离线 7 天，恢复网络后无静默丢账或重复 |
| 可访问性 | 大字号、深浅色和屏幕阅读器覆盖主要操作，金额不只靠颜色表达 |
| 可恢复性 | 空白手机与独立服务器分别恢复，笔数、余额、关联和删除状态核对一致 |
| 可部署性 | 干净 amd64 与 arm64 环境完成安装、双端连接、备份和升级 |

锁屏后台运行受平台调度，不承诺固定秒数；首版产品承诺为“联网并打开解锁后自动同步”。支持的最低系统版本以 M0 依赖验证和后续真实设备矩阵冻结。

## 8. 许可、隐私与商业策略

采用源码可见模式，个人可免费构建、私有修改和自部署，无需逐个申请授权或访问许可服务器。根许可证是授权来源，不以“开源”宣传。公开协议和数据格式允许独立互操作，具体边界见[许可策略](licensing-strategy.md)。

官方托管的长期价值来自稳定运维、备份和支持。首版邀请制试用与基础配额先行，不建设复杂付费 / 促销系统；收费与商店规则在商业化前单独设计。

核心记账、自部署、加密、导出和恢复不被官方订阅开关控制。默认无广告和跨应用追踪，不上传明文分类、备注或交易做产品分析。

产品验证先使用小规模访谈、用户主动反馈和脱敏诊断。建议邀请 10–20 位已有记账习惯的试用者，覆盖两个平台和自部署，观察至少两周的录入、同步理解及恢复体验。留存率可观察，但小样本不被当作市场结论。

## 9. 关键风险与控制

| 风险 | 控制方向 |
| --- | --- |
| Rust / Flutter / SQLCipher 移动端接入成本 | M0 两端最小验证，冻结依赖与桥接边界后再铺页面 |
| 余额或统计口径错误 | 明确合成账务样例与跨语言共同测试材料 |
| 同步重复、丢失或删除复活 | 幂等、条件提交、冲突保留、故障注入与旧设备验证 |
| 手机丢失或密钥无法恢复 | 独立恢复资料、备份归档、真实密钥失效场景 |
| 换端点导致分叉或秘密串用 | 实例隔离、显式迁移、单活动端点、迟到响应验证 |
| 官方服务误用单用户模型 | 所有请求账号 / 账库归属校验，官方多用户隔离单独验收 |
| 多产品维护负担 | 小纵向切片、共享规范先行、暂不抽取通用平台 |

范围不以预计工期反向裁掉恢复、加密和可靠同步。M0 完成后按实际任务与可投入时间重新估算，不在验证前给固定上线日期。
