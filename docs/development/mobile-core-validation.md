# 移动端核心接入与加密验证矩阵

本篇将[架构](../architecture.md)与[威胁模型](../privacy-threat-model.md)落实为 M0-B / M0-C 的验证要求。账务共同输入见[合成样例](../validation/accounting-cases.md)，UX 结果见[移动端规格](../design/mobile-experience.md)。这里定义动作和证据，不记录一套独立的当前进度；实际结果与下一步统一进入[当前状态](../status/current.md)和月度 devlog。

## 1. 验证目标与执行条件

最小纵向目标是：Flutter 发起调用 → Rust 校验 → 加密本机事务保存事实与 outbox → 返回明确本机结果 → 核心查询余额 / 月报 → 锁定和重新解锁后读取同一事实。使用合成账户与共同案例，不为接入实验铺完整页面或接入 Go 服务。

验证实现开始前先只读盘点已有工具链与设备，列出候选、锁定版本、下载 / 安装 / 构建影响及预计资源；随后在相应实施授权下引入最小工程和真实检查。不得顺手更新全局工具链、设置证书或操作用户已有系统密钥。设备写入、安装测试包、创建测试系统密钥和长驻进程需要明确目标、归属与清理方式。

两端使用同一 Rust 规则；在 Android 模拟器通过不能代替 Android 真机，iOS Simulator 通过不能代替真机。具体设备、最低 OS、ABI 范围、桥接版本、密码依赖和 KDF profile 根据实际证据冻结，不能把矩阵中的待填值当成支持承诺。

### 工具链、设备与依赖记录

| 记录项 | Android | iOS | 接受依据 |
| --- | --- | --- | --- |

| 辅助目标 | 开发模拟器的 ABI、系统和宿主信息 | Simulator 的架构、系统和宿主信息 | 只用于对应环境开发，不外推真机密钥能力 |

记录真实版本时核对官方文档和许可证，明确采用的发行方式与再分发义务。版本、许可或平台条件不满足时停止该候选，不能降低已有保护或另造并行账务核心。

## 2. M0-B：桥接与最小核心接入

每个 B 项都在 Android 与 iOS 分别记录结果；无法在某个目标运行时标记环境和缺口。debug 包不能替代 release 包，静态链接成功不能替代实际调用。

| ID | 动作 / 故障 | 必须看到的结果 | 证据 |
| --- | --- | --- | --- |
| B01 | 两端构建并安装最小 release 包 | Native 核心随包加载，创建 / 查询真实调用可用，重启仍可加载 | 目标、构建命令、包与核心版本、实际调用记录 |
| B02 | 候选 bridge 执行同一小接口和输入 | 金额字符串、中文 / Unicode、空值与无效编码有明确边界；A01 / A09 结果一致 | 两候选的平台结果、生成物来源、编码 / 所有权说明 |
| B03 | 重复分配 / 释放、异常返回与取消 | 所有权、缓冲区释放、重复释放拒绝明确，无悬空句柄 / 多次释放；没有持续资源增长 | 可重复压力动作、资源观察及工具限制 |
| B04 | 合成 panic / native 错误 / ABI 不兼容 | 不以默认成功或空列表返回；不让 panic / 异常穿越未定义 ABI；兼容失败可解释 | 故障入口、结构化错误、进程与调用结果 |
| B05 | 多次并发保存 / 查询、KDF 和 IO | 写入串行事务边界有效，UI 可响应，输入错误与运行错误分开 | 并发 / 线程记录，实际 UI 响应与事务结果 |
| B06 | 连点、重复回调、结果返回前终止等待或进程 | 同一意图只提交一次；明确未提交 / 已提交 / 未定；跨重启能核对操作结果 | 操作身份、事实 / outbox 集合及重启观察 |
| B07 | 在事实与队列写入之间、提交前后中断 | 事实与 outbox 同在或同无，转账只有完整旧 / 新状态；本机成功只在事务持久化确认后返回 | A01 / A04，实际故障点、DB 事务和重启核对 |
| B08 | 编辑 / 删除 / 恢复，候选或观察版本变化 | A04 / A05 / A07 / A08 / A10 数值与事实一致；过期预览先核对，候选不重复入账 | 核心结果、选中版本、保留候选及界面状态 |
| B09 | 重启、锁定再解锁、迁移失败或库不可读 | 保留已提交事实，损坏 / 失败不展示为空账簿，不新建库覆盖旧文件 | 合成 DB、副本、错误分类、前后事实清单 |
| B10 | 输入边界、归档和缺少引用 | 金额 / 日期 / V 输入按共同材料接受或拒绝；拒绝不留事实或队列，计算越界显式失败 | 输入与预期差异；不只断言返回码 |
| B11 | 审阅最终包内 native / generated 资产与依赖 | 许可可接受，生成入口可追溯；包不依赖兄弟目录、开发机路径或未声明库 | 依赖 / notices 清单、构建与资产检查 |

桥接比较只需要支撑上述边界的最小接口：初始化 / 打开合成账库、保存、查询、锁定 / 关闭和结果核对。两个候选共用 Rust 领域代码与样例，不各写一套核心，不提前规定最终函数名、完整 DTO 或目录层级。选型结论说明安全边界、生成与调试成本、release 体积 / 构建复现和维护取舍，经 ADR 固定采用方式。

M0-B 的阶段退出需两端真机 release 核心调用、B 项相关边界与依赖许可证据；某候选被实测排除可记录原因，不要求继续发展两套 bridge。用于加密 / 密钥的接口要能承接 C 项，不能把临时明文库当作可进入 M1 的存储基线。

## 3. M0-C：加密与系统密钥

每个 C 项都记录 Android / iOS 的实际实现与保护等级；算法向量是核心验证，设备失效和后台行为必须在对应真机验证。所有测试秘密只在隔离实验内生成，日志与交付只记录结果，不记录秘密值。

bootstrap、受保护的跨进程解锁与独立恢复的实验实现及复现契约见[实验专题第 7 节](mobile-core-prototype.md#7-m0-c-bootstrap解锁与独立恢复方案)。它将下面的 C 项拆成可执行流程和中断点；不改变本矩阵的正式退出条件。删除隔离测试项只证明“项缺失”的恢复，不能代替真实锁屏 / 生物识别变化；设备不支持日常认证保护时如实记录，不切换到较弱项制造通过。

| ID | 动作 / 故障 | 必须看到的结果 | 证据 |
| --- | --- | --- | --- |
| C01 | 在最终 release 包建库、写共同数据、关闭并检查 | 实际启用 SQLCipher，普通 SQLite / 错密钥不能读取；正确密钥读取原事实 | 库 / features 识别、正反向打开、文件结果；非仅扩展名变化 |
| C02 | 写入、回滚、checkpoint、排序 / 临时查询、崩溃与导出 | DB、WAL、回滚日志、临时文件、索引与缓存无非预期明文；各路径受保护 | 实际文件清单、生成条件、合成明文标记检查与停止条件 |
| C03 | AEAD / HKDF / KDF 向量及认证篡改 | 选定实现符合独立向量；AAD / 密文 / 参数篡改拒绝，无未认证输出 | 向量来源与版本、正反向结果；不由同一实现自制预期 |
| C04 | KDF 候选 profile、错误口令、极端参数与取消 | 真机时间 / 峰值内存可接受，界面可响应；资源有界拒绝、无静默降强度；取消结果明确 | release 设备、profile、统计样本与上 / 下界拒绝 |
| C05 | 首次创建、重启及部分 bootstrap 写入失败 | 解锁所需封装不只在加密 DB 内；完成状态明确，失败不覆盖既有材料 | 各中断点、可恢复阶段、旧 / 新文件身份核对 |
| C06 | 日常系统解锁：正常、取消、拒绝、暂不可取、不支持 | 不同原因可解释，取消不误报失效；保护等级按能力报告 | 对应真机条件与平台错误映射、实际 UI 结果 |
| C07 | 隔离测试系统密钥 / 生物识别保护项失效 | 以独立解锁材料读取原 DB 和未同步事实，不生成新钥替换旧库 | 失效方式、A01 事实 / 队列前后对比和恢复路径 |
| C08 | 错解锁口令、错误恢复材料、封装缺失或损坏 | 明确失败并保留文件；无空账簿、无零余额“成功”，不将服务登录当作解密 | 失败分类与未改动证明；实际材料缺口 |
| C09 | 锁定、后台、任务切换、未完成写入 / 长任务 | 遮挡敏感预览、清理可控明文与会话，暂停需密钥工作；已提交事实保留，晚回调不泄露明文 | 真机录像 / 状态记录（合成数据）、核心 / UI 生命周期核对 |
| C10 | 剪贴板、分享、日志、崩溃输出与辅助技术 | 无默认秘密复制、账务或秘密日志；隐藏金额覆盖各可见 / 可读渠道 | 明确检查渠道与实际限制；不宣称绝对内存清零 |
| C11 | 本机备份 / 新设备恢复、重装后的材料可用性 | 不依赖系统密钥自动跨设备复制；恢复资料与完整归档用途明确，无秘密默认云备份 | 隔离设备 / 测试容器范围、平台配置及实际恢复限制 |
| C12 | 独立解锁成功后重新建立日常保护 | 先读取并核对原事实，再替换测试保护项；失败保留可恢复路径 | 未同步事实、密钥封装与切换前后身份核对 |

C02 的明文标记搜索只是其中一项证据，未搜到字符串不能独自证明密码正确。C03 的算法正确也不证明 KDF 强度、密钥生命周期或整个产品安全；公开发布前仍需专项评审。归档完整格式与空白设备保真恢复在 M0-E / M1 单独验证，C11 不提前宣称归档已可用。

M0-C 退出需两端实际加密库、文件边界、系统密钥失效后的独立本机恢复和可评审的 KDF 资源证据。Android / iOS 策略可以适配平台能力，但不能降级为明文或删除独立恢复路径。

## 4. 单项证据格式与清理

每个验证项至少记录：

- ID、Git commit、bridge / 核心 / DB / 密码依赖版本、release / debug 和构建参数。
- 平台、设备或模拟器、OS / ABI、保护等级与相关前置条件；未具备的目标明确列出。
- 合成案例版本、动作顺序、故障点、预期、实际结果及差异；成功、失败、未执行、环境受限分别标记。
- 结果证据的位置、是否含敏感信息和可保留范围；原始文件 / 包 / 运行证据留在被忽略的本地证据位置，正式文档仅保留可公开的合成摘要。
- 本次创建的测试 App / 容器、系统密钥项、进程、端口和临时资源；清理只针对确认归属的精确对象，不能清除用户账库、全局证书或其他任务资源。

没有实际执行证据的行不能标记通过；适用性判断需要写原因，不能用整列 `N/A` 跳过一个平台。出现签名 / SDK / 网络 / 权限阻塞时保留命令与限制，按同一已授权目标申请必要最小权限，不改变系统信任来制造通过。

## 5. 后续冻结和阶段衔接

| 冻结材料 | 所需证据 |
| --- | --- |
| bridge、ABI 边界与最小依赖 | B01–B06、B10–B11，两端 release 和同一输入 / 错误结果 |
| 支持系统 / ABI 矩阵 | 候选最低系统、实际目标的构建与运行记录；缺少真机覆盖的范围明确保留 |
| SQLCipher 链接、文件和升级策略 | B07 / B09、C01–C02、C05，不将明文临时方案带入 M1 |
| 日常系统密钥与独立本机恢复 | C05–C12，两端取消 / 失效 / 重启 / 后台的实际结果 |
| KDF profile、资源边界和错误语义 | C03–C04 / C08 的向量、真机资源与负向结果 |

对应 ADR 记录采用、排除原因、影响与未验证范围；实际实现同步正式契约和真实检查入口。M0-D 再细化同步条件提交、幂等、代次、删除与迁移冻结，M0-E 再冻结 CSV / 认证归档 / 暂存切换，均复用共同样例。M0-B / C 的最小运行证据不能替代这两项，更不能直接宣布 M1 或公开 MVP 完成。
