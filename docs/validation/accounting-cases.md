# 共同账务样例与验收方法

本篇说明[合成样例 JSON](accounting-cases.json)的用途和复核方式；账务语义仍以[领域模型](../domain-model.md)为准。具体输入和人工预期只在 JSON 维护，本篇不复制金额结果。

## 1. 来源与使用边界

材料完全人工构造，与私人账单、截图、生产账号或密钥无关。`A01` 承接原有正式领域基线，其余案例从已接受的事件和版本语义推演；日期、名称、身份和组合也为合成。

`fixtureVersion: 1` 是验证材料结构的版本，`dataOrigin: synthetic` 标识数据来源。它不是产品版本、FFI ABI、envelope、DB 或归档 schema。案例里的符号 ID 用于阅读和测试映射；生产身份仍按正式规格随机生成，各测试 adapter 记录其映射，不把这些短名称当作生产 ID 格式。

预期值由人工维护，不由待测生产实现生成。Rust 核心、Flutter 展示和后续同步 / 迁移 / 恢复分别消费同一材料：Flutter 核对核心返回值和界面映射，不再实现一套生产账务公式。新增行为先在领域专题说明，再添加有区分力的案例；不得为适配错误实现而修改预期。

## 2. 案例索引

| ID | 要证明的行为 | 关键区别 | 发布验收关联 |
| --- | --- | --- | --- |
| A01 | 期初、收入、支出、转账、还款、普通退款 | 每一步账户、资产负债、月报与分类明细一致；期初不计日常收入 | T01、T05、T06、T17 |
| A02 | 跨月独立退款 | 原月不改、到账月净支出可负；无原消费关联或累计上限承诺 | T06 |
| A03 | 信用卡溢缴与现金负余额 | 正余额归资产、负余额归负债；还款只算转账，现金负数不自动改零 | T06 |
| A04 | 转账修订、删除与恢复 | 同一事件身份，两个账户同时变化；删除修订保留，恢复形成新修订 | T04、T05 |
| A05 | 固定差额对账 | 调整不算收支；后来出现的事实可使余额偏离旧目标，不再自动调整 | T03、T15 |
| A06 | 归档与改名 | 历史仍解释并计入报表，身份不改，新录入拒绝归档引用 | R04 对应主流程 |
| A07 | 冲突候选与明确解决 | 两个候选只选一个投影，另一方保留；解决生成新修订 | T03 |
| A08 | 业务日期、UTC 和设备时区 | 月份由业务日期决定；编辑日期迁移统计，换时区不改历史 | T07 |
| A09 | 分精度累计 | 小额累计精确，普通退款仍可使分类净支出为负 | T06 |
| A10 | 修改期初 | 替换同一事件的有效版本，重算余额，不额外增加日常收入 | R04 对应主流程 |

金额输入 M01–M18 覆盖分精度、正值、零、有符号边界、溢出、格式和未完成输入；日期输入 D01–D08 覆盖有效日历日、闰年、无效 / 不明确和空输入。V01–V05 是有明确基线的无效引用 / 类型 / 转账意图，拒绝后事实与投影不变。

这些案例提供数据和预期，不代表上述 T 场景已经运行，也不能代替实际事务中断、密钥失效或服务器恢复。

## 3. 数据结构的解释

| 字段 | 解释 |
| --- | --- |
| `currency` / `minorUnitScale` | 此材料为 CNY、分精度；没有换币或重新解释历史的含义 |
| `accounts` / `categories` | ID 到类型的案例局部映射；只定义此案例所需引用，不定义完整生产对象 |
| `openingEvents` | 显式期初事件与修订，`deltaMinor` 允许有符号整数和零；不是隐藏的账户余额字段 |
| `steps` | 按案例顺序发生的意图或观察，每一步从上一步事实继续；每个案例独立重新初始化 |
| `eventId` / `revisionId` | 同一事件跨编辑 / 删除 / 恢复保持身份，修订身份变化；实际协议前置条件另行冻结 |
| `amountMinor` / `deltaMinor` / `expectedMinor` | 最小单位的规范十进制整数字符串；没有小数点、加号、千位分隔、负零或非必要前导零 |
| `inputYuan` | 输入意图的元字符串，先校验格式 / 精度，再精确换算为分；与规范金额字符串不是同一种表示 |
| `businessDate` / `recordedAtUtc` | 用户选择的业务日与独立追踪时间；追踪时间不决定月报或冲突胜负 |
| `observedCheckpointId` | 此案例中对账观察的检查点，用于表达版本关系；不是生产观察版本编码 |
| `expected` | 此步骤结束后的完整当前余额、累计资产负债与指定月份统计；余额不是某月月末快照 |
| `activeEventIds` | 当前有效且非删除的事件集合，包含期初、调整和普通流水；集合大小不冒充普通流水笔数 |
| `selectedRevisionIds` | 有多版本语义时明确断言所选修订；删除修订也可以是当前选中版本 |
| `unresolvedCandidateRevisionIds` | 需要处理的候选集合，包含当前选择；为空表示此检查点没有未解决候选，不要求抹除历史修订 |
| `deletedEventIds` | 当前删除的事件集合；恢复后从该集合移出，历史删除证据仍保留 |
| `monthlyReports` | 月收入、毛支出、退款、净支出和结余；分类明细为该月支出减退款，含负数及显式零 |
| `archivedAccountIds` / `archivedCategoryIds` | 当前归档状态，历史引用仍有效；改名不改这些 ID |
| `failureClass` | 样例中的失败分类，便于区分原因；不是提前冻结的公共错误码或最终文案 |

未列出的可选断言不表示必须为空。每个给出的 `expected` 字段必须逐项比较；余额、分类和月份映射按键精确比较，集合按成员比较，不用只比较金额总和掩盖对象错配。

### 步骤意图

| `action` | 意图 |
| --- | --- |
| `observe` | 读取当前状态，没有新增事实 |
| `record` | 创建一个普通交易或调整；转账是一个整体事件 |
| `revise` / `reviseOpening` | 新修订取代原事件的当前有效版本，不叠加旧金额 |
| `delete` | 写删除修订，整笔退出投影；保留可追踪内容与防复活信息 |
| `restore` | 以删除修订为前置，按指定历史 payload 创建新修订，不直接撤掉删除标记 |
| `archiveReferences` / `renameReferences` | 改引用对象的归档 / 名称状态，不重写历史账务 |
| `receiveCandidate` | 接收并发候选，此案例保留既有本机选择，两个候选均可追踪 |
| `resolveCandidate` | 基于列出的最新候选集合，使用用户选定内容形成新修订 |
| `changeEnvironment` | 改测试设备环境，不改账务事实和历史业务日 |

这些 action 是验证叙事，不是拟定的核心函数名或 HTTP 操作。案例 A07 不定义所有冲突的自动选择策略，尤其不提供“按时间选择最新”的默认算法。

## 4. 输入与边界复核

- 普通金额正值和有符号变动分别校验。编辑中的空值 / 尾随小数点可继续输入，保存时明确未完成；超过两位小数不能舍入、截断或补成零。
- M05 / M15 只证明标量转换的上 / 下边界。合法标量不保证后续总和可表示；最小有符号值取绝对值、资产 / 负债总和、账户累加、差额相减和月结余都需独立范围检查，失败不篡改既有事实。
- 样例不定义完整自由文本、粘贴或 CSV 字法；语言 / 千位分隔、前导零、日期支持年份和导入映射在对应契约中明确。既定拒绝案例不能在 adapter 中“修好”后当作原意图通过。
- 无效意图在指定案例检查点单独运行；多次拒绝不能累积部分写入，也不能落入默认账户 / 类别。V05 可报告账户或分类的具体归档错误，不强制两种错误的先后次序。
- 对账预览失效、编辑前置版本过期、提交结果未知和损坏投影属于状态 / 故障验证，分别按 UI 规格与移动端矩阵取证，不伪造成纯数值测试已经覆盖。

## 5. 执行与证据

1. 逐案例重置隔离合成账库，建立引用和显式期初，再顺序执行 steps。实际随机 ID 与符号 ID 的映射随测试保留，不能混用其他案例的账户。
2. 每一步核对有效事实集合、选中版本、删除 / 候选 / 归档状态，再核对各账户、资产负债、月报和分类。金额以整数比较，显示另按元与两位小数核对。
3. 本地事务验证时同时检查事实与不可变 outbox；纯数值相等不能证明 outbox、原子性或持久化正确。崩溃注入后只允许完整旧状态或完整新状态，不能出现一边转账或只有事实没有队列。
4. 同步、导出 / 恢复、迁移阶段复用同一材料并补对应状态与故障证据；归档核对还包含必要非有效修订、删除和冲突候选。金额相等但丢候选 / 关联也判失败。
5. 记录案例版本、Git commit、平台、构建、运行方式和实际失败差异。仅复算人工材料时标记“样例复核”；运行实现后才标记对应核心 / 平台通过，不据此自动完成发布场景。
