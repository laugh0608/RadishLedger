# 同步事务共同案例与验证设计

本篇是 [M0-D 同步语义](../sync-protocol.md)的人工验证材料，定义合成输入、调度及独立预期，不是已运行的测试报告或公开请求格式。这里的状态、操作名称和短 ID 仅供测试 adapter 映射；生产随机 ID、确定性字节编码、算法与资源上限仍需评审冻结。

## 1. 共用输入与读法

每个案例从独立隔离状态开始；除非明确引用另一检查点，不继承前例结果。以下数值都是传输位置或控制记录数量，不是金额；账务预期只引用[账务 JSON](accounting-cases.json)，不在这里复制另一份余额表。

| 符号 | 固定合成含义 |
| --- | --- |
| `S0` | `(instance-A, account-A, vault-A, V1, R1)`；V 为安全域代次，R 为服务恢复代次 |
| `C0` | 已提交种子操作 `op-seed`，位置 1；从不存在创建对象 `X:x0` 和 `Y:y0`；相应完整批次及成功回执存在 |
| `B0` | 初态：S0 可写、访问合法、H=1，heads 为 X:x0 / Y:y0，Z 从未存在；增量流仅 C0；客户端已应用位置 A=1 |
| `P` | `(op-p, body-p)`；读条件 X=x0、Y=y0；一次发布 X:x1、Y:y1，无删除 |
| `Q` | `(op-q, body-q)`；读条件 X=x1；发布 X:x2，无删除 |
| `P*` | 与 P 使用同一个 op-p，但正文不同；分别替换 nonce、密文、前置修订或成员集合，每种变体独立运行 |
| `D` | `(op-delete, body-delete)`；读条件 X=x0；写 X:xd，外层删除标记与认证删除意图相符 |
| `E` | `(op-edit, body-edit)`；读条件 X=x0；写 X:xe，客户端离线编辑意图 |
| `F` | `(freeze-1, freeze-body-1)`；针对 S0 的显式源域冻结控制请求，具备当前所需权限 |

`body-p` 等标识代表可比较的完整不可变请求，包含所属上下文、所有前置条件和全部 envelope。它们不是密文正文、hash 测试向量或固定 nonce。密码验证前需把这些输入映射成经过独立核验的真实字节；同一案例内的重复请求必须使用同一份字节，不能每次随机重新加密。

X / Y 是两个对象，不能解释成一笔转账的两边；转账整体性另用 A04。初态和预期的 `heads` 表示服务端当前 head，不等于客户端选中投影。除特别说明，新增位置、heads、变更正文、回执都要求重连后持久可见；失败要求比较整个前后集合，而非只看返回码。

`unchanged` 指指定检查点的业务 heads、删除证据、完整变更流和 H 不变；若预期新建 CAS 拒绝登记，会单独说明。用例中的 committed / preconditionRejected 等为语义分类，不是 HTTP status 或正式错误枚举。观察日志只记案例、调度屏障、非秘密身份映射和计数，不记录请求密文、token、口令或密钥。

## 2. 服务端事务、重试与顺序

### S01–S04：原子性与原结果

| 案例 | 输入与调度 | 独立预期 |
| --- | --- | --- |
| S01 整批提交 | B0 上提交 P；在事务写完 X、尚未写 Y 时，用另一连接读取，再允许提交 | 提交前仅见 B0；提交后 H=2、heads X:x1 / Y:y1、恰有一个位置 2 的完整 P 和一个 op-p 成功回执。不能见 X:x1 / Y:y0 或半个 P |
| S02 任一 CAS 失败 | 独立准备位置 2 的操作将 X 改成 xe，Y 仍 y0，再提交 P。另一分支从 B0 给 P 额外增加只读条件 Z=z0（实际 Z 不存在）。重复 X 成员、矛盾或缺失写前置条件再各自从 B0 测试 | 过期 P 得 preconditionRejected 登记，业务保持原位置 2 状态、不生成 3；原 P 再次提交返回原拒绝。只读 Z 条件失败分支保留 B0 / H=1 并登记拒绝。结构矛盾分支受理前拒绝；均无半批或新对象 / 删除效果 |
| S03 原成功回执 | B0 上 P 成功于 2，Q 成功于 3；将域置只读冻结，再重试原 P；另独立测试配额耗尽和当前写入 epoch 政策变化 | 在当前访问权、同 R1 下返回 P 的原位置 2 和原修订 x1 / y1；heads 仍 X:x2 / Y:y1、H=3，不新增流或重复扣业务配额。不能把 Q 的 x2 当作 P 的确认 |
| S04 同键异内容 | P 已成功后分别发送 P*；另从 S02 的已登记拒绝状态发送改过 parent 的同键请求；再以新的 operationId、匹配的当前 CAS 重用 x1 写入不同内容 | 均拒绝，不覆盖原请求摘要 / 回执或既有修订，不增加 H；同键只改 token 后发送原 body-p 仍按原回执处理。换操作身份不能绕过修订身份不可变约束 |

S02 的拒绝登记是本轮回执策略候选：不计作业务批次，不凭这一设计宣称存储配额与保留机制已实现。受理前无法合法比较的请求不要求生成登记，但客户端不因此获准修改已发送操作。

### S05–S08：竞争、结果未定与崩溃

| 案例 | 输入与调度 | 独立预期 |
| --- | --- | --- |
| S05 同键并发 | 两个独立数据库连接同时提交 P；屏障让第一个持有域控制锁，第二个已经尝试进入；另以 P 与 P* 竞争 | 相同请求只有一个位置 2 和一个成功回执，另一方取得相同结果。异内容竞争只允许一个正文成为 op-p 的绑定，另一方拒绝；不能仅测试串行调用或进程内缓存 |
| S06 提交后失联 | 在 P 数据库提交后、发送响应前断开连接；重启服务后查询 / 重试原 P。另在原事务未结束时查询 op-p | 已提交分支返回原位置 2，无新效果。未结束分支允许“当时未查到”，但客户端仍保持结果未定；待原事务完成后原 P 重试仍最多一次。查无回执不授权换新 ID |
| S07 晚提交与回滚 | B0；连接甲取得控制锁，准备独立新增 Z 的操作，停在提交前；连接乙提交 P；读者轮询 H。分别让甲提交或回滚 | 甲持锁时乙不能取得本域下一个位置，读者 H=1。甲提交时 Z 批次为 2、P 为 3；甲回滚时 Z 不存在、P 为 2。不能出现 P 先成为可读位置 3，而稍后位置 2 才提交 |
| S08 数据库中断 | 对 P 分别在 head 写入、变更写入、回执写入、高水位更新后但 COMMIT 前中断连接；再测 COMMIT 后响应前退出服务 | COMMIT 前全回滚：B0、无 op-p 终态；COMMIT 后完整新状态与 S01 相同。独立连接核对 heads / stream / receipt / H 四者一致，再用原 P 重试。语句报错或超时未证实 rollback 时仍按未定处理 |

S07 必须带一个明确失败的对照调度：普通 sequence 先给甲 2、乙 3；甲暂停，乙提交、读者把 cursor 推到 3，甲才提交 2；按 `position > 3` 永远漏掉甲。该对照只能证明错误方案有缺陷，不能作为候选成功证据。候选必须通过真实等待与提交可见性检查；用 sleep 猜测竞争先后不充分。

## 3. 分页、本地事务与冲突

### S09–S12：稳定窗口与整批应用

| 案例 | 输入与调度 | 独立预期 |
| --- | --- | --- |
| S09 固定上界 | P 已在位置 2；另一个独立 Z 操作在位置 3；客户端 A=1，建立 U=3、每页最多一个完整批次。读第一页后 Q 提交于 4 | 第一页只能包含原 P，下一页仅位置 3，结束 A=U=3；Q 留待下一窗口。即使 X 当前为 x2，位置 2 正文仍是 x1 / y1，不从当前 head 拼出历史 |
| S10 页与资源界限 | 页面字节预算装不下完整 P；分别输入单个超限 envelope、总批次超限、过多前置条件、重复成员及计数溢出 | 返回具体界限 / 结构错误，不返回半批、不推进 cursor。接收已合法提交但本客户端能力不足的批次时明确阻塞；不能反复返回“成功空页”或放大资源。数值阈值用冻结后的 limit−1 / limit / limit+1，当前不虚构上限 |
| S11 本地应用中断 | 客户端 B0 接收完整 P；分别在写 x1、写 y1、更新投影、记去重身份及 cursor 前后结束进程 | 新进程只允许完整 B0 / A=1 或完整 P / A=2；不得有半批、丢 outbox、重复业务效果或 cursor 先走。重取 P 后完整新状态只出现一次 |
| S12 无效完整批次 | P 中仅一个 envelope 的认证失败；分别测试未知业务类型、缺引用、无效金额、外层删除意图不符、成员替换 / 拆分 / 拼接 | 整批不应用，A=1、原本地事实与未确认队列保留，显示阻塞原因。服务端可能已经存入有界但业务无效的密文，这不等于服务端解密成功；不能只跳过坏成员再把 A 推到 2 |

S09 另验：A=U 时返回本窗口完成；A>U、同代次上界回退或篡改 token 的域 / U 时拒绝。token 过期时从持久 A 重新建立窗口，不能清除已经应用的事实。页读取与恢复切换竞争时不得把旧代次核对结果用于新代次批次。

### S13–S16：重放、确认与候选

| 案例 | 输入与调度 | 独立预期 |
| --- | --- | --- |
| S13 乱序 / 重放 | 客户端 A=1 先收到位置 3、缺少位置 2；随后完整收到 2；重放同一 2，再提供同位置 / 同修订异内容的变体 | 首次不能应用 3 或推进 A；合法 2 原子应用一次，相同 2 不重复计账，异内容立即阻塞。不能以排序、相同余额或同 ID 忽略内容替换 |
| S14 本机确认与回声 | 客户端在 A=1 有本地 P；远端先提交独立 Z 于 2，再提交 P 于 3。客户端先收到 op-p 的位置 3 回执，再拉取 2 / 3 | 先记 P 已确认但 A 仍为 1；依次应用 Z、P 后 A=3，P 回声不重复创建交易或 outbox。确认与应用中断分别核对，无“跳到 3”遗漏 Z |
| S15 并发修改 / 解决再冲突 | 两端基于 X:x0 分别建立本地 xa 与 xb，甲先提交 xa，乙 CAS 拒绝并拉取 xa；乙保留 xb 为本机选择。解决操作以 xa 为前置，提交前第三次修改 xc 已成功；分别将甲追踪时钟提前 48 小时、乙回退 7 天，业务日期不改 | 乙保留 xa / xb 候选及原意图，只投影所选一个；服务器流不含被拒绝的 xb。解决 CAS 再失败后仍保留候选 / 新选择，不能静默覆写 xc；时钟偏移不改变结果。引用 A07 的候选选择检查点验证账务效果，不承诺其他设备已收到失败候选 |
| S16 删除 / 旧编辑 / 恢复 | B0 上 D 先提交为位置 2，旧设备再发 E；再以“从未存在”创建 X；最后显式以 xd 为 parent 发布恢复修订 xr | E 冲突、创建拒绝，X 不复活，删除证据和本地编辑候选保留。有效恢复占位置 3，X 变 xr，旧 xd 仍可追踪。用 A04 的 delete / restore 检查点核对整笔转账两端投影 |

S15 的服务端单 head 与客户端多候选分别核对，禁止为了让案例通过而把失败操作作为成功流项写入。A07 中的 `receiveCandidate` 只规定客户端候选行为；真实 adapter 需记录哪些修订已远端提交、哪些仅保存在发起端。

## 4. 隔离、恢复、冻结与停止

### S17–S20：身份与恢复代次

| 案例 | 输入与调度 | 独立预期 |
| --- | --- | --- |
| S17 同 ID 不同域 | 建立与 S0 分别仅 instance、account、vault、vaultGeneration 不同的独立状态，刻意重复 op-p / X / x1；在所有提交、确认查询、流读取、冻结路径混用另一范围的 token / 身份；restoreGeneration 单独见 S19 | 有效独立域之间互不去重、不串 heads / 队列 / cursor；越权请求不能读到另一域是否存在回执或对象。合法登录不等于有解密钥；跨域 envelope 即使被传输层返回也必须被客户端绑定验证拒绝 |
| S18 切换时迟到 | 原 runtime R-local-1 发出 S0/P 后切到另一个域，R-local-2 已活动；旧确认 / 旧拉取页分别在切换前检查后、切换后才尝试落库 | 旧回调不能修改新域状态、凭据、队列或 cursor。原 S0 的 P 保留结果未定；显式返回 S0 后按原身份核对，不把旧成功提示显示到新域 |
| S19 运维回滚 | R1 中 P、Q 已确认至 H=3；恢复只含 C0 的备份，建立 R2 恢复屏障。备份还含已被独立删除记录撤销的 account-deleted；客户端持有旧确认、未同步修改和删除证据 | 重新开放前旧会话失效，account-deleted 仍禁止访问；旧 R1 请求 / 分页 / 冻结证明不能在 R2 正常执行。客户端进入恢复对账并保全全部材料，不能把旧 P / Q 确认当作 R2 仍有这些数据。C0 继承来源与 R2 读取基线的映射待恢复契约冻结，未冻结前不运行自动续接 / 重新上传 |
| S20 同代次异常 / 无检查点 | 客户端已知 R1/H=3，服务却仍声称 R1/H=1；分别提供原位置异内容。另给全新客户端仅 R1/H=1 | 有检查点者停止并报告回滚 / 一致性异常，不自动 A=0 后继续。全新客户端不能据当前服务器声称证明“无历史截断”；如实保留这一威胁边界，不制造总能检测的断言 |

### S21–S24：冻结、取消、依赖与受理

| 案例 | 输入与调度 | 独立预期 |
| --- | --- | --- |
| S21 冻结与写入竞争 | B0 上 F 与 P 用两个连接争同域控制；分别让 P 或 F 先提交；冻结响应丢失后重试 F，再重试先前已确认的业务操作 | P 先则 F 的 U=2 且包括完整 P；F 先则 U=1、P 不提交。F 重放仍返回原冻结身份 / U；同代次已确认操作可返回原结果，不新增写入。不得出现返回 U 后仍有漏在 U 外的先行写 |
| S22 失败迁移与过期撤销 | F 生效后目标导入失败，查询 / 条件撤销 freeze-1；另先建立 freeze-2 再送迟到的 freeze-1 撤销；再测试源已恢复为 R2 或暂时失联 | 只有当前同代次 / 同冻结身份可撤销；迟到请求不能解除 freeze-2 / 恢复屏障。源失联或身份变化时保留源 / 目标暂存与本地事实，停止切换，不默认为已解冻、不双写。目标开始日常写后回源须再次迁移 / 对账 |
| S23 取消与锁定 | 本机 P 已发送，在远端提交前 / 提交后分别取消等待、锁定或结束 App；返回后重新解锁原域 | 本地事实 / P 身份 / 内容保留，不能把取消当作远端回滚。重新查询或重试原 P 后只出现一个远端效果。暂停需明文工作，不能为测试通过常驻解密钥；迟到结果按 runtime 检查 |
| S24 依赖 / 受理竞争 | 本机 P 的后续编辑依赖 x1，P 仍未定或已冲突；分别测试受理前版本 / epoch / 配额拒绝、排队期间撤销权限、拒绝登记配额耗尽；另测试同批 / 已有的账户类别引用 | 子操作不越过依赖、不改写 P，冲突时保留整个意图链。受理前拒绝无部分业务效果，排队后必须重新核对权限；控制配额满不创建无限拒绝登记。服务端不检查密文引用，客户端完整验证后才发布；归档引用与新增限制按领域规则区分 |

### 账务材料映射

| 共用账务检查点 | 本篇用途 | 额外必须记录 |
| --- | --- | --- |
| `A04.steps`：transfer / edit / delete / restore | S11、S16、S23 的转账整体与恢复 | 只发布一个 Transaction payload；两个账户投影和删除 / 恢复修订一起核对 |
| `A07.steps`：original / local-edit / conflict / resolved | S15 的并发候选与明确选择 | 本机选中版本、全部未解决候选、远端 head、未确认 / 拒绝意图分别记录，不把两个候选相加 |
| `A11.steps`：transfer / edit / delete / original / local-edit / conflict | S11、S19、S22 的非空事实保全 | 完整修订集合、删除、候选、原 outbox / 确认与域绑定；仅余额一致不算恢复完整 |

账务金额及事实集合期望只消费 JSON 对应步骤的 `expected`。传输位置、回执和队列状态使用本篇独立预期，两者分别比较。现有 M0-C A11 core replay 只证明本地实验操作重放，不能冒充跨服务幂等与代次对账。

## 5. 后续实施任务与运行条件
