# 数据可迁移共同案例与验证设计

本篇对应 [M0-E 语义规格](../data-portability.md)，定义人工维护的合成输入、故障调度与独立预期。它不是已运行结果，不冻结 CSV 列名、归档字节、密码 profile、DB schema 或 HTTP 接口。金额与账务集合的真相源仍为[账务 JSON](accounting-cases.json)；本篇只补导入、归档、恢复和迁移的任务 / 身份 / 发布预期。

## 1. 共用材料与比较范围

每个案例独立初始化；分支也从其声明基线开始，不继承前例的污染状态。下列标识是符号，adapter 必须记录实际随机身份映射，不能把短 ID 固化为公共格式。

| 符号 | 合成定义 |
| --- | --- |
| `C0` | A01 的 accounts / categories / openingEvents 与 `initial.expected`；尚未导入 salary 及后续六步 |
| `CSV-A` | 将 A01 的 salary、transfer、dining、shopping、repayment、refund 各映射为一个逻辑业务行 r1–r6；来源命名空间 source-A、来源 ID src-1–src-6；目标为 C0；不复制另一份金额表 |
| `I1` | 固定 CSV-A 输入 fingerprint、解析 profile、映射及目标身份的导入任务；第一批 r1–r3，第二批 r4–r6；分批数仅是故障调度，不是生产上限 |
| `L0` | A11 到 `conflict` 的完整非空本机事实、全部修订 / 候选、所选版本和删除；本地发布的期初 / 交易 / 修订保留原意图，receiveCandidate 只保留接收候选，不新增上传意图。确认状态由各案例另行赋值，不从账务 expected 推断 |
| `K1` | 从指定一致检查点生成的独立归档身份；Archive Key、备份口令仅供测试安全通道使用，不写本文或日志 |
| `O / N` | 原活动本机库与本任务新建未发布暂存库；O 可含 L0 与未同步事实，N 起始为空 |
| `M1` | 迁移任务，绑定源 S0、冻结 freeze-1 / U、最终快照 K-final 与新空目标 T0；沿用 S01–S24 的域 / 代次语义 |
| `P-old / P-new` | 活动选择记录的原 / 新身份；不是可由文件 mtime 推断的状态，也不是密码值 |

CSV-A 的金额输出按领域规则从账务输入字符串精确映射；账户类别、业务日、类型逐行一一对应。转账和信用卡还款分别都是一个完整交易行。引用 `initial` 的期初只建一次，不能又作为六行之一重复导入。字段映射的 parser 与密码 codec 必须有单独的手写负向输入 / 独立向量，不能只依赖同一 exporter 生成所有测试文件。

完整核对包括事实与修订集合、引用、所选 / 未选候选、删除、导入来源 / 批次、原意图、活动身份与运行状态；统计只消费对应步骤全部 `expected`。归档恢复后的业务身份如需映射，先验证映射完整且无碰撞，再逐项比较，不能只看余额。任何额外记录、漏记录、错误来源或旧队列被激活都应失败。

## 2. CSV 输入、批次与导出

| 案例 | 输入与调度 | 独立预期 |
| --- | --- | --- |
| E01 映射与正常发布 | C0 + CSV-A，预览 I1，再依次提交两批；另从空业务目标显式导入 A01 的期初事件 | 预览不新增正式账户 / 事件；第一批后对应 A01 `dining.expected`，第二批后对应 `refund.expected`，r1–r6 各一次；转账 / 还款不计收入或支出。期初分支只出现专门事件，不能藏入余额字段或日常收入 |
| E02 CSV 语法与记录身份 | CSV-A 的一个备注分别加入逗号、双引号、字段内换行和首尾空格；CRLF / LF、文件首 BOM、末尾无换行各独立输入；另给非法 UTF-8、NUL、未闭合引号、列数不符和重复映射列 | 合法备注保留原文本及六条逻辑记录，不因物理换行多造一行；BOM 只在文件首识别并报告。不合法结构在发布前拒绝，C0 不变；无表头模式不得丢 r1 |
| E03 金额、日期与引用 | 映射既有 M01–M18 / D01–D08 适用输入；另给未知事件、手续费 / 拆分、两个相同转账账户、不同币种、缺类别及预览后归档引用；调整分支使用 A05 `adjust` 的完整观察材料，再移除观察来源 | 只接受明确的输入 profile 与领域合法值；金额不隐式舍入 / 浮点，歧义日期不猜测。失败行不能静默改类型、改引用或变成零。完整调整保留固定差额语义，对应 A05 `adjust.expected`；缺必要材料停止该行，不能按导入时余额补造。通用新增拒绝归档引用，既有历史不变 |
| E04 重复与来源冲突 | I1 完成后原任务重试；分别同 source-A/src-1 相同内容和异内容、另一来源同 src-1、无来源 ID 的两笔相同消费；重选相同文件 | 原任务不再新增；已绑定同键同内容显示已导入，异内容要求核对且不覆盖。其他来源与两笔相同消费不能被自动合并；重选文件展示历史处理范围，需要明确继续原任务或建立新计划，不自动清零去重状态 |
| E05 原子进度与中断 | I1 每批分别在写第一条事实、完整事实、来源绑定、进度 / 上传意图前后中断进程；第二批失败后重开；另在转账成员写入期间中断 | 每批仅完整旧或完整新状态，任务进度与业务 / 意图同在；第一批已提交时保持 `dining.expected`，第二批重试后为 `refund.expected`，没有半笔转账或重复 r1–r3。不能因整个文件未完成抹掉第一批 |
| E06 输入变化、取消与切库 | 预览后替换输入字节或映射；提交进行中取消 / 锁定；旧任务检查活动库后、写入前切到另一库；原提交响应丢失 | 输入改变重新预览，旧行身份不能套新内容。取消停止后续批次，当前批按持久结果核对；未查明前显示结果待核对。旧回调不改变新库；返回旧任务沿原身份读取已完成范围，不因未见成功提示重复导入 |
| E07 受限撤销 | I1 完成后只改 r1 备注形成新修订；撤销预览排除 r1，再在提交前只改 r2 备注。重新预览后确认撤销 r3–r6；独立测试导入新账户后来被其他交易引用 | 第一次撤销批因版本竞争拒绝，统计仍为 A01 `refund.expected`；重新确认后保留新 r1 / r2，统计对应 `transfer.expected`，r3–r6 有删除修订 / 意图、来源与原批次保留。重复撤销不新增效果，重导不能自动复活。新增账户不因删导入行而硬删除 |
| E08 导出范围、公式与分享 | 从 A07 `conflict` 导出选中投影，从 A04 `delete` / `restore` 分别导出；备注、账户名、来源文本含 `=1+1`、`+1`、`-1`、`@x`、tab、换行、引号 / 分隔符、全角前缀及合法原始单引号；保存 / 重开和再导入；写文件途中失败或分享取消 | 候选不各计一笔，删除范围和未导出内容明确，恢复后的转账仍是一行。每个支持表格软件不执行输入公式，指定 profile 的再导入保留原文本；不能剥掉合法前缀。临时文件失败不替换旧文件，分享结果未定不宣称外部已保存，清理只触及本任务临时文件。规则 / 软件矩阵未冻结前此例仅待验证 |

E03 的 M / D 输入先按各自预期区分合法正金额、有符号调整与未完成输入，不能把所有样例都用普通交易 parser 运行。E07 只引用既有步骤的统计与有效事件集合；新增的备注修订、删除证据与来源状态另按本例核对，不能把原步骤的旧修订身份误当作撤销后应覆盖的版本。

## 3. 归档生成、认证与保真

| 案例 | 输入与调度 | 独立预期 |
| --- | --- | --- |
| E09 一致快照 | L0 导出 K1；独立分支从 A04 `delete` 捕获快照后，原库继续 `restore`；在读取事实 / 候选 / 汇总之间加入并发写 | K1 包含捕获点完整 L0。A04 分支归档仍对应 `delete.expected`，活动库对应 `restore.expected`；不混成旧事实新汇总。不依赖“导出开始 / 结束时间差不多”证明一致 |
| E10 独立解锁与失败分类 | K1 使用正确 / 错误备份口令；损坏封装、已解封后损坏内容；关闭原服务、移除测试访问旧设备钥的通道 | 正确口令不依赖旧 DB Key、同步钥或服务器即可验证；错误 / 篡改不发布部分内容，不改 O 或原档。封装认证失败不伪称一定是口令错误；格式 / 资源等可判定原因保留 |
| E11 完整认证边界 | 独立更改头、KDF 参数、salt、封装、归档身份、manifest、记录及终结；截断各边界、尾部附加；分块候选另测重复 / 缺块 / 重排 / 跨归档拼接 | 有界拒绝，N 不激活、O 不变；单块认证成功不能绕过归档完整性。块方案未选定前不生成假向量；独立向量需覆盖全部认证关系 |
| E12 资源与不可信容器 | 各冻结界限的 limit−1 / limit / limit+1，含输入 / 字段 / KDF / 记录 / 解压 / 累计工作量；声称很小但实际很大、未知算法、恶意内部路径 / 链接 / 重复项 | 不支持 / 超限在相应分配或解码前拒绝，流式累计也受限；不跟随路径写出暂存、不加载外部资源。不存在默认成功或降级弱 KDF。未冻结数值时保留参数化案例，不假填资源性能通过 |
| E13 非空事实保真 | L0 中一部分原意图标为旧域已确认，其余未确认 / 结果未定；归档后恢复到 N；同一修订分别在事实与意图 / 确认来源中出现 | A11 `conflict.expected` 所有字段及完整修订、删除 / 候选 / 原意图关系一致，只投影所选一个候选。相同事实不因两种状态重复入账；旧回执 / cursor 仅是历史，N 没有可执行旧域队列 / 会话。摘要必须覆盖事实集合，不只核对统计 |
| E14 关系与内容非法 | 从可信测试生成器建立可认证但含重复 ID、同修订异内容、缺 parent、缺引用、跨币种、无效金额、所选修订不在候选、删除与有效状态矛盾的归档 | 密码认证成功后业务校验仍拒绝，O / P-old 不变；不忽略坏记录后宣布恢复。A06 `renamed` 中合法归档引用则可作为历史完整恢复，不能按“新增不允许归档账户”误删历史 |
| E15 归档生成与目标保存 | 输出内容 / manifest / 终结 / 保存确认各点失败、取消、锁定或结束进程；目录已有成功旧归档；外部文件提供方丢失完成响应 | 原成功归档与活动账务保留，部分输出不标记可用；结果未定要求核对 / 重试。重新生成使用新归档身份 / Archive Key；未验证的断点加密不冒充续写。清理不删除用户目标或其他任务文件 |
| E16 版本与恢复任务状态 | 当前支持旧格式、未知主版本 / 必需字段、业务 schema 过新；K1 包含 I1 已完成第一批与未完成第二批，恢复后重新选择 CSV-A；另含绝对临时路径或可执行旧 envelope 的违规材料 | 只有明确支持且独立验证的转换可成功，未知关键内容不丢弃降级。来源 / 行绑定映射后 r1–r3 仍识别为已处理，未完成范围需匹配文件并重新确认；不恢复旧路径权限或自动发送 envelope。违规材料按 schema 拒绝，不默默激活 |

E11 的任意字节篡改材料和 E14 的“合法认证但业务非法”材料需分开构造，否则只测到 AEAD 拒绝，不能声称业务校验有效。E13 与 E16 的来源 / 确认状态由 adapter 显式设置并独立检查，账务 JSON 本身不定义生产同步队列。

## 4. 暂存恢复、切换与迁移

| 案例 | 输入与调度 | 独立预期 |
| --- | --- | --- |
| E17 暂存继续、放弃与清理失败 | O 含 L0，N 写入途中取消 / 强杀；分别同归档继续、替换输入后继续、owner 不符、删除暂存失败；锁定后再次打开任务 | O 及 P-old 保持完整，N 未发布；匹配且重新认证后才可继续，不信任裸进度。输入 / owner 不符拒绝，清理失败登记精确项并可重试，不删除 O / 其他任务。秘密不作为进度持久化 |
| E18 发布中断点 | 在新库完成、bootstrap / 系统项准备、核对清单持久化、选择记录写入 / 同步、重开校验及成功响应前后逐点失败 / 结束进程 | 重开只允许经验证的完整 P-old / O 或完整 P-new / N；结果未定先核对选择身份，不重新创建 / 删除任一库。不一致时明确阻塞；不会按 mtime 或能解锁的库自动选。新项准备失败不破坏旧钥，已切换后新钥暂不可取不自动回退 O |
| E19 旧库变化与晚回调 | N 校验后、切换前 O 新增未同步事实；另有旧任务已检查身份但尚未落库，随后请求切换；切换后再收到旧成功 | 条件切换发现核对点变化，重新展示范围并保全新事实；最终写入与切换串行边界中旧写不能落入 N。旧回调不更新新状态。取消若晚于已持久切换，显示实际已切换，不报告“原样取消” |
| E20 空白设备独立恢复 | 独立新安装环境仅提供 K1 与备份口令，无原 DB / bootstrap / 系统项 / 服务器；恢复 L0 到 N，再重开；主动启用新空域同步作为后续独立分支 | L0 的完整事实、关系、候选、删除和统计一致，新本机钥 / 安全域独立；本地无网络可用。没有旧 token / cursor / 可发送 outbox。新域分支未有 D / E 快照绑定与读取基线契约前不标通过；不能靠重放全部历史制造重复事实 |
| E21 空目标迁移 | 以 A04 `restore` 为已核对源，M1 冻结后最终快照上传 T0；另在预览后目标被其他写者占用，或目标实例 / 账号改变 | 正常路径只在完整目标认证 / 业务核对及条件发布后切换；目标事实按 A04 `restore.expected` 且历史删除可追踪。目标竞争 / 身份漂移停止，不覆盖 / 合并；半个导入不可作为正常账库读取或写入。源保持可恢复且冻结 |
| E22 冻结、未定与条件回源 | 冻结前归档后源又提交一笔；冻结结果未定、目标上传中断、目标发布响应丢失、本机切换前退出分别运行；最终快照后本机又有未同步新增；回源时目标失联或已有新日常写入；迟到撤销 freeze-1 遇 freeze-2 | 最终快照必须包含到 U 的完整新增，不能复用旧归档冒充；快照后本机变化保全并使旧切换计划暂停，不改写原任务绑定。每个未定控制按原身份查询，无双写。目标未知不能直接解冻源；目标已日常写入需新迁移 / 对账。旧撤销不能解除后一次冻结；源 / 目标暂存与本地事实保留 |
| E23 源离线与旧设备 | 无法取得源冻结，只持本机 L0 或 K1 显式迁出；旧设备尚有未上传事实，源后来恢复；另只有恢复秘密无数据，或只有运维密文无解密材料 | 离线迁出明确为新域分支，显示最后已知范围 / 未知缺口，不宣传完整同步搬迁；旧设备保全后显式核对，不自动向新旧双写。只有秘密或只有不可解密密文不能恢复交易，不显示空库假成功 |
| E24 运维继承与删除控制 | 复用 S19 / S20：R1 曾确认 P / Q，旧备份只含 C0，恢复为 R2；客户端同时有旧确认、未确认事实与删除。独立删除控制含被备份复活的已注销身份 | 开放前旧会话失效且删除控制重应用；原 envelope 保留原绑定，当前 R2 读取上下文独立。继承 / 本地缺失 / 删除 / 候选分别核对；旧确认不赋新 cursor，缺失不当作用户删除。清单绑定与基线映射未冻结时只能验证停止与保全，不能宣布自动补传 / 对账成功；新客户端无法证明没有被隐藏历史 |

E18 必须覆盖真实目标文件系统、SQLCipher 与系统密钥项，宿主替身只能验证状态分支；E20 的“空白”不能复用同进程缓存的旧钥；E22 的数据库冻结实验不代替真实网络、目标导入与本机切换。T21 的已删除账号控制与本地交易删除分开，旧归档数据不能为原账号重新授予远端权限。

## 5. 实施任务与证据

以下为待实施工作，不是已有检查入口。本轮只建立规格与人工材料，不编写返回成功的模拟导入 / 归档工具，不操作真实账单、设备、服务或密钥。实施前依任务范围说明版本、依赖、数据 / 端口 / 运行时长和精确清理范围。

| 任务 | 最小切片 | 必须取得的证据 / 停止线 |
| --- | --- | --- |
| E-CSV 映射与任务 | E01–E08；先固定通用输入 profile 与手写材料，Rust 使用同一领域验证；真实存储的批次、来源 / 进度、受限撤销 | 独立输入与账务 expected、逻辑行 / 重试身份、真实中断恢复；公式规则 / 支持表格软件未验证前不交付生产导出。专用来源不凭截图或真实私人文件补 fixture |
