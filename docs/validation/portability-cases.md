# 数据可迁移共同案例与验证设计

本篇对应 [M0-E 语义规格](../data-portability.md)，定义人工维护的合成输入、故障调度与独立预期。第 1–4 节定义人工预期，第 5 节分别维护宿主候选的实现 / 运行证据与缺口；案例编号本身不代表已经通过。本文不冻结 CSV 列名、归档字节、密码 profile、DB schema 或 HTTP 接口。金额与账务集合的真相源仍为[账务 JSON](accounting-cases.json)；本篇只补导入、归档、恢复和迁移的任务 / 身份 / 发布预期。

## 1. 共用材料与比较范围

每个案例独立初始化；分支也从其声明基线开始，不继承前例的污染状态。下列标识是符号，adapter 必须记录实际随机身份映射，不能把短 ID 固化为公共格式。

| 符号 | 合成定义 |
| --- | --- |
| `C0` | A01 的 accounts / categories / openingEvents 与 `initial.expected`；尚未导入 salary 及后续六步 |
| `CSV-A` | 将 A01 的 salary、transfer、dining、shopping、repayment、refund 各映射为一个逻辑业务行 r1–r6；来源命名空间 source-A、来源 ID src-1–src-6；目标为 C0；不复制另一份金额表 |
| `I1` | 固定 CSV-A 输入 fingerprint、解析 profile、映射及目标身份的导入任务；第一批 r1–r3，第二批 r4–r6；分批数仅是故障调度，不是生产上限 |
| `L0` | A11 到 `conflict` 的完整非空本机事实、全部修订 / 候选、所选版本和删除；本地发布的期初 / 交易 / 修订保留原意图，receiveCandidate 只保留接收候选，不新增上传意图。确认状态由各案例另行赋值，不从账务 expected 推断 |
| `K1` | 从指定一致检查点生成的独立归档身份；Archive Key、备份口令仅供测试安全通道使用，不写本文或日志 |
| `O / N` | 原活动本机库与本任务新建未发布暂存库；O 可含 L0 与未同步事实，N 起始为空 |
| `M1` | 迁移任务，绑定源 S0、冻结 freeze-1 / U、最终快照 K-final 与新空目标 T0；沿用 S01–S24 的域 / 代次语义 |
| `P-old / P-new` | 活动选择记录的原 / 新身份；不是可由文件 mtime 推断的状态，也不是密码值 |

CSV-A 的金额输出按领域规则从账务输入字符串精确映射；账户类别、业务日、类型逐行一一对应。转账和信用卡还款分别都是一个完整交易行。引用 `initial` 的期初只建一次，不能又作为六行之一重复导入。字段映射的 parser 与密码 codec 必须有单独的手写负向输入 / 独立向量，不能只依赖同一 exporter 生成所有测试文件。

完整核对包括事实与修订集合、引用、所选 / 未选候选、删除、导入来源 / 批次、原意图、活动身份与运行状态；统计只消费对应步骤全部 `expected`。归档恢复后的业务身份如需映射，先验证映射完整且无碰撞，再逐项比较，不能只看余额。任何额外记录、漏记录、错误来源或旧队列被激活都应失败。

## 2. CSV 输入、批次与导出

| 案例 | 输入与调度 | 独立预期 |
| --- | --- | --- |
| E01 映射与正常发布 | C0 + CSV-A，预览 I1，再依次提交两批；另从空业务目标显式导入 A01 的期初事件 | 预览不新增正式账户 / 事件；第一批后对应 A01 `dining.expected`，第二批后对应 `refund.expected`，r1–r6 各一次；转账 / 还款不计收入或支出。期初分支只出现专门事件，不能藏入余额字段或日常收入 |
| E02 CSV 语法与记录身份 | CSV-A 的一个备注分别加入逗号、双引号、字段内换行和首尾空格；CRLF / LF、文件首 BOM、末尾无换行各独立输入；另给非法 UTF-8、NUL、未闭合引号、列数不符和重复映射列 | 合法备注保留原文本及六条逻辑记录，不因物理换行多造一行；BOM 只在文件首识别并报告。不合法结构在发布前拒绝，C0 不变；无表头模式不得丢 r1 |
| E03 金额、日期与引用 | 映射既有 M01–M18 / D01–D08 适用输入；另给未知事件、手续费 / 拆分、两个相同转账账户、不同币种、缺类别及预览后归档引用；调整分支使用 A05 `adjust` 的完整观察材料，再移除观察来源 | 只接受明确的输入 profile 与领域合法值；金额不隐式舍入 / 浮点，歧义日期不猜测。失败行不能静默改类型、改引用或变成零。完整调整保留固定差额语义，对应 A05 `adjust.expected`；缺必要材料停止该行，不能按导入时余额补造。通用新增拒绝归档引用，既有历史不变 |
| E04 重复与来源冲突 | I1 完成后原任务重试；分别同 source-A/src-1 相同内容和异内容、另一来源同 src-1、无来源 ID 的两笔相同消费；重选相同文件 | 原任务不再新增；已绑定同键同内容显示已导入，异内容要求核对且不覆盖。其他来源与两笔相同消费不能被自动合并；重选文件展示历史处理范围，需要明确继续原任务或建立新计划，不自动清零去重状态 |
| E05 原子进度与中断 | I1 每批分别在写第一条事实、完整事实、来源绑定、进度 / 上传意图前后中断进程；第二批失败后重开；另在转账成员写入期间中断 | 每批仅完整旧或完整新状态，任务进度与业务 / 意图同在；第一批已提交时保持 `dining.expected`，第二批重试后为 `refund.expected`，没有半笔转账或重复 r1–r3。不能因整个文件未完成抹掉第一批 |
| E06 输入变化、取消与切库 | 预览后替换输入字节或映射；提交进行中取消 / 锁定；旧任务检查活动库后、写入前切到另一库；原提交响应丢失 | 输入改变重新预览，旧行身份不能套新内容。取消停止后续批次，当前批按持久结果核对；未查明前显示结果待核对。旧回调不改变新库；返回旧任务沿原身份读取已完成范围，不因未见成功提示重复导入 |
| E07 受限撤销 | I1 完成后只改 r1 备注形成新修订；撤销预览排除 r1，再在提交前只改 r2 备注。重新预览后确认撤销 r3–r6；独立测试导入新账户后来被其他交易引用 | 第一次撤销批因版本竞争拒绝，统计仍为 A01 `refund.expected`；重新确认后保留新 r1 / r2，统计对应 `transfer.expected`，r3–r6 有删除修订 / 意图、来源与原批次保留。重复撤销不新增效果，重导不能自动复活。新增账户不因删导入行而硬删除 |
| E08 导出范围、公式与分享 | 从 A07 `conflict` 导出选中投影，从 A04 `delete` / `restore` 分别导出；备注、账户名、来源文本含 `=1+1`、`+1`、`-1`、`@x`、tab、换行、引号 / 分隔符、全角前缀及合法原始单引号；保存 / 重开和再导入；写文件途中失败或分享取消 | 候选不各计一笔，删除范围和未导出内容明确，恢复后的转账仍是一行。每个支持表格软件不执行输入公式，指定 profile 的再导入保留原文本；不能剥掉合法前缀。临时文件失败不替换旧文件，分享结果未定不宣称外部已保存，清理只触及本任务临时文件。规则 / 软件矩阵未冻结前此例仅待验证 |

E03 的 M / D 输入先按各自预期区分合法正金额、有符号调整与未完成输入，不能把所有样例都用普通交易 parser 运行。E07 只引用既有步骤的统计与有效事件集合；新增的备注修订、删除证据与来源状态另按本例核对，不能把原步骤的旧修订身份误当作撤销后应覆盖的版本。

## 3. 归档生成、认证与保真

| 案例 | 输入与调度 | 独立预期 |
| --- | --- | --- |
| E09 一致快照 | L0 导出 K1；独立分支从 A04 `delete` 捕获快照后，原库继续 `restore`；在读取事实 / 候选 / 汇总之间加入并发写 | K1 包含捕获点完整 L0。A04 分支归档仍对应 `delete.expected`，活动库对应 `restore.expected`；不混成旧事实新汇总。不依赖“导出开始 / 结束时间差不多”证明一致 |
| E10 独立解锁与失败分类 | K1 使用正确 / 错误备份口令；损坏封装、已解封后损坏内容；关闭原服务、移除测试访问旧设备钥的通道 | 正确口令不依赖旧 DB Key、同步钥或服务器即可验证；错误 / 篡改不发布部分内容，不改 O 或原档。封装认证失败不伪称一定是口令错误；格式 / 资源等可判定原因保留 |
| E11 完整认证边界 | 独立更改头、KDF 参数、salt、封装、归档身份、manifest、记录及终结；截断各边界、尾部附加；分块候选另测重复 / 缺块 / 重排 / 跨归档拼接 | 有界拒绝，N 不激活、O 不变；单块认证成功不能绕过归档完整性。块方案未选定前不生成假向量；独立向量需覆盖全部认证关系 |
| E12 资源与不可信容器 | 各冻结界限的 limit−1 / limit / limit+1，含输入 / 字段 / KDF / 记录 / 解压 / 累计工作量；声称很小但实际很大、未知算法、恶意内部路径 / 链接 / 重复项 | 不支持 / 超限在相应分配或解码前拒绝，流式累计也受限；不跟随路径写出暂存、不加载外部资源。不存在默认成功或降级弱 KDF。未冻结数值时保留参数化案例，不假填资源性能通过 |
| E13 非空事实保真 | L0 中一部分原意图标为旧域已确认，其余未确认 / 结果未定；归档后恢复到 N；同一修订分别在事实与意图 / 确认来源中出现 | A11 `conflict.expected` 所有字段及完整修订、删除 / 候选 / 原意图关系一致，只投影所选一个候选。相同事实不因两种状态重复入账；旧回执 / cursor 仅是历史，N 没有可执行旧域队列 / 会话。摘要必须覆盖事实集合，不只核对统计 |
| E14 关系与内容非法 | 从可信测试生成器建立可认证但含重复 ID、同修订异内容、缺 parent、缺引用、跨币种、无效金额、所选修订不在候选、删除与有效状态矛盾的归档 | 密码认证成功后业务校验仍拒绝，O / P-old 不变；不忽略坏记录后宣布恢复。A06 `renamed` 中合法归档引用则可作为历史完整恢复，不能按“新增不允许归档账户”误删历史 |
| E15 归档生成与目标保存 | 输出内容 / manifest / 终结 / 保存确认各点失败、取消、锁定或结束进程；目录已有成功旧归档；外部文件提供方丢失完成响应 | 原成功归档与活动账务保留，部分输出不标记可用；结果未定要求核对 / 重试。重新生成使用新归档身份 / Archive Key；未验证的断点加密不冒充续写。清理不删除用户目标或其他任务文件 |
| E16 版本与恢复任务状态 | 当前支持旧格式、未知主版本 / 必需字段、业务 schema 过新；K1 包含 I1 已完成第一批与未完成第二批，恢复后重新选择 CSV-A；另含绝对临时路径或可执行旧 envelope 的违规材料 | 只有明确支持且独立验证的转换可成功，未知关键内容不丢弃降级。来源 / 行绑定映射后 r1–r3 仍识别为已处理，未完成范围需匹配文件并重新确认；不恢复旧路径权限或自动发送 envelope。违规材料按 schema 拒绝，不默默激活 |

E11 的任意字节篡改材料和 E14 的“合法认证但业务非法”材料需分开构造，否则只测到 AEAD 拒绝，不能声称业务校验有效。E13 与 E16 的来源 / 确认状态由 adapter 显式设置并独立检查，账务 JSON 本身不定义生产同步队列。

## 4. 暂存恢复、切换与迁移

| 案例 | 输入与调度 | 独立预期 |
| --- | --- | --- |
| E17 暂存继续、放弃与清理失败 | O 含 L0，N 写入途中取消 / 强杀；分别同归档继续、替换输入后继续、owner 不符、删除暂存失败；锁定后再次打开任务 | O 及 P-old 保持完整，N 未发布；匹配且重新认证后才可继续，不信任裸进度。输入 / owner 不符拒绝，清理失败登记精确项并可重试，不删除 O / 其他任务。秘密不作为进度持久化 |
| E18 发布中断点 | 在新库完成、bootstrap / 系统项准备、核对清单持久化、选择记录写入 / 同步、重开校验及成功响应前后逐点失败 / 结束进程 | 重开只允许经验证的完整 P-old / O 或完整 P-new / N；结果未定先核对选择身份，不重新创建 / 删除任一库。不一致时明确阻塞；不会按 mtime 或能解锁的库自动选。新项准备失败不破坏旧钥，已切换后新钥暂不可取不自动回退 O |
| E19 旧库变化与晚回调 | N 校验后、切换前 O 新增未同步事实；另有旧任务已检查身份但尚未落库，随后请求切换；切换后再收到旧成功 | 条件切换发现核对点变化，重新展示范围并保全新事实；最终写入与切换串行边界中旧写不能落入 N。旧回调不更新新状态。取消若晚于已持久切换，显示实际已切换，不报告“原样取消” |
| E20 空白设备独立恢复 | 独立新安装环境仅提供 K1 与备份口令，无原 DB / bootstrap / 系统项 / 服务器；恢复 L0 到 N，再重开；主动启用新空域同步作为后续独立分支 | L0 的完整事实、关系、候选、删除和统计一致，新本机钥 / 安全域独立；本地无网络可用。没有旧 token / cursor / 可发送 outbox。新域分支未有 D / E 快照绑定与读取基线契约前不标通过；不能靠重放全部历史制造重复事实 |
| E21 空目标迁移 | 以 A04 `restore` 为已核对源，M1 冻结后最终快照上传 T0；另在预览后目标被其他写者占用，或目标实例 / 账号改变 | 正常路径只在完整目标认证 / 业务核对及条件发布后切换；目标事实按 A04 `restore.expected` 且历史删除可追踪。目标竞争 / 身份漂移停止，不覆盖 / 合并；半个导入不可作为正常账库读取或写入。源保持可恢复且冻结 |
| E22 冻结、未定与条件回源 | 冻结前归档后源又提交一笔；冻结结果未定、目标上传中断、目标发布响应丢失、本机切换前退出分别运行；最终快照后本机又有未同步新增；回源时目标失联或已有新日常写入；迟到撤销 freeze-1 遇 freeze-2 | 最终快照必须包含到 U 的完整新增，不能复用旧归档冒充；快照后本机变化保全并使旧切换计划暂停，不改写原任务绑定。每个未定控制按原身份查询，无双写。目标未知不能直接解冻源；目标已日常写入需新迁移 / 对账。旧撤销不能解除后一次冻结；源 / 目标暂存与本地事实保留 |
| E23 源离线与旧设备 | 无法取得源冻结，只持本机 L0 或 K1 显式迁出；旧设备尚有未上传事实，源后来恢复；另只有恢复秘密无数据，或只有运维密文无解密材料 | 离线迁出明确为新域分支，显示最后已知范围 / 未知缺口，不宣传完整同步搬迁；旧设备保全后显式核对，不自动向新旧双写。只有秘密或只有不可解密密文不能恢复交易，不显示空库假成功 |
| E24 运维继承与删除控制 | 复用 S19 / S20：R1 曾确认 P / Q，旧备份只含 C0，恢复为 R2；客户端同时有旧确认、未确认事实与删除。独立删除控制含被备份复活的已注销身份 | 开放前旧会话失效且删除控制重应用；原 envelope 保留原绑定，当前 R2 读取上下文独立。继承 / 本地缺失 / 删除 / 候选分别核对；旧确认不赋新 cursor，缺失不当作用户删除。清单绑定与基线映射未冻结时只能验证停止与保全，不能宣布自动补传 / 对账成功；新客户端无法证明没有被隐藏历史 |

E18 必须覆盖真实目标文件系统、SQLCipher 与系统密钥项，宿主替身只能验证状态分支；E20 的“空白”不能复用同进程缓存的旧钥；E22 的数据库冻结实验不代替真实网络、目标导入与本机切换。T21 的已删除账号控制与本地交易删除分开，旧归档数据不能为原账号重新授予远端权限。

## 5. 实施任务与证据

以下按完整能力列出实施任务；E-CSV 的输入预览、持久批次及现有模型内的受限撤销见第 5.1–5.3 节，E-SNAPSHOT 的只读宿主候选见第 5.4 节，认证容器与受保护暂存宿主候选见第 5.5–5.7 节。活动条件发布、暂存物化及恢复库只读捕获的宿主证据见第 5.8–5.10 节。入口存在不代表完整 E01–E24 已通过。实施前依任务范围说明版本、依赖、数据 / 端口 / 运行时长和精确清理范围，只使用合成输入，不操作真实账单或生产秘密。

### 5.1 E-CSV 输入预览候选

Rust 入口 [`csv_import::preview`](../../crates/ledger-core/src/csv_import.rs) 接收当前已解锁 Store、借用的输入字节、显式 Mapping 和取消标志；底层 [`csv_input.rs`](../../crates/ledger-core/src/csv_input.rs) 是本项目自写的小型严格状态机，不引入第三方 parser 依赖。该选择用于有界实验方言，不宣称替代完整 CSV 生态；扩大方言前需比较维护成本与可选库，不能不断追加静默修复。

`m0-csv-preview-v1` 仅是实验 profile，支持范围如下：

| 项目 | 本切片行为 |
| --- | --- |
| 输入 | UTF-8；文件首 BOM 识别并报告；记录分隔 LF / CRLF，字段内换行按原文保留；逗号 / 双引号引用与双引号加倍；末尾可无换行。记录外单独 CR、未闭合 / 非法位置引号、NUL、非法 UTF-8 拒绝 |
| 结构 | Mapping 指定有 / 无表头，每个输入列按位置映射到一个业务字段或显式 Ignore；空 / 重复表头、列宽不一致、重复业务字段映射整份拒绝。不猜表头 / 方言、不 trim 文本；全空额外行不静默跳过 |
| 字段 | 必需 Kind、Amount、Date、Currency；可选 Account、Category、FromAccount、ToAccount、SourceId、Note。收入 / 支出 / 独立退款需账户 / 类别，转账 / 还款需两个账户；由现有 Event 校验约束，额外冲突引用也拒绝 |
| 格式 | 精确 `CNY`、`YYYY-MM-DD`；金额复用 parse_yuan 的十进制元输入，接受整数 / 一位 / 两位小数，输出规范整数分。不会按负号猜类型、去除外围空格、使用浮点或补日期 |
| 映射 | 调用方明确来源类型到 EventKind、账户 / 类别标签到既有稳定 ID；类型名与名称均原样匹配。来源命名空间非空、最多 128 字节，仅 ASCII 字母 / 数字 / `-_.`；引用 ID 复用核心身份校验 |
| 尚未支持 | 期初、差额调整返回 csv_unsupported_kind；未映射类型 / 引用、未知币种明确逐行错误。此 preview 函数不发布；持久任务 / 显式跳过 / 批次见第 5.2 节。新建引用、UI 确认、撤销、跨库 runtime、CSV 导出、归档与迁移未接入 |

固定实验预算为输入 1 MiB（含 BOM）、解码后每字段 4096 字节、每记录 16 列、业务记录 1000 条（表头另计一条）；三类名称映射各最多 256 项、每名称 256 字节。文件总预算同时约束累计解码工作；此 API 不负责从文件流有界读取，未来文件适配层必须在申请大缓冲前检查上限，不能先无限 read 再调用本入口。三组主要解析边界及文件字节都按 limit−1 / limit / limit+1 运行，Unicode 以字节计，不是字符数。

文件结构 / 映射错误使整份预览失败；可定位的业务错误保留逻辑记录号和具体核心错误，其他行仍可查看。全部候选在 Store 的同一个只读事务中复用正常提交的引用 / 归档 / 类别类型校验，报告该读取点的 sequence；存储错误中止整个预览，不变成普通坏行或空数据。sequence 并不覆盖所有未来引用变化，也不是目标库身份或提交许可，真正发布时必须重检。

每行保留独立 Candidate 与备注。相同来源 ID 的 Event + Note 完全相同给文件内重复提示；不一致或其中一行无法形成候选时，全组标来源冲突。Ignored 列不参与该语义比较。两种结果均不自动删除 / 跳过任何记录；无来源 ID 的相同消费也保留两行。本 preview 函数不查询持久历史，因此 UniqueInFile 只表示本文件未重复，不能显示为“从未导入”。来源 ID 来自输入，不因进入预览就自动成为可信来源证明。

结果包含 profile、精确输入字节 SHA-256、当前固定 Rust 映射序列化与 profile 的内部比较指纹、BOM 和忽略列提示及逐行结果。字段 / 映射改变必须重新预览；这些指纹不是公开密码编码、授权 token 或持久行身份。逻辑记录号只定位本预览，不能直接充当未来跨任务去重键。此预览仍将备注原文留在 Candidate；第 5.2 节确认时将它一并写入 Event.note、修订和意图，不允许丢弃备注后逐行调用 commit 冒充完整导入。

解析、映射、引用核验与最终返回前均检查取消；取消返回明确错误而不返回半份成功预览。输入 / 结果仅在调用方内存，包含用户内容的 Preview / Row / Candidate 不提供 Debug / Serialize，仍须由调用方按敏感内容管理。该入口没有文件选择 / 日志 / 上传 / 明文临时文件行为；未证明锁屏 UI、运行时内存绝对清零或文件提供方权限。

机器材料 [`csv-preview-cases.json`](csv-preview-cases.json) 人工编写 A01 六行输入、独立引用 / 文本预期、12 个语法向量和 14 个业务拒绝行；数值 / 事件 / 统计预期仍来自 accounting-cases.json，不由本 parser 或 exporter 生成。测试在真实 SQLCipher 中建合成引用 / 期初，预览后核对完整账务 digest / outbox 不变；候选累计投影对照 A01 各检查点，不将其计作导入持久化。双连接在读取点后提交归档，验证单份预览不混合前后引用状态；另测只读重开、取消和损坏表结构的存储错误传播。

复现 `CARGO_NET_OFFLINE=true cargo test --locked -p radishledger-core csv_import::tests --jobs 4`，需要已缓存锁定工具链 / 依赖。普通 `check-core.sh` / Core Quality 自动发现这些真实核心测试；临时合成库由 tempfile 清理。实际通过数量与范围见 current / devlog；E01 仅输入 / 投影部分、E02–E04 / E06 的相关预览边界取得本入口证据，该入口不覆盖 E05 批次发布；持久验证见下一节，受限撤销见第 5.3 节，E08 导出仍未完成。

### 5.2 E-CSV 持久任务与原子发布候选

[`csv_store.rs`](../../crates/ledger-core/src/csv_store.rs) 在现有 Store 上实现以下实验流程，仍只接收合成输入，不提供 Flutter / FFI 或用户文件入口：

1. `Store::create_csv_experiment` 仅独占新建 schema `2` 的加密库和随机目标身份；`Store::create` / 既有移动实验继续使用 schema `1`。新版 open 接受 v1 / v2 及第 5.3 节新增的 v3，不自动迁移、覆盖或降级旧库；创建中断留下的文件需按任务归属核对，不因无法打开而重建。
2. `csv_import::prepare` 复制有界输入、固定 Mapping，并联合预览 sequence 检查持久来源。Prepared 字段不可由外部改写；确认使用已复制字节，不再读取原路径。原文件或映射要改变时必须重新 prepare。相同文件 fingerprint 的历史任务 ID 会列出，即使映射不同；调用方可查询这些任务的范围。它不是自动去重或恢复授权。
3. `save_csv_task` 要求调用方预先固定 task_id、逐行选择 Import / Skip 和每批 1–100 条逻辑记录。该事务保存原输入 BLOB、映射 / 选择 / profile、随机行 / 交易 / 修订 / 操作身份及完整意图；不产生有效账务。同 task_id 同计划重试返回原状态，换输入 / 映射 / 选择 / 批宽拒绝；过期预览、错误选中行、目标不符或来源重复拒绝整份登记。明确 Skip 的行保留其逻辑位置和选择，不静默丢失。
4. `publish_csv_batch(target_id, task_id, first_record, ...)` 只接受下一个固定范围，最多 100 行，单行转账不拆分。IMMEDIATE 事务核对目标、profile、进度、引用、归档和来源，再复用单笔 `apply_write` 写入事实 / selected / outbox / sequence，与来源、行结果、批次回执及任务进度一起提交。第二行拒绝也回滚第一行；其他连接只见完整提交前或提交后。sequence 仍按业务行递增，不代表服务端批次序号。
5. `csv_tasks` / `csv_task` / `csv_task_rows` 供重开核对固定身份及 pending / imported / skipped 范围；不会自动继续。重复提交已完成范围返回原回执，不重新核对已发生的编辑 / 删除，也不再生成事实。`set_csv_cancelled` 持久停止后续批次，恢复需显式调用；取消信号在提交前可回滚本批，提交后不将成功伪装为撤回。调用方丢失结果时必须查原任务 / 原批次。

Event.note 为最多 4096 UTF-8 字节、不含 NUL 的原文；空备注保持旧序列化字节，无 note 的旧事实可读。v1 拒绝非空备注写入；v2 把备注纳入修订正文、原意图幂等比较和来源内容比较，名称 / 金额 / 日期仍用原领域边界。修订读取、后续编辑和正常删除沿既有入口；来源绑定保留最初导入内容及原修订，不因后续编辑或删除而释放，因此重导不会自动复活。

来源键为本库内 namespace + source_id。持久同键同内容显示 PreviouslyImported，导入需明确跳过；同键异内容拒绝覆盖。同文件重复来源只能选其中一条，其余明确 Skip；两个待发任务竞争同一来源时后发布者拒绝整批。无来源 ID 的相同行保留为两笔；同任务重试靠持久身份防重，新任务须显式选择，不能凭内容 hash 自动删重。来源可信度仍由未来适配和用户确认处理。

本候选的 outbox 沿用每笔 Write，批次关系由固定 csv_rows 身份 / 范围与 csv_batches 回执持久保留，均在同一事务。没有同步发送器或冻结的 D-ENVELOPE；未来发送必须利用批次关系保持服务端原子语义，不能逐笔发送后宣称同步批次已完成。目标身份只隔离本机实验库，不替代实例 / 域 / runtime / restore generation；复制库、新域恢复和迟到回调须另按正式恢复契约实现。

验证入口为 `CARGO_NET_OFFLINE=true cargo test --locked -p radishledger-core csv_ --jobs 4`，完整核心检查仍为 `check-core.sh`。共用手写输入和 A01 JSON：两批 r1–r3 / r4–r6 的实际投影分别对照 dining / refund，原备注逐条核对修订及 outbox；额外覆盖批宽 0 / 1 / 99 / 100 / 101、备注字节边界、错误行跳过、v1 保全、任务幂等、目标 / profile / 进度拒绝、取消 / 恢复、来源隔离及编辑删除后重导。

真实 SQLCipher 双连接验证事务中不可见和第二行引用失败的全批回滚；触发器制造真实 SQL 错误，核对登记或发布没有半状态。五个独立进程强杀点分别位于首笔事实后、来源后、进度前、COMMIT 前及 COMMIT 后未返回确认：普通入口重开后比较包括输入 / 任务 / 来源 / 进度 / 账务 / outbox 的完整 digest，再以原身份重试。子进程仅用父测试独占的 tempfile 目录，随机合成 key 通过 stdin 匿名管道传入；单进程等待上限 20 秒，父测试 Drop 终止并回收，目录由 tempfile 清理。ignored worker 是父测试实际调用入口，不是遗漏的业务测试。

这些证据覆盖 E01 的六行发布分支、E02 的备注持久化、E04 的来源 / 原身份重试、E05 的本机批次中断及 E06 的目标 / 输入固定 / 引用重检。受限撤销的新增范围见下一节；期初 / 调整、新建引用、真实 IO / 掉电、移动 UI / runtime 切换、生产资源上限、导出 / 归档 / 迁移仍未完成；不据此关闭完整 E01–E08 或 M0-E。v1 / v2 是隔离实验格式，未运行旧二进制读取 v2，也未交付旧库升级工具。

### 5.3 E-CSV 受限撤销候选

公开 Rust 类型见 [`csv_undo.rs`](../../crates/ledger-core/src/csv_undo.rs)，存储入口见 [`csv_undo_store.rs`](../../crates/ledger-core/src/csv_undo_store.rs)。只对当前独立交易模型进行宿主验证，不创建移动入口、通用依赖框架或同步发送器。

1. `Store::create_csv_undo_experiment` 独占新建 schema `3` 库：复用 v2 的输入、来源、行与批次布局，新增撤销任务、行意图和批次回执。v1 / v2 可按原有能力打开，撤销入口明确拒绝这两个版本，不隐式加表或升级。v3 允许与 v2 相同的备注 / 导入写入；既有移动实验仍新建 v1。创建失败保留本次创建文件供精确核对，不自动删除或重建。
2. `preview_csv_undo(target_id, import_task_id, ...)` 在同一只读快照列出全部逻辑行，核对原导入修订、来源绑定、当前所选修订、额外历史与候选。未完成 / 已跳过、后续编辑 / 恢复、已删除、冲突候选、额外未选历史及已撤销行分别受限。原证据缺失、损坏或未知 Event 字段导致整体失败，不将损坏解释成空集合。预览不改变账务或任务。
3. `save_csv_undo` 接收不可外改的 Preview、严格升序的显式记录集合、调用方预先固定的撤销 ID 和每批 1–100 行。最多确认 1000 行，空集合、重复 / 越界 / 受限记录拒绝。登记时重检条件，持久保存确认集合与随机删除 operation / revision 身份，不发布删除；同身份同计划返回原进度，改变原任务、集合或批宽拒绝。登记不是对未来修订的删除授权。
4. `publish_csv_undo_batch(target_id, undo_id, first_ordinal, ...)` 按确认集合的一基序号调度，不能将其当作 CSV 原记录号。IMMEDIATE 事务先重检本批全部原行身份、原修订、来源、当前版本和候选，再复用 `apply_write` 写正常删除修订、selected、outbox、sequence，与逐行结果、回执及撤销进度一起提交。任一竞争或 SQL 失败拒绝整批，其他连接只见完整前 / 后状态。此前已完成批次保留；重新预览后需用新的确认计划，不能跳过竞争行后继续使用旧集合。
5. `csv_undo_tasks` / `csv_undo_task` / `csv_undo_rows` 供重开核对原任务、身份及已完成范围，不自动继续。`set_csv_undo_cancelled` 持久停止新批次，恢复需显式调用；提交前取消回滚本批，提交后返回真实结果。原回执优先于取消和当前版本变化，重复提交不产生新删除；即使后来显式恢复交易，也不能用旧撤销重试再次删除新修订。
6. 原导入任务、行结果、来源内容和原批次均保留。稳定来源同键重导仍识别为 PreviouslyImported，异内容仍拒绝；原导入任务重试不会复活删除。无来源 ID 时沿用原任务防重，新任务仍需显式确认，不能凭内容相等推定是同一业务。共享账户 / 分类及其归档状态不因撤销交易而删除或改变。

真实 SQLCipher 证据包括 E07 的 r1 备注编辑排除、r2 在登记后只改备注导致整批拒绝且仍为 A01 `refund.expected`，重新确认 r3–r6 后为 `transfer.expected`；同时核对原 r1 / r2 新修订、有效 / 删除集合、删除 predecessor、outbox、来源与原批次，统计直接引用原 A01 JSON。双连接覆盖预览期间并发编辑的一致快照、提交前后可见性、候选竞争和两个确认任务竞争。人工注入的额外未选历史 / 未知关联字段只证明保守停止，不代表已实现关联交易或同步接收流程。

登记 / outbox / 第二行进度 / 回执 / 任务更新的真实 SQL 拒绝、事务各点失败与取消、确认丢失、持久取消 / 重开 / 显式恢复均核对完整内容。父测试先提交第一撤销批，再在第二批首个删除后、行结果后、进度前、COMMIT 前及 COMMIT 后未返回确认五点分别 SIGKILL 专属子进程。普通入口重开只见完整旧 / 新状态，保留第一批并以原删除身份重试；另核对独立笔数与删除事实，不只依赖完整提交副本的 digest。

定向复现：`CARGO_NET_OFFLINE=true cargo test --locked -p radishledger-core csv_undo --jobs 4`；全部 CSV 用例仍使用 `csv_` 过滤，聚合入口仍为 `check-core.sh`。依赖 / 工具链均沿用锁定版本，无新依赖、设备、服务或宿主端口；只用 tempfile 独占合成库，子进程 key 经匿名 stdin、单 worker 等待上限 20 秒、Drop 终止并回收，结束清理本次临时目录。ignored worker 由父测试实际调用，不算缺失的强杀验收；精确数量和运行环境见 [11 月 devlog](../devlogs/2026-11.md)。

本切片关闭现有平坦交易模型内 E07 的预览 / 竞争 / 删除 / 恢复风险，不关闭完整 E07、E-CSV 或 M0-E。新建账户后来被引用的 E07 分支、交易间引用 / 复杂关联、旧 v1 / v2 升级、移动 UI / runtime、真实 IO / 掉电与同步批次发送均未实现 / 未验证；新建引用和关联模型进入后须补依赖判定，未能证明安全的范围保持阻塞。v3 仍非冻结格式，无旧二进制读取或设备兼容结论；E-SNAPSHOT 必须把新增撤销任务、确认身份、原意图、行结果和回执纳入保全集合。

### 5.4 E-SNAPSHOT 最小一致逻辑快照候选

类型与有界编码见 [`logical_snapshot.rs`](../../crates/ledger-core/src/logical_snapshot.rs)，单一事务读取见 [`snapshot_store.rs`](../../crates/ledger-core/src/snapshot_store.rs)，关系校验见 [`snapshot_validate.rs`](../../crates/ledger-core/src/snapshot_validate.rs)。`Store::logical_snapshot(limits, months, cancel)` 返回本机声明集合与核对清单，`LogicalSnapshot::encode` 显式输出有界内存 JSON；没有写归档、解码、恢复或活动切换入口。

| 声明集合 | 捕获与核对边界 |
| --- | --- |
| 头部与范围 | 内部 profile `m0-logical-snapshot-v1`、源实验 schema / sequence、既有 CNY / 分精度；远端范围固定为 unknown，不伪造确认 / cursor。原 CSV 目标 ID 仅作来源证据，v1 无此身份；不作为生产 Book、归档身份、新 runtime 或同步域 |
| 账户与分类 | 稳定 ID、kind、名称、归档状态，保留合法历史归档引用；不以“新交易不可引用归档对象”删除历史 |
| 事实与修订 | 当前实验库全部 revisions，包括 parent、原文 Event、删除空 payload；selected 与全部 candidates 独立保存。校验根、同事件 parent、无环、完整引用、金额 / 日期 / 类型，以及所选候选关系，不只读取有效事实 |
| 业务意图历史 | 读取全部 outbox 的原 Write 语义，核对 operation / revision 及正文关系。复用单一 Write 类型，拒绝未知字段；不包含 envelope、服务授权或传输状态，不自动激活旧意图。当前模型没有已确认 / 未确认分类，不能从队列存在推断远端状态 |
| 导入历史 | v2 / v3 的输入与映射 fingerprint、解析 profile、显式 Mapping / Import / Skip、task / target / 随机行身份、原计划意图、pending / imported / skipped、来源内容与绑定、批宽 / 进度 / 回执；交叉核对选择、已提交修订 / 意图及连续批次 |
| 撤销历史 | v3 的原任务与确认集合、行 / 原修订绑定、删除 operation / revision、pending / deleted、取消 / 完成状态、进度与连续回执；可保留因后续编辑而失效但尚未执行的计划，不误当作损坏或自动续做 |
| 核对清单 | 从捕获的 selected 原文重建有效 / 删除 / 候选集合、账户余额、资产负债和显式月份报表；不再读取另一个时点的数据库汇总。共同账务 JSON 是独立数值来源 |

源 schema 1–3 均为明确候选，读取不升级库、不修改 sequence 或任务。未知版本、未声明业务表 / 列布局、缺表、未知正文 / 意图字段、缺 parent / 引用、环、所选版本错配、来源或进度 / 回执不一致明确失败。bootstrap_identity / bootstrap_fixture 与 SQLite 内部表明确排除，不读取其中内容；原 CSV BLOB 和原 request 字符串不作为输出，后者只解出必需的显式语义。输入 fingerprint 作为原登记证据保留，本批未重新读取原 CSV 校验其 hash；后续恢复必须由用户重新提供匹配文件并重新确认。

读取在一个 SQLCipher 只读事务中完成，以同一快照覆盖元数据、引用、修订、选择 / 候选、意图、任务与清单；事务结束后持有稳定内存对象。schema / 关系校验不把历史档案当作“重新录入”，已归档引用仍允许。各集合按稳定 ID 或任务序号排序，JSON 固定字段次序，嵌入正文先解为既有类型再编码；同语义不因物理页布局、JSON key 顺序或空白改变候选字节。未包含捕获时间或随机归档 ID，不因此声称已定义正式归档身份、规范编码或认证摘要。

调用方显式提供行数与声明字段读取字节预算，实验硬上限为 100,000 行 / 16 MiB，编码另有至多 16 MiB 的显式预算，月份最多 120 项且在复制前校验。读取字节按实际选中 UTF-8 字段及每个整数 8 字节计，NULL 不计；复制 / JSON 解析前逐字段扣账，逐行检查取消。它不衡量 SQLite 页缓存、排除的原始文件、分配器峰值或真机性能，数值不冻结为生产容量。编码逐次写入检查预算 / 取消；失败不返回部分对象或部分字节，源库不改写。读取事务会保留 WAL 读取基线，本批只证明有界工作负载并发，不承诺任意大库长期读事务。

真实 SQLCipher 验证：A11 保全 8 个修订、7 个原意图、2 个候选及 1 个删除，并逐项对照原 parent / 数值和完整集合；A04 `delete` 捕获后，另一连接在七个读取边界分别提交 `restore`，旧快照始终符合 `delete.expected`，活动库符合 `restore.expected`。A06 `renamed` 的归档引用 / 名称及全部共同账务案例末状态按原 JSON 复核。v3 独立合成任务保留已发布、跳过、未完成导入及已完成一部分的取消撤销，逐项核对原行 / 删除身份，重开捕获不自动继续；排除标记证明原 CSV 与 bootstrap 内容没有进入输出。另测读取 / 编码预算 limit−1 / limit / limit+1、七处取消 / 失败、损坏关系 / 任务 / 意图拒绝、只读重开、VACUUM 与 JSON key / 空白变化后的稳定编码。

复现：`CARGO_NET_OFFLINE=true cargo test --locked -p radishledger-core snapshot_store --jobs 4`；聚合仍由 `check-core.sh` 自动发现。沿用锁定工具链和缓存依赖，不启动服务 / 设备、不访问系统密钥；合成库由 tempfile 独占创建并清理，不输出账务或秘密到日志。精确结果见 [11 月记录](../devlogs/2026-11.md)。

本入口只覆盖 E09 的宿主捕获和 E13 / E14 / E16 的部分事实读取 / 关系前置，不关闭这些完整案例、E-SNAPSHOT 的生产交付或 M0-E。本捕获层不承担认证容器或解码；宿主内存封装与独立密码向量见第 5.6 节。暂存恢复、空白设备、旧域确认 / 新读取基线、完整非秘密设置和生产 Book 身份仍缺证据；真实读取 IO 故障、捕获中强杀 / 掉电、移动内存 / 长期 WAL 表现尚未验证。候选 JSON 不作为用户备份格式；接续顺位只维护在 current。

### 5.5 E-CONTAINER 评审材料与输入

候选构造与唯一字节表见[可迁移性第 3.2.1–3.2.6 节](../data-portability.md#321-e-container-首个宿主候选与实施边界)，机器输入见 [`archive-container-review-inputs.json`](archive-container-review-inputs.json)。所有者已批准宿主实验，候选仍未冻结；实际实现、证据与未覆盖项见下一节。

- 候选为有界整体 XChaCha20-Poly1305、无压缩 / 无加密续写，176-byte 固定公开头，独立随机 Archive Key 与归档用途 HKDF 标签；KDF 沿用当前 64 MiB / 3 / 1 宿主候选，不将其与 RFC 9106 的 4 路推荐组合混同。
- 公开 S / M / B 为 518 / 116 / 654 字节，完整密文为 846 字节。材料版本 2 保留人工输入与 framing 预期，并补入先于 Rust encoder 生成的独立 Go Argon2id / HKDF / XChaCha 输出、完整密文及来源指纹；没有用生产 encoder 自生 expected。
- R01–R24 是 E10–E12、E15–E16 的输入 / 调度细化，不替代原案例编号。`hostTest` 映射实际 Rust 测试；不以 24 个输入编号宣称 24 项独立业务测试。R24 是合成阶段取消 / 共享名额验证，不代表原生 KDF 中途抢占或移动 UI 延迟。
- `python3.14 -B scripts/check-archive-review.py` 仅用 Python 3.11+ 标准库核对固定偏移、SHA、AAD、11 个预检调度及独立输出 / 源码指纹。它不执行密码算法、产品 codec 或恢复，不接收用户文件，不加入 Core Quality 冒充业务门禁。

### 5.6 E-CONTAINER 宿主内存封装与有界解封

`archive_container::seal` 接收 E-SNAPSHOT、原始 UTF-8 口令、显式 `Limits` 和取消标志，每次使用系统新随机材料，返回仅可显式借用的 `SealedArchive`。`open` 接收有界密文，在全部认证与业务校验通过后返回 `OpenedArchive` 的逻辑 `Contents`；不伪造原库捕获统计，不提供旧域运行权限、恢复写入或活动切换。实现沿用锁定依赖，无新增 schema、生产 ABI 或移动入口。

公开版本 / 长度 / flags / suite / KDF 白名单在昂贵调用前拒绝；封装失败为 `archive_unlock_failed`（“口令不正确或归档损坏”），封装成功后正文失败为 `archive_content_auth_failed`。认证成功后还要核对清单、原始 payload SHA、长度 / 终结、唯一 JSON 键、未知字段、完整事实图及从事实重建的核对报告；业务非法为 `invalid_archive_payload`，超预算和取消分别保留。调用复用原 M0-C 的一个 KDF 名额，忙则拒绝；原始 Argon2id 提取后仍保留旧派生标签 / salt 的字节兼容。

| 实际宿主测试组 | 核对范围 |
| --- | --- |
| 独立向量与口令身份 | Go 全容器与 Rust 逐字节相同；原始 Argon2id、两用途密钥、两层密文、旧 M0-C 派生及 NFC / NFD 原始字节分别匹配；直接打开 Go 密文 |
| KDF 前拒绝 | 持有真实执行名额调用非法头、版本 / 参数、截断 / 附加 / 超限密文，仍得到预检错误而非 `kdf_busy`；弱 / 极端参数不触发 KDF |
| 认证分层 | 错口令、salt / ID / nonce / 封装变化、正文 / tag 变化与等长跨归档拼接失败；正文每个字节的变化另经底层 AEAD 对照，不宣称对每字节都重跑完整 KDF |
| 认证后非法载荷 | 合法 AEAD 下错误清单 / hash / 数量 / 长度 / 终结、非法 UTF-8、BOM / 多顶层值、重复及转义重复键、未知字段、虚假汇总、缺 parent / 引用均拒绝；观测点证明已越过正文认证 |

| 取消 / 失败 / 重试 | KDF 前后、封装 / 正文 / JSON / 返回边界合成注入；原语执行和工作块清理期间名额仍占用；结果不发布、源 SQLCipher 内容不变、重试成功并使用新随机材料 |

复现：`CARGO_NET_OFFLINE=true cargo test --locked -p radishledger-core archive_container --jobs 4`，也由 `check-core.sh` 的 workspace all-features 测试自动执行。本批最终新增 13 项全部通过；全量结果、精确工具版本及非秘密日志见 [11 月 devlog](../devlogs/2026-11.md#2026-11-03-e-container-已批准宿主实现与独立向量)。使用 tempfile 独占合成 SQLCipher 库与内存缓冲，不启动服务 / 设备、访问系统项或下载依赖。

### 5.7 E-RESTORE 受保护暂存宿主候选

定向命令为 `CARGO_NET_OFFLINE=true cargo test --locked -p radishledger-core restore_stage::tests --jobs 4`，也由 `check-core.sh` 自动发现。子进程仅处理本批 tempfile 合成目录，随机暂存钥经匿名 stdin，单 worker 等待上限 20 秒，父进程回收自己启动的 worker；不把 ignored 子入口单独计作通过。精确运行数量 / 版本、过程修正和输出见[11 月 devlog](../devlogs/2026-11.md#2026-11-03-e-restore-受保护暂存与真实中断恢复)。

文件阶段判定见[暂存契约](../data-portability.md#411-e-restore-受保护暂存宿主候选)。旧实现曾在缺少已验证数据库时返回准备成功；本轮先复现该行为，再用以上用例验证拒绝和保全。

完整 E13 / E16–E20、E-RESTORE、M0-E 和 M0 仍待验收。暂存钥尚无平台保护 / 持久化，设备重启后需已有安全通道提供原暂存钥；若钥遗失，仅能保留现场并从归档新建另一任务。旧活动身份 / 核对点、停止旧写 / 在途操作、新 bootstrap / 系统项、条件选择发布与结果未定恢复、空白设备 / 新域基线尚未实施。owner 原子替换内部各 IO 点、实际目录同步失败、真实容量不足 / IO / 掉电与移动峰值 / UI 仍缺证据。同 UID 对私有目录的恶意替换竞争仍在实验边界之外。

### 5.8 E18 与 E19 活动条件发布宿主验收候选

按[活动条件发布候选](../data-portability.md#412-e-restore-活动条件发布评审候选)准备 O 和 N 两个具有独立合成钥与绑定的真实 SQLCipher 库，控制目录排他使用本批 tempfile。预期由下表和已有 A11 共同材料给出。对两库核对绑定、全部业务集合及独立统计，并检查未同步原意图和暂存任务未被移动或清除。控制文件只记非秘密身份，子进程的合成钥沿既有匿名通道传递。

| 归属 | 调度 | 独立预期 |
| --- | --- | --- |
| E18 正常发布与丢响应 | 旧核对点一致，新目标绑定 / 事实正确；正式选择同步后、成功响应前结束进程 | 重开精确识别同一 P-new，O 与归档保留；同次查询不会再次发布。N 后来有日常新写时仍保留，不能因查询旧结果而恢复 N 的初始内容。 |
| E19 核对点变化 | 确认后 O 分别增加一笔未同步交易、添加不推进 `sequence` 的账户、仅取消已有 CSV 任务 | 三条都保全 O 的新变化并使旧确认失效；P-old 仍生效，N 和选择记录保持原样。至少一条明确断言 `sequence` 相等但快照内容不同。 |
| E19 写入竞争与晚结果 | 旧写先持共同锁，切换尝试进入；另一路旧写停在门禁前，待切换后再尝试；延迟交付旧成功 | 前者的提交只能归 O，切换重读后发现差异。后者用原选择 / runtime 上下文被拒绝，不能改投 N。旧成功不更新 N 的活动状态。 |
| E18 文件中断 | 分别在未定记录发布前后、选择临时写入 / 文件同步、原子替换前后、目录同步、重开核对及未定记录撤除前后注入失败；主要边界另用子进程 SIGKILL | 重开仅接受与未定记录相符的完整 P-old 或 P-new。P-old 允许恢复旧库并重新确认；P-new 必须核对新库后才能放行。阻断写入期间两库与原归档均保全。 |
| E18 无法确定或解锁 | 选择缺失、损坏、指向不匹配的库或候选钥不可用；分别在发布前和 P-new 已出现后触发 | 发布前钥失败保留 P-old；P-new 已出现时保持选中新库并报告不可用。记录不一致时保留现场并阻塞写入。 |
| E18 / E19 取消、并发重试 | 在替换前取消和替换后丢响应分别重试；同一身份并发请求，另用已过期身份请求 | 确认旧选择后才报告未切换，已生效显示真实结果；同一身份只核对，过期身份不重新发布。清理未定记录后首次写入仍需核对持久选择。 |

宿主入口为 [`restore_selection`](../../crates/ledger-core/src/restore_selection.rs)。在 Darwin arm64 执行 `CARGO_NET_OFFLINE=true cargo test --locked -p radishledger-core restore_selection --jobs 4`，9 项通过。两库由 A11 共同材料独立填充，候选逐项核对 8 个修订、2 个候选、1 个删除、7 个原意图。每轮比较两库真实内容，旧库添加交易、仅添加账户和仅改变 CSV 取消状态均使旧确认失效，后二者的 `sequence` 保持不变。跨进程锁竞争、旧成功回调归属、候选键不可用 / 绑定或事实改变、控制记录缺失 / 损坏 / 不匹配和取消点均有定向检查。

分别对未定记录和活动选择注入部分写入后零写 / 错误、文件同步、替换与父目录同步故障。另在重开核对及撤除未定记录后注入失败。父测试在登记前后、选择发布后、目标重开核对后、撤除未定记录后及最终同步后共 6 个点实际 SIGKILL；已生效的选择可重复核对，且其后在 N 中提交的新事实仍保留。目录同步故障由共享文件原语注入，强杀是进程中断证据。两库由共同样例独立填充，本批未生成或物化真实归档。真实设备系统密钥、设备文件保护、掉电、正式写入入口的覆盖、暂存物化和 E20 仍待验收。

### 5.9 暂存物化宿主验收候选

按[物化契约](../data-portability.md#413-e-restore-可运行候选库物化评审)用实际加密归档和暂存核对取得输入，派生独占的新 N。验收从 N 的实际 SQLCipher 表读取事实和历史。原账务样例提供独立预期，另核对稳定 ID、关系、任务权限和活动选择。只使用合成数据、独立目录和合成钥。

| 归属 | 调度 | 独立预期 |
| --- | --- | --- |
| E13 / E14 事实与历史保真 | 分别物化 A11 `conflict`、A06 `renamed`、A04 `delete`；A04 另让 O 推进至 `restore` | N 的所选、修订链、原意图、删除、候选和统计分别符合原共同样例。历史归档引用保留。A04 的 O 保留后续变化，N 仍是源捕获点。 |
| E16 CSV 与来源查重 | 物化 v2 未完成导入、v3 部分撤销；在 N 重新预览相同及改动的来源，包含原事实已删除的情况 | 原任务、行、批次回执、进度和关系完整。相同来源指回原事实，内容漂移明确冲突。旧任务与原未提交意图无法直接运行，活动 outbox 从空开始。 |
| E17 原身份重试 | 在 N 归属登记、事务提交前后、关闭 / 重开与报告前取消、注入失败或终止进程；另测归属 / 输入变化、已建库缺失、错误或不可用的新钥 | 原 N 只能按原身份和新钥续作。提交前不留半批事实，提交后重开核对完整数据。身份、文件或钥不可证时停止保全，O、原归档和暂存保持完整。 |
| E18 / E19 交接与独立新写 | 让真实物化 N 进入宿主条件选择，测试 O 变化后拒绝切换、重核后正常选择、原上下文迟到，以及 N 上的正常新写与重开 | O 变化保全且旧确认失效。N 生效后正常新写只提交到 N，原业务历史仍在，运行 outbox 只含本机新意图。旧任务、旧序号和旧操作身份不能获得新写权限。 |
| E17 / E18 放弃与发布竞争 | 分别在 N 未选中、被未定记录引用、已选中或归属缺失时请求清理；让清理与发布竞争共同锁 | 仅确证未选且归属匹配的 N 可在明确确认后精确清理。其余停止并保留。清理不会触碰 O、原归档、原暂存或其他任务。 |

Darwin arm64 宿主执行 `CARGO_NET_OFFLINE=true cargo test --locked -p radishledger-core restore_materialization --jobs 4`，6 项通过。A11、A06、A04 与原共同样例的独立预期一致，A04 的旧库仍保留归档捕获后的恢复。v2 未完成导入和 v3 部分撤销在 N 中仍可查重，已删除事实的来源也能匹配。改动来源内容报告冲突，旧任务入口及旧操作 ID 被拒绝。原库和暂存的 DB Key 无法解锁 N，常规 Store 和旧快照入口显式拒绝 schema 1002。

父测试在 N 的加密绑定登记后、事实提交前、提交后和重开核对后实际 SIGKILL。前两处无部分事实，后两处完整保留；同一 Ticket 和新钥可继续。另覆盖取消、错钥、原归档字节变化、源任务错配、已建库后缺失、额外 trigger 及原操作索引损坏。真实 N 在 O 变化后拒绝旧确认，重核选择后正常提交新本地交易，原历史保留、活动 outbox 只含新意图；旧回调无法写入新库。归属缺失、选择未定或 N 已生效时拒绝清理；清理和发布使用同一锁。选择结果未定且已指向 N 时，新钥暂不可用会保留选择和未定记录，钥恢复后才完成核对。

再次归档须保全恢复历史与新写入，验收预期见第 5.10 节。平台 bootstrap、文件保护、实际磁盘故障和掉电、E20 空白设备及 D / E 新域仍待验收。

### 5.10 恢复后再次归档验收候选

按[再次归档契约](../data-portability.md#414-e-restore-恢复后再次归档评审)使用实际加密归档和已经选中的物化库。期望来自 A11 / A04 / CSV 共同材料与手算新增交易影响。旧读者与新格式向量使用相互独立的材料，捕获端的摘要只能辅助核对。

| 归属 | 调度 | 独立预期 |
| --- | --- | --- |
| E09 一致捕获 | N 完成一次带本地观察点的写入；捕获边界同时尝试第二笔写入及一项不推进 sequence 的账户变化；另以旧选择和未定选择调用 | 捕获对应实际的一个读点。修订、所选、意图、账户和统计全部属于该点；旧选择和未定选择拒绝。 |
| E13 / E14 修订与序号 | 从 A11 恢复，在 N 新增带备注交易；从 A04 的删除状态恢复，在 N 用新修订恢复原事件。构造认证有效但把意图放到观察序号不足的段、同操作 ID 跨段重复、历史意图与实际修订内容不符的归档 | 真实捕获保留 A11 候选及原历史，并按新增交易手算统计；A04 当前所选为新修订，原删除修订仍在。原 sequence 与 N 的 sequence 分开，异常载荷全部拒绝。 |
| E16 CSV 与身份 | 从 v2 未完成导入、v3 部分撤销恢复，在 N 做新账务；尝试用新操作复用原未提交计划的修订或导入事件身份。分别篡改来源索引、历史任务或原计划状态 | 新写不能占用原计划的保留身份。有效捕获保留旧任务、批次和来源；新库重新预览已编辑或删除事实的来源仍识别原绑定，内容变化明确冲突；篡改材料拒绝。 |
| E16 版本与认证 | 旧读者读 0.2、新读者读旧独立向量；另验证独立 0.2 非空向量，调度错口令、头版本篡改和重新认证的头 / 清单 profile 混搭、段数 / 数量错误、未知必需字段 | 旧读者在 KDF 前明确拒绝 0.2，新读者保留 0.1 语义；0.2 向量核对完整字节和解码事实，混搭、认证或业务非法均无可用结果。 |
| E09 / E16 累计预算与取消 | 合法边界和超出一单位，覆盖多段总数、总记录和字节；在捕获、编码和 KDF 前后取消 | 所有段共用预算。失败或取消无可用归档，原库及旧归档保持完整，释放锁后可重试。 |
| E17 独立恢复回环 | 仅提供再次归档与口令，在新独占目录经受保护暂存物化 N2；再在 N2 提交一笔并重复回环。另调度 sequence 为 0 时仅修改账户，然后恢复并重复归档 | 无需上一份归档、原暂存或原钥。最新事实按同一业务 ID 保全，原段与新写段均可解释；N2 初始 outbox 空、观察点 0、旧意图不可运行。零意图空段不累积，账户变化仍保全。 |

已取得 schema 1003 的 Unix 宿主捕获证据。A11 合成案例附加一笔源库写入后，继承观察序号为 9，本地观察序号从 0 开始；继承段的观察值 8 保留，写入本地段则被拒绝。实际第二 SQLCipher 连接在读点建立后提交本地交易并新增账户，第一次捕获只见原有事实和按手算得到的 8042 余额，下一次捕获见 8053 和新增账户。受控写入口在共同锁持有期间返回忙。A04 在 N 恢复已删转账后，原删除修订保留，所选及余额符合原样例的恢复步骤。

v2 未完成导入和 v3 部分撤销的历史与来源绑定在编辑原交易后仍保留。测试实际拒绝旧计划的事件 / 修订 ID、保留身份索引损坏、来源索引缺失、历史摘要不匹配、未知生成列、捕获预算超限、取消、旧选择及未定选择。早期 schema 1002 可选中、重开和继续写入，再次捕获显式拒绝。

**0.2 宿主封装证据。** 独立 Go 非空向量全长 3,127 字节，Rust 从核对后的事实编码、清单到完整密文逐字节一致。两段观察序号分别为 4 与 1，原意图与新写的观察值为 3 与 0，所选的两笔期初合计 137 分。旧读者在 KDF 前拒绝实际 `0.2` 密文，新读者打开原 `0.1` 独立向量。错误口令、改头版本、重新认证的 profile 混搭和计数漂移均拒绝；解码直接用例另覆盖未知字段、重复键、跨段操作复用、序号越界和累计预算。v2 / v3 SQLCipher 恢复库编辑后的实际捕获，完成 `0.2` 封装 / 解封后仍保留旧 CSV 历史、来源和新修订。见[独立输入](archive-restored-review-input.json)及[向量](archive-restored-review-vector.json)。

当前结果覆盖内存封装 / 解封。完整 E17 跨代恢复回环、归档文件保存、设备及掉电仍待运行。
