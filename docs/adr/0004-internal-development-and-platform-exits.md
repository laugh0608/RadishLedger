# ADR-0004 内部开发准入与逐平台验收出口

状态：已接受（规划边界）；尚未据此完成内部准入、产品验收或生产选型。

日期：2026-11-10。

## 背景

现有 M0-B/C 已有宿主与模拟器证据，但没有两端真机及完整认证/签名条件。原先以全部双端 M0 风险关闭作为 M1 开发的串行前置，使设备等待持续转化为 D/E 宿主实验，日常记账流程迟迟不能验证。项目所有者已确认拆分内部开发准入与真机产品验收，并要求本轮只更新文档。

## 决定

1. 允许 M0 工作包尚未全部退出时，按下列条件进入受限的 M1 Android 内部开发：账务规则和共同预期可复核；既有加密核心、错误保全、重启与恢复证据明确；选定一个内部桥接候选并登记平台缺口；只使用合成数据。条件逐项核对，规划接受不是准入自动通过。
2. 内部流程先覆盖创建/解锁、账户分类、收支录入与编辑删除、流水/月度汇总、强杀重开和独立加密归档到空目标恢复。复用 Rust 核心、SQLCipher 和既有账务/恢复语义；正常、取消、拒绝、失败及结果未定均需可见。平台认证不可用时相应操作如实阻断，不以随机内存 key、假成功或降级保护冒充产品解锁。
3. M1 正式退出仍包括完整声明范围的本地账务、CSV 与独立归档，以及 Android 真机 release、系统认证/密钥失效恢复、文件边界、生命周期、KDF 资源和数据保全。无真机最多交付内部流程，不作为私人主力账簿或公开发行。
4. iOS 工具链和关键 native 依赖可行性仍在 M0 验证；iOS 真机风险在 M2 双端准入前关闭，完整客户端和真实双端同步、自部署/独立恢复在 M2 验收。iOS 设备等待不整体阻塞 Android 内部开发或已满足 Android 条件的 M1 退出。M0-B/C 整体完成仍需双端证据，未完成部分持续列为开放风险，不标为通过或 N/A。
5. 内部开发只推进一个桥接候选，不再给所有新业务流程维护双实现；另一候选及已有比较/失败证据保留。内部选择不冻结生产 ABI、支持矩阵、KDF、密码/归档格式或双端选型，正式冻结仍依据对应实际证据另作决定。
6. E15 先完成宿主新建归档文件保存与失败保全，再接受限内部本地流程。完整 CSV 在正式 M1 前交付；新建引用、复杂关联和扩展格式先后置，声明范围内的依赖/撤销安全不得省略。完整 D-CLIENT/ENVELOPE/RECOVERY、Go 服务、端点/迁移/运维及 iOS 完整页面后置到相应阶段；不把全部 M0-D/E 实现设为内部开发前置。

## 替代方案与代价

继续等待双端真机后再做所有页面，可降低未冻结接口引起的返工，但不能在现有资源下验证记账流程。取消真机门会把模拟器结论外推为系统保护，故不采用。选择受限内部开发，接受桥接、ABI、平台接口和运行布局在真实验收后可能返工的代价；不因此扩大支持承诺或删除恢复路径。
