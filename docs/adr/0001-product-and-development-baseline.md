# ADR-0001 产品与开发基线

状态：已接受；实现细节按 M0 验证后冻结。

日期：2026-10-12。

## 背景

项目需要可自部署、支持 Android / iOS、多端同步和隐私的个人记账产品。早期规划范围包含多账簿、预算和年度图表，技术建议主要为 Flutter + Go。阅读 Radish 系列后，方案需要与现有核心分工、串行开发、家族视觉和源码可见策略一致。

项目所有者已确认 RadishLedger（萝卜账簿）名称，并授权按调整后的建议建立正式产品与开发文档，当前不编写业务代码。

## 决定

1. 产品名为 RadishLedger（萝卜账簿），本地优先、默认 E2EE，同一官方安装包运行时支持官方 / 自部署端点。
2. 公开 MVP 收敛为单人、单账簿、CNY，保留基础账务、双端、可靠同步、完整恢复、迁移和服务交付。
3. 多账簿、预算、年度专门图表、复杂关联退款、共享和自动记账后置；普通退款保留独立冲销语义。
4. 技术方向为 Flutter + Rust 客户端核心 + Go + PostgreSQL，优先验证 SQLCipher 和 RustCrypto。
5. 移动 bridge、依赖版本、KDF profile、最低系统、精确 API / ABI / 归档格式尚未冻结；M0 提供证据后另写 ADR。
6. 复用 Radish 的边界与测试经验，产品仍独立；不提前建共享账号 / 同步平台，不复用根密钥。
7. `dev` 日常串行推进，`master` PR 晋级与回流；普通任务不强制主题分支。
8. 仓库正式文档为来源，current 记录实际状态，根协作文件保持短且一致。
9. 源码可见授权明确允许个人免费自部署 / 私有修改；数据自主和独立互操作有明确许可边界。

## 替代方案与后果

纯 Dart 核心能减少桥接面，但账务 / 同步 / 加密将脱离现有 Rust 经验。Rust 方向增加打包与 FFI 成本，因此不能跳过两端最小验证，也不预建大量 crate。

首版纳入多账簿、预算和复杂退款会扩大关系、同步和恢复面。后置这些增强，优先验证可信的私人账簿闭环。

仅交付单用户 bearer 后端无法直接成为官方多用户服务。服务内部从一开始明确账号 / 账库隔离，自部署通过配置缩小开放范围。

全部开放源码并非当前默认策略；复制兄弟项目“部署逐个申请”又与本产品定位不符，故采用明确个人使用授权的独立许可证。

## 后续验证

M0 关闭移动端、系统密钥、账务 / 同步和归档关键问题。M2 / M3 分别取得自部署与官方真实目标证据。具体退出条件见[MVP 路线图](../mvp-roadmap.md)，实际进度仅见[当前状态](../status/current.md)。
