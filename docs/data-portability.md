# 数据交换、备份恢复与服务器迁移

CSV 用于交换，独立认证加密归档用于保真恢复。服务器运维备份是第三种用途，不能相互冒充。用户能在原服务不可用时恢复账务，是第一版公开 MVP 的门槛。

本篇是 M0-E 语义规格草案，不表示 CSV / 归档 / 迁移实现已经交付。字段名称、字节编码、密码构造、资源数值及平台发布机制需验证后冻结；不直接采用当前实验 DB / ABI 作为公开格式。合成调度与独立预期见[数据可迁移共同案例](validation/portability-cases.md)，实际证据与下一步只见 [current](status/current.md)。

| 路径 | 保存 / 恢复的对象 | 不承诺的能力 |
| --- | --- | --- |
| CSV 交换 | 用户选定范围的业务行及显式映射 | 完整修订、冲突、删除历史或密钥恢复 |
| 独立加密归档 | 一个本机一致快照中的完整必要业务状态和来源证据 | 其他离线设备事实、旧会话恢复或旧同步队列直接续传 |
| 空目标迁移 / 安全重建 | 验证快照进入新安全域，显式发布并切换 | 两个已有账库自动合并、跨服务原子事务 |
| 服务器运维恢复 | 原域密文备份及原提交来源，在新 restoreGeneration 下对账 | 管理员解密、自动补回服务器从未收到的事实 |

## 1. 通用 CSV

目标字段包含稳定来源 ID（若有）、交易类型、十进制金额、业务日期、账户、分类、备注，转账还需两端账户。期初 / 差额调整使用独立事件类型，不能导成普通收入。

每种支持类型必须能明确映射；未知手续费、拆分、分期或关联退款列出不支持记录，不猜测成普通支出。第一版退款为独立冲销，不承诺源系统复杂关系完全保真。

导入步骤：

1. 选择文件并检查大小、编码和 CSV 格式。
2. 明确金额 / 日期格式及字段映射，不静默修正不明确的小数和日期。
3. 映射或新建资金账户 / 类别，预览错误、重复候选、笔数和金额。
4. 用户确认明确的批次范围，保存来源、映射和行处理身份。
5. 每个有界批次原子发布事实与队列，完成后可见；中断保留完成与未完成范围。
6. 输出成功、失败、跳过与后续处理清单。

大文件可拆成明确批次，界面显示进度与已完成范围，不宣称整个文件原子提交。一个批次的中间行不进入有效报表；同步提交需满足相同原子语义。

有可信来源 ID 时按来源命名空间识别，文件 fingerprint / 行映射辅助重复导入。日期、金额和备注相同仅为重复提示，两笔正常相同消费不能被自动删除。

批次撤销只自动处理未被后续编辑、引用或恢复的导入事实；受影响部分先列出，不直接清空。撤销产生正常删除修订与同步证据，不以删批次元数据代替。

专用来源适配需要取得授权的脱敏导出样本。截图不能证明导出格式，当前不读取真实银行 / 支付账单来构造 fixture。

### 1.1 输入、映射与行身份

通用入口的首个验证候选为 UTF-8、逗号分隔、双引号引用的 CSV；允许记录分隔 CRLF / LF，文件开头的 UTF-8 BOM 可识别并在预览中报告，其他非法 UTF-8 不以替换字符继续。带引号字段中的逗号、换行和双引号按 CSV 语法解析；不能按物理行 split。空白是字段内容，不能全局 trim；不可辨认的表头、重复映射列、列数不符、未闭合引号和 NUL 明确拒绝。无表头文件必须显式选择列位置，不能把首笔账务自动吞作表头。这是项目输入候选，不宣称任意表格软件方言兼容；CSV 的引用规则参考 [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180)。

解析前限制文件 / 字段 / 记录 / 列数，解析期间限制累计解码字节和工作量。预览保存输入副本身份、精确字节 fingerprint、解析 profile、映射版本、目标账库及核对点；确认时原文件已改变则重新预览，不能按旧行号套用新内容。原始文件与预览明文只在受限本机范围处理，不写普通日志或自动上传。

| 映射语义 | 最小要求 |
| --- | --- |
| 类型与方向 | 收入、支出、转账、独立退款、期初、固定差额调整逐类确认；不能仅按金额正负猜类型 |
| 金额 | 字符串按选定小数 / 分隔规则精确转为分；普通交易为正，类型决定方向；调整 / 期初使用有符号变动。使用[领域边界](domain-model.md#2-金额日期与验证)，无隐式四舍五入、指数或浮点累计 |
| 日期 | 明确日历日期格式与有效日期；UTC 追踪时间和业务日分开。日期歧义须选择 profile，不按机器地区猜测 |
| 账户 / 类别 | 来源标识或名称经显式映射到稳定 ID；同名不自动合并。新建引用与引用它的首个业务批次一起提交，预览不创建正式对象 |
| 转账 / 还款 | 同一行表达完整单一交易、两个不同同币种账户和一个正金额；不拆成收入 / 支出。源系统分成两行时需专用可验证关联规则，通用入口不猜配对 |
| 期初 / 调整 | 期初保持独立事件；固定差额调整需保留观察余额、目标、差额、原因及观察来源，不能把“当前余额”列自动当作调整。缺材料的行列为未支持，不凭导入时余额补造 |
| 来源与文本 | 来源命名空间、可信来源 ID（可缺）、备注与必要来源说明分别保存；不把备注、名称或其公开 hash 当作随机业务 ID |

映射需区分新增交易与保真历史恢复：通用 CSV 新录入不能引用当前已归档对象，也不能以导入名义绕过类别类型约束；完整归档中的历史引用则允许保留已归档状态。已有期初、来源同名 / 同 ID 冲突或未支持关系必须预览处理，不自动改写既有事实。

一个任务固定输入身份、映射与目标上下文；每条逻辑记录分配稳定的任务内行身份，不能以物理行号作为唯一依据。重试沿用已持久化的任务 / 行 / 批次身份；改变输入、映射或目标即形成新计划，旧计划与已完成事实保留。

首个 Rust 输入预览候选的精确方言、预算、只读引用校验与未支持范围见 [E-CSV 预览入口](validation/portability-cases.md#51-e-csv-输入预览候选)。preview 函数只形成有界候选 / 错误，不发布账务；逻辑记录号、文件内重复提示和内部 fingerprint 不能被冒用为持久导入 / 去重协议。后续 [持久任务候选](validation/portability-cases.md#52-e-csv-持久任务与原子发布候选)在新建 v2 实验库内固定输入 / 映射 / 目标和随机行身份，原子保存备注、来源、批次及意图；在此模型上新增的[受限撤销候选](validation/portability-cases.md#53-e-csv-受限撤销候选)使用独占新建 v3 实验库，验证原修订重检、正常删除、取消及原身份恢复；未提供旧库迁移或移动入口，尚未支持的引用 / 关联分支保持阻塞。

### 1.2 重复判定、发布与撤销

可信来源 ID 的比较键包含目标业务范围和来源命名空间。同键同已登记内容可显示为已导入；同键异内容是需核对的来源修正或碰撞，不能直接覆盖或当作新交易。只有日期 / 金额 / 备注相等不构成去重依据。没有来源 ID 时，同一已登记任务的恢复按行身份防重；重新选择相同文件显示历史导入范围，不自动假设用户必然想重试或必然想再导一份。

确认计划明确纳入 / 跳过 / 需修正的逻辑记录及有界批次。错误行不会悄悄从批次消失；用户改变选择后重新生成计划。跨行依赖和一笔完整转账不能跨发布边界；超出单批支持界限时阻塞相应范围，不拆成半笔事实。

每批事务重新核对活动身份、引用 / 归档状态、来源绑定和已完成行身份，再原子写入业务事实、修订、来源 / 进度及本域上传意图。纯本地模式按现有核心语义保存尚未绑定服务的意图，不凭导入自动启用同步。批次进度不能先于业务提交；中断后读取持久结果，已经完成的不重复发布，未完成的从原身份继续。

取消停止新的批次调度；正在提交的批次可能已完成，不能立即显示“全部撤回”。再次打开任务必须列出已完成、明确未完成、结果待核对和跳过范围。锁定、切库或 runtime 变化时停止新工作；旧回调只能归属旧任务，不能写入新活动域。

撤销预览基于当前版本：原导入事实若已被编辑、引用、恢复或形成依赖，列为受限范围；不能将它与可撤销事实一并清空。用户确认可处理集合后，每批重新核对前置条件并提交正常删除修订及对应同步意图；竞争变化则该批拒绝并重新预览。保留来源 / 导入 / 撤销身份，防止重试重复撤销或重新导入使已撤销事实自动复活。导入时创建的账户 / 类别不因撤销交易就硬删除；引用与归档仍走领域规则。

## 2. CSV 导出

导出前明确“文件未加密”，由用户选择范围和去向。临时文件受限保存并按分享完成 / 超时策略清理，不自动上传原始账单。

字段按 CSV 规则转义，避免表格公式执行；防公式编码规则须文档化，导入时不能随意删除合法备注前缀。金额、类型和日期使用确定格式。

CSV 不含完整修订、冲突、删除与恢复材料，不能称为完整备份。软件许可不限制用户自由处理自己的数据。

### 2.1 导出核对与公式防护门槛

导出固定一个本机一致读取点、用户选择的范围和当前选中版本；不把冲突候选各导成一笔正常流水。默认业务行不包含已删除事件，另行说明候选 / 删除未导出的范围。期初与调整仍是专门类型，转账 / 还款始终一行，业务日期不随导出时区变化。导出的稳定 ID 必须带来源命名空间，不能被另一账库当作覆盖本地对象的权限。

确定的金额文本与日历日由核心生成；类型、名称、备注等自由文本按已选择的可逆导出 profile 编码。CSV 引用只解决分隔语法，不保证表格软件不会执行公式；`=`、`+`、`-`、`@`、控制字符及相关全角变体等输入需专项覆盖。不能只加双引号后声称安全，也不能在导入时无条件剥掉原始单引号或 tab。[OWASP 的 CSV 注入说明](https://community.owasp.org/attacks/CSV_Injection)指出，不同软件和保存 / 重开行为没有通用的安全净化策略。

本轮不冻结防公式前缀：后续须给出完整可逆规则、版本识别、合法前缀的无损处理，并在声明支持的表格软件中验证首次打开及保存重开。识别为本产品 profile 也不免除普通输入校验；未知 profile 不猜解码。未满足这些证据前，不提供声称已安全的生产 CSV 导出；不得以未经用户明确知情的字符改写换取表面兼容。

导出先完成受限临时文件与完整性核对，再交给用户选定目标；写入中断、分享取消、提供方失联与完成分别呈现。分享系统接收文件不证明外部提供方已持久保存；目标保存结果未定时保留重试入口，不将半文件称作完成。不覆盖已有文件而不提示。到期清理仅限本任务临时材料，不删除用户选定目标，也不承诺远程擦除已分享副本或闪存物理残留。

## 3. 独立加密归档

归档目标为版本化、公开规格的认证格式，临时扩展名方向为 `.ledger-backup`，具体格式在 M0 冻结。

包含：

- 账簿、账户、分类、全部有效账务事实与必要关联；
- 必要修订、删除身份、导入来源与批次状态；
- 本机已提交但尚未远端确认的业务事实及冲突候选；
- 时区、币种、精度与恢复所需的非秘密设置；
- 记录数量、确定性业务快照摘要和余额 / 分类核对清单。

不包含服务会话、管理员凭据、系统私钥或可直接重试的旧域 outbox。旧操作可作为业务意图 / 历史保留，恢复后重新绑定身份。

### 3.1 一致快照与保真清单

归档从核心取得一个一致的本机逻辑快照；记录快照身份、格式、币种 / 精度 / 时区、本地核对点、最后已验证的远端范围及未知完整性。后台新记账可继续，但不能混入此快照的一半；若采用短暂停写捕获或 MVCC 快照，其资源及锁定策略须实测，不承诺无限长事务。

| 清单内容 | 恢复判据 |
| --- | --- |
| 业务身份与引用 | Book、Account、Category、Transaction 的 ID / 类型 / 归档状态及关系一致；名称不代替身份 |
| 修订、候选与删除 | 保存解释当前事实、未解决候选、所选修订及防复活所需的修订 / parent / 删除证据；保留声明范围内的可恢复内容。已按明确策略清除的历史不伪造为空，也不承诺永久全历史 |
| 本地事实与业务意图 | 已提交且未远端确认的事实、原意图及依赖均保留；确认 / 未确认不使相同修订被恢复两次；失败或取消等待不等于业务事实不存在 |
| 导入来源与进度 | 已提交行绑定、完成 / 跳过 / 未完成范围、映射与撤销证据可核对；撤销保留确认集合、原行 / 修订绑定、删除意图身份、逐行结果、进度与批次回执。不含临时绝对路径和原始文件副本。未完成任务仅恢复状态，导入需重新提供匹配文件并确认、撤销需显式确认恢复，不能自动继续 |
| 非秘密设置与检查点 | 解释业务日期、数值和已知同步范围所需设置；旧确认 / cursor 是注明原域的历史证据，不能激活为新域运行状态 |
| 核对清单 | 各类对象 / 修订 / 候选 / 删除的数量与集合摘要、选中关系、笔数、账户余额及分类 / 月份汇总；不能只比较总金额 |

原意图历史只保留解释 / 对账必需的语义内容、原身份和依赖关系，不带可发送旧 envelope、会话或解密钥；待重新发送时由新上下文生成新操作。快照未含其他设备未上传事实，归档认证也不能证明其存在或不存在。

确定性业务快照摘要须覆盖完整声明集合及关系，独立于 DB 文件布局、页号、平台路径和密文随机性；其编码 / 算法与 schema 版本待冻结。恢复端重建投影后逐项比较清单，清单与事实共同认证；同一实现自己写出再读回不算独立正确性证据。

当前 [E-SNAPSHOT 宿主候选](validation/portability-cases.md#54-e-snapshot-最小一致逻辑快照候选)从实验 schema 1–3 的单一读取事务保全声明事实、原意图和导入 / 撤销语义，并重建核对清单；原始 CSV、bootstrap 与运行凭据排除。其有界 JSON 仅为内存比较候选，不是认证归档、恢复入口或冻结格式；完整恢复、远端确认 / 新读取基线、生产身份与非秘密设置仍待验证。

### 3.2 认证容器与资源约束

每份归档生成独立随机 Archive Key，用独立备份口令经 Argon2id 派生的密钥封装；内容不依赖原设备 DB Key 或原服务在线。格式头、长度、manifest 与内容均须认证，限制 KDF、记录数、解压与内存资源。

不能只把原手机加密 DB 改扩展名，也不能通过归档把根密钥和数据无保护地并排存放。恢复资料和完整归档分别提示用途。

容器必须认证版本、算法 / KDF 参数、salt、Archive Key 封装、归档身份、manifest 与内容的关系。公开头仅暴露有界解码 / 解锁必需的信息，不放账户名、备注、金额或业务摘要；未认证头只能用于选择受支持解析器和提前拒绝，不能指导任意分配 / KDF。参数范围先查白名单，再做有界 KDF 与认证；原口令、根钥、DB Key 和 Archive Key 均不进入清单。

整体认证与分块认证属于待比较构造。若分块，必须绑定归档身份、顺序 / 索引、完整成员及终结信息，拒绝截断、重复、重排、跨归档拼接和尾部附加；仅每块单独 AEAD 成功不足以证明归档完整。逐块认证后可写入受保护暂存，但完整认证与业务校验通过前不能展示、导出或发布恢复内容。压缩是否启用仍待取舍；任何解压都按压缩 / 解压总量、记录数、嵌套 / 工作量分别限额，不能信任头部声称的大小。

归档不是任意目录包：不按内部名字直接写文件路径，不加载脚本、链接或外部资源；路径穿越、重复记录、重复 manifest 项及未知必需字段拒绝。格式过新不得丢字段后当作旧版成功；兼容转换需明确版本、保真范围和独立旧版样本。

口令封装认证失败通常不能区分错误口令和封装损坏，应提示“口令不正确或归档损坏”并保留重试；只有有依据时才细分不支持版本、资源超限、已解封后的内容认证失败和业务关系错误，不泄露未认证内容。这里不新增密码算法或降低既有 KDF 保护，精确构造与向量按[威胁模型](privacy-threat-model.md#5-算法候选与认证边界)评审。

生成归档在临时输出中完成全部认证内容、终结和保存确认后才标记可用；失败 / 取消不把部分文件替换到既有成功备份。重新开始归档生成使用新的 Archive Key / 归档身份；若支持断点写续传，必须证明 nonce / 块身份不复用及输出未改变，不能简单在旧文件尾继续加密。外部文件提供方的保存语义另行验证；本地完成与外部保存结果分开报告。

### 3.2.1 E-CONTAINER 首个宿主候选与实施边界

所有者已于 2026-11-03 批准 `m0-archive-container-review-1` 的 Rust 宿主内存封装 / 有界解封实验；以下字节、用途与资源 profile 仍是**实验候选，未冻结为生产格式**。实现与实际证据见[宿主验证入口](validation/portability-cases.md#56-e-container-宿主内存封装与有界解封)。现有归档边界继续有效，不据此关闭完整 E10–E12、E15–E16 或 M0-E。

| 候选 | 适用性与代价 | 本轮建议 |
| --- | --- | --- |
| 有界整体 AEAD | 与当前至多 16 MiB 内存快照衔接；一个内容 tag 覆盖清单、完整载荷和终结字段；需要完整密文 / 明文缓冲，暂不能支持任意大归档 | 首个宿主候选；超限明确拒绝，不截断或拆成不完整备份 |
| 分块 AEAD | 可降低单次密码缓冲，但还需块身份 / 顺序、成员清单、终结认证、nonce / 续写、受保护暂存与 IO 恢复证据 | 保留方向，当前不引入；单块认证不得代替完整档案认证 |

本宿主切片采用整体认证、无压缩、无断点加密续写；每次新尝试都生成新的随机 Archive Key、archive_id、salt 与 nonce。取消、失败或重新选择输入不能在旧文件尾继续加密。本候选只验证内存封装与有界解封，不写用户备份、不创建恢复库或操作系统密钥，不新增依赖，也不把实验 `.ledger-backup` 变成已交付承诺。

原语沿用威胁模型方向：XChaCha20-Poly1305、HKDF-SHA256 和 Argon2id。192-bit nonce 的随机使用与同钥不复用边界依据 [libsodium 原始说明](https://doc.libsodium.org/secret-key_cryptography/aead/chacha20-poly1305/xchacha20-poly1305_construction)；`info` 的用途 / 上下文隔离依据 [RFC 5869 §3.2](https://www.rfc-editor.org/rfc/rfc5869.html#section-3.2)。这是本项目候选构造，不是这些来源已经评审本容器的结论。XChaCha 的[公开向量文档](https://datatracker.ietf.org/doc/html/draft-irtf-cfrg-xchacha-03#appendix-A.3.1)为过期 Internet-Draft，不称为 RFC。

### 3.2.2 公开头的精确候选字节

所有无符号整数均为大端；区间均为从 0 开始、右端不包含的字节区间。ASCII 常量不带隐式 NUL，只有后文明确列出的 AAD 分隔字节为 `00`。外层为 `H[176] || C_body[L]`；不存在可忽略的尾部、可选扩展、目录成员或第二份头。

| 区间 | 字段 | 本候选唯一接受值 / 解释 |
| --- | --- | --- |
| `[0,8)` | magic | ASCII `RLM0E001`，明确为 M0 实验标识 |
| `[8,10)`、`[10,12)` | major、minor，u16 | `0`、`1`；当前只接受这一对，不把未知 minor 当兼容 |
| `[12,16)` | header_length，u32 | `176`，不据此任意分配头缓冲 |
| `[16,18)` | suite_id，u16 | `1`：XChaCha20-Poly1305 / HKDF-SHA256 |
| `[18,20)` | kdf_profile_id，u16 | `1`：本候选固定 Argon2id 参数 |
| `[20,24)` | flags，u32 | `0`；非零包括压缩 / 分块标志均不支持 |
| `[24,40)` | archive_id | 每份尝试独立的 16 个系统随机字节，不是业务 / 同步身份 |
| `[40,56)` | salt | 16 个独立系统随机字节，用于 Argon2id |
| `[56,60)`、`[60,64)` | Argon2 version、memory_kib，u32 | `19`（0x13）、`65536` |
| `[64,68)`、`[68,72)` | iterations、lanes，u32 | `3`、`1` |
| `[72,96)` | N_wrap | 24 个系统随机字节，封装 Archive Key |
| `[96,120)` | N_body | 24 个系统随机字节，认证完整正文 |
| `[120,128)` | content_cipher_length，u64 | `L=N+152`，含 16-byte tag；`N` 是载荷字节数 |
| `[128,176)` | C_wrap | 32-byte Archive Key 的 AEAD combined 输出，含 16-byte tag，共 48 字节 |

未认证头只允许做固定读取、整数检查、版本 / 算法 / profile 白名单与资源拒绝。先检查 `153 <= L <= 16,777,368` 和实际总长 `176+L`，再做 KDF；尾部附加或截断均拒绝。不可 seek 的输入须在相同上限内读足并核对 EOF；实际提供方错误按 IO 失败返回，不把未知长度当成功。头不放账户名、业务日期、金额、备注、payload hash、清单或生产 Book ID；长度与随机标识仍会暴露，不能宣称隐藏体积或新鲜度。

### 3.2.3 密钥与认证输入

令 `P` 为备份口令的原始 UTF-8 字节：1–1024 字节，继承当前口令输入边界，不 trim、不做 Unicode normalization、不隐式换编码。Argon2id 使用头中固定参数、16-byte salt、32-byte 输出，不使用 Argon2 的 secret / associated-data 可选输入。

```text
I = Argon2id(P, salt, v=19, m=65536 KiB, t=3, p=1, out=32)
K_wrap = HKDF-SHA256(IKM=I, salt=archive_id,
                    info=ASCII("radishledger/archive/review1/password-wrap"), L=32)
K_body = HKDF-SHA256(IKM=ArchiveKey, salt=archive_id,
                    info=ASCII("radishledger/archive/review1/content-key"), L=32)
AAD_wrap = ASCII("radishledger/archive/review1/wrap") || 00 || H[0:128]
C_wrap = AEAD_Encrypt(K_wrap, N_wrap, ArchiveKey, AAD_wrap)
H = H[0:128] || C_wrap
AAD_body = ASCII("radishledger/archive/review1/content") || 00 || H[0:176]
C_body = AEAD_Encrypt(K_body, N_body, B, AAD_body)
```

HKDF 均含 Extract 与 Expand。`L` 在头部先确定，因此认证关系无循环：先构造 128-byte 前缀，再封装、形成完整头、最后认证正文。公开参数、salt、nonce、archive_id 与长度由封装认证绑定；正文再绑定完整封装字节。等长跨归档拼接也必须失败。manifest 在正文内一并认证，不能把未认证头当作清单。

本地 `crypto::password_key` 已在 Argon2id 后使用 `radishledger/m0c/v1/password-wrap`；其输出不能直接冒充上式 `I` 或 `K_wrap`。实现以 `password_material` 提取原始 Argon2id 材料，共享原有执行锁 / 内存管理；既有 `password_key` 保留 M0-C 标签和 salt 关系，独立向量核对其派生兼容。不能复制一套无执行限额的 KDF，也不能手写密码原语。依据 [RFC 9106 §4](https://www.rfc-editor.org/rfc/rfc9106.html#section-4)，其 64 MiB / 3 次迭代推荐组合使用 **4 路**；这里的 **1 路**沿用项目既有未冻结实验候选，不将其描述为 RFC 同一 profile 或已获真机性能证据。

Archive Key 独立随机生成，不由原 DB Key、Vault Root Key、同步钥或登录凭据导出，也不写进 manifest。两次 AEAD 的 nonce 独立随机，同钥不得复用；不提供原地换口令 / 重封装 / 加密续写入口。持有相应解密材料的人能够创建有效容器，AEAD 不提供作者签名、时间新鲜度、唯一最新档案或其他离线设备完整性证明。

### 3.2.4 认证正文、清单与终结

`S` 为长度 `N` 的 UTF-8 逻辑快照候选载荷；当前候选仅承载 `m0-logical-snapshot-v1` 的 schema 1–3 语义，不能据此承诺生产身份、设置或旧域恢复。`1 <= N <= 16,777,216`。正文为：

```text
B = u32be(116) || M[116] || u64be(N) || S[N] || ASCII("RLM0END1")
len(B) = N + 136
len(C_body) = N + 152
len(H || C_body) = N + 328       # 最大 16,777,544 字节
```

| M 内区间 | 字段 | 认证后必须核对 |
| --- | --- | --- |
| `[0,8)` | manifest_magic | ASCII `RLM0MAN1` |
| `[8,10)`、`[10,12)` | manifest_version、payload_profile_id，u16 | `1`、`1`；未知值不忽略 |
| `[12,16)` | source_schema，u32 | 仅 1–3，且与 S 一致 |
| `[16,24)` | source_sequence，u64 | 与 S 一致且在源 i64 非负范围；不是新域 cursor |
| `[24,76)` | 13 个 u32 数量 | 依次为 accounts、categories、revisions、selected、candidates、intent_history、import tasks / rows / sources / batches、undo tasks / rows / batches |
| `[76,84)` | payload_length，u64 | 与外层推得的 N、正文长度和实际 S 一致 |
| `[84,116)` | payload_sha256 | SHA-256(S 原始字节)，密文内保存；认证后重算 |

13 项数量分别对应 S 的声明数组；无 imports 时其中七项为 0。它们累计不超过 100,000，并在解码中独立计数重检，不据头或 manifest 值直接 reserve。嵌套确认集合、mapping 与候选引用另受累计成员预算和领域关系约束。payload hash 只核对本载荷字节，**不是已冻结的确定性业务摘要、签名或归档身份**；不能以它替代完整事实、关系和统计检查。

S 为无 BOM 的单个 UTF-8 JSON 文本，可含 JSON 定义的前后空白；拒绝多个顶层值和非空白尾部，hash 始终覆盖原始 S 字节。写端沿当前快照编码输出固定字段次序与紧凑字节，不把读端接受的空白 / key 顺序变化误称为统一的业务规范编码。

完整 AEAD 成功后，仍须拒绝错误 manifest / 长度 / 终结、重复 JSON 键、重复身份、未知必需字段、非法 UTF-8 / 金额 / 引用 / 候选 / parent、来源与任务漂移，以及虚假的核对清单。不能直接用会覆盖重复 map key 的普通 JSON 解码宣布成功。须从事实重建报表、与 S 的 verification 和 M 逐项比较；合法归档历史引用保留。正文必须精确结束于终结字段，外层也必须精确 EOF。终结常量本身不代替认证；本候选没有块序号，分块重排用例不能伪称已覆盖。

### 3.2.5 资源、取消与失败结果

| 边界 | 候选限制 / 行为 |
| --- | --- |
| KDF | 只允许 profile 1 的全部精确参数；更弱、更高、未知算法 / 版本 / 路数都在昂贵调用前拒绝，不做 fallback |
| 并发 | 与既有核心共享至多一个昂贵 KDF 执行名额；忙则明确返回，不建立无限等待队列 |
| 明文 / 密文 | 按上表 N / L / 总长检查，加法先 checked，再转换平台 usize；只读固定头，不跟随内部路径、链接、脚本或外部资源 |
| JSON 解码 | 原始 S 至多 16 MiB；嵌套深度 64、单个解码字符串 64 KiB、累计解码字符串 16 MiB、全部集合 / map 成员累计 1,000,000；另重检 100,000 个声明数组成员及现有领域限额 |
| 分配 | 显式预算与可失败预分配；评估 in-place AEAD，避免不受控明文副本；不能捕获 OOM 后假报成功或降 KDF 强度。64 MiB KDF、内容缓冲、typed JSON / 集合与 SQLite 缓存不能混称为 64 MiB 峰值内存 |
| 取消 | KDF 前、返回后及 AEAD / 解码阶段检查；当前 Argon2 原语不能中途停止，UI 停等不等于已退出。取消后待本次原语返回、丢弃并清理结果，期间不释放名额再启动下一次 |
| 解密失败 | 受污染的工作缓冲不返回、不展示、不写普通文件；尽量 Zeroizing，清理不宣传为系统级绝对擦除 |
| 生成失败 | 不生成可用归档标记、不覆盖旧备份；重试新建随机材料。平台保存 / fsync / owner / 条件发布留给后续实际 IO 切片 |

错误分层候选为：公开格式 / profile 不支持、资源超限、口令输入无效、KDF 忙 / 分配失败、IO、取消、封装认证失败、正文认证失败、认证后载荷 / 业务非法。`archive_unlock_failed` 的用户解释必须为“口令不正确或归档损坏”；封装成功后才可报告 `archive_content_auth_failed`，不能透露未认证内容。代码名称也是候选，不另冻公共错误 ABI。

### 3.2.6 独立向量输入与实施门槛

[公开评审输入](validation/archive-container-review-inputs.json)提供一个人工空快照 S、公开固定测试口令 / key / nonce / salt、精确头前缀 / manifest / 正文摘要 / AAD 以及 R01–R24 调度。它们全部是已公开标记的合成输入，不能用于运行材料。输入 S 为 518 字节，M 为 116 字节，B 为 654 字节；独立 Go 向量的完整密文为 846 字节，Rust 随后逐字节匹配。该文件的固定材料只用于公开向量，生产入口没有注入固定 nonce / key 的选项。

[`check-archive-review.py`](../scripts/check-archive-review.py)仅用 Python 标准库独立解读固定偏移、重算 SHA / 长度并复核 11 个预检调度；它不执行 Argon2、HKDF、AEAD、生产 codec 或恢复。材料版本 2 已补独立密码输出和来源指纹，R01–R24 映射到宿主测试；检查脚本只验证材料 / 指纹，不运行密码算法，也不以材料检查替代 Cargo 的真实认证与业务校验。原语来源仍是 [RFC 9106 §5.3](https://www.rfc-editor.org/rfc/rfc9106.html#section-5.3)、[RFC 5869 Appendix A.1](https://www.rfc-editor.org/rfc/rfc5869.html#appendix-A.1)和上述 XChaCha 草案；现有原语测试不替代新的用途 / 组合向量。

独立预期先于 Rust encoder 生成：复用已安装 Go 1.26.3、缓存 `golang.org/x/crypto v0.50.0` / `x/sys v0.43.0`（The Go Authors，BSD-3-Clause），使用 Go Argon2id、XChaCha20-Poly1305 与标准库 HKDF。入口为 [`archive-vector-oracle.py`](../scripts/archive-vector-oracle.py)，来源 API 见 [Go Argon2](https://pkg.go.dev/golang.org/x/crypto/argon2)、[Go XChaCha](https://pkg.go.dev/golang.org/x/crypto@v0.50.0/chacha20poly1305) 与 [Go HKDF](https://pkg.go.dev/crypto/hkdf)。仅在独占忽略目录生成工具、模块引用和输出，禁用下载 / 自动工具链 / 遥测；没有安装或修改产品依赖。固定输入、工具版本、Go 源码 / 模块 / 许可指纹和原输出 hash 保留在材料 provenance；Rust 逐项匹配 I、两用途密钥、两层完整密文、旧 M0-C 派生和 Unicode 输入，不以生产 encoder 自生 expected。

宿主验证映射至少覆盖 R01 正常独立解封、R02–R12 KDF 前拒绝、R13–R17 错口令 / 各层篡改 / 等长拼接、R18–R21 **合法认证但载荷非法**、R22 可达硬上限与下调资源预算的 limit−1 / limit / limit+1、R23 原始 UTF-8 身份与 R24 取消 / 忙 / 原库保全。A11 非空事实及 v2 / v3 历史已有宿主内存保真证据；后续仍需临时保存与旧备份保全、真实 IO / 中断、移动峰值 / KDF 与空白设备恢复证据；正式格式与支持矩阵另经 ADR，不由本次确认自动冻结。

## 4. 恢复流程

1. 在新暂存区检查格式与版本，不覆盖活动账库。
2. 获取备份口令，认证后有界解密；完整认证与校验通过前不发布部分明文。
3. 校验 ID、引用、币种、金额、删除、候选与批次状态。
4. 重建投影，核对事实集合、笔数、余额和分类汇总。
5. 建立新本机密钥和明确的活动身份，成功后切换。
6. 若启用新服务同步，重新认证、创建域并生成新钥，不复用旧 token、cursor 或操作确认。

同一业务事实的确认 / 未确认版本去重恢复；冲突候选保留但不重复入账。归档不会证明其他设备没有未同步修改，必须展示快照时间与范围。

恢复中断可以继续或放弃暂存，旧活动账库仍完整。格式过新、认证失败、空间不足与关系不合法按可判定原因报告，不把无法区分的口令 / 损坏原因伪装成确定结论。

### 4.1 恢复任务与活动切换

恢复目标是一个新建、独占且未发布的本机暂存账库，不向非空活动库 upsert 或自动合并。任务持久记录归档身份 / 输入 fingerprint、暂存 owner、已验证阶段、预期旧活动身份 / 核对点与新目标身份。再次打开先核对文件、版本和归属；没有恢复钥时要求重新解锁，不把秘密写入任务进度。

| 阶段 | 对用户可见的结果 | 取消 / 失败后的处理 |
| --- | --- | --- |
| 已选择 / 检查输入 | 格式、范围说明、资源需求，尚未确认归档正文 | 不改活动库；原输入保留 |
| 认证 / 暂存写入 | 明确仍未恢复完成；不发布中间事实 | 保留或清理本任务受保护暂存，不能清旧库；中断点重新认证，不信任裸进度标志 |
| 完整校验通过 | 核对事实、关联、选中候选、删除、来源与统计，列出原 / 新库范围 | 差异阻止切换；放弃不影响旧库 |
| 准备切换 | 用户确认目标；阻止本机旧库新写，排空 / 核对在途操作，再复查活动身份与核对点 | 旧库自预览后又变化则重新核对，不能丢弃新增未同步事实或让旧写落入新库 |
| 发布结果未定 | 尚不能显示成功或取消成功 | 重开后按持久选择记录与新库身份判定；不凭 UI 超时重建 / 删除任一库 |
| 已切换 | 新本机密钥 / 安全域与新 runtime 生效，旧库不再接收日常写入 | 旧库和归档保留，后续删除是独立确认；切换后的取消不能伪称回滚成功 |

候选发布顺序为：完成新加密库与新 bootstrap / 系统密钥项准备 → 持久核对清单 → 以预期旧身份为条件发布活动选择记录 → 重开验证所选库 → 报告结果。文件、选择记录和系统密钥项不能假装跨存储有一个原子事务；各平台须验证可恢复的写入 / 同步顺序、owner 登记及每个中断点。启动只接受明确完整的旧或新选择；损坏 / 不一致时停止并保留现场，不按“最新文件”或“能打开哪份”静默回退。

本机切换前需要的新钥 / 系统项准备失败时保持旧库可用；切换后新库暂不可解锁时报告解锁问题，不自动激活可能已过时的旧库。继续恢复需重新核对完整源身份及暂存内容；可重新创建本任务暂存，但不覆盖其他任务或用户数据。清理失败登记精确 owner 与失败项，重试不扩大路径；不能承诺取消即完成安全擦除。

### 4.1.1 E-RESTORE 受保护暂存宿主候选

本切片落实新独占 SQLCipher 目标、完整事实核对与原任务继续 / 放弃；不是第 4.1 节的活动发布、平台钥准备或空白设备交付。实验实现入口为 `restore_stage::Task`，具体验证与剩余门槛见[共同案例第 5.7 节](validation/portability-cases.md#57-e-restore-受保护暂存宿主候选)，顺位仅维护在 current。容器 profile 与生产支持范围不因暂存实现而冻结。

- `Task::new` 在暂存 IO 前生成独立随机 DB Key、task_id 与 target_id，绑定归档 ID 和完整密文 SHA-256。Ticket 是非秘密定位材料，既不是恢复钥，也不是生产 Book / runtime / 同步身份；口令、Archive Key、DB Key、原设备钥不进入 Ticket / owner / 进度。新任务不能注入旧 DB Key；`resume` 不新建任务目录，需调用方重新提供暂存钥；目录内 stage.db 缺失时的当前行为与限制见本节末段。本宿主切片只在内存 / 测试匿名管道持有该钥，尚无平台封装 / 保存。
- `prepare` 每次重检密文 fingerprint、重新认证原归档并校验业务内容，然后才创建 / 使用调用方指定父目录下的固定 `restore-<task_id>`。归档不能提供路径；目录 / 文件使用 Unix 0700 / 0600，owner、普通文件 / 单硬链接及独占锁约束精确目标。owner、输入、目录类型 / 权限、未知成员或 schema 不符即停止；不扫描猜测其他可打开目标。
- 暂存使用独立实验 schema `user_version=1001`：账户、分类、修订、所选与候选为实际表行，顺序位置显式保留；原意图和导入 / 撤销各集合进入独立 `restore_*` 历史表。没有 outbox、可执行 CSV 任务、bootstrap、会话 / cursor 或可发送 envelope。源 schema 1–3 与 sequence、原导入目标仅作加密的来源证据，新 target_id 与其分开；普通 `Store::open` 拒绝暂存版本。该编号是内部实验隔离，不是生产账务升级或格式承诺。
- schema / 绑定先原子登记；全部事实、历史和 written 状态再同一事务提交。未提交失败保留 registered 空目标，已提交后取消 / 丢响应保留完整 written 内容；再次 prepare 沿原身份核对，不对非空暂存 upsert、不顺序重放旧编辑、不为统计另造余额。关闭写连接后从实际目标重开，用原关系验证 / 投影重建逐项比较全部内容，才登记 verified；`inspect` 也重新认证源并从单一读取事务重建，不信任裸 verified 标志。异常不自动重建覆盖差异。
- 暂存读取复用容器预算与快照有界编码，并重检实际记录 / 字节、嵌套 JSON 与完整关系。资源预算不是设备内存峰值承诺；SQLCipher 配置复用原核心，MEMORY 临时策略不变。取消只表示本次准备停止、原活动库保留，不保证已提交暂存被回滚或被擦除。
- `abandon` 核对 owner / 目标及已建立的加密绑定，再持久写入固定 discard 许可，只逐一删除本任务 DB / WAL / SHM。在 DB / WAL / SHM 删除阶段失败或中断时，许可与定位材料仍在，原任务可继续清理；discard 仍存在时不允许重新 prepare。最终移除许可 / 定位材料后的中断另属未关闭窗口。目标目录已不存在时可重试同步父目录，不能据此扫描或删除其他目录。未知文件、链接、错误钥或归属漂移保留现场，不执行递归删除。

返回的 `VerifiedStage` 只提供核对后的 Contents 与 Ticket；没有日常记账、旧队列续发或活动选择写入能力。旧库在暂存期间继续变化时，暂存仍代表归档捕获点，不能据此丢弃旧库新增事实。旧活动身份 / 核对点、停止旧写与在途操作、平台 bootstrap / 系统项及选择记录条件发布须在下一切片实现，不能从本宿主目标推导已切换。

日终静态对照进一步限定两处行为：`Task::resume` 只禁止新建任务目录；owner 已匹配而 stage.db 缺失时，`StageDb::prepare` 仍会新建数据库并从重新认证源填入。当前 owner 仅保存 Ticket，不能独立区分首次尚未建库与 written / verified 后丢库。清理在数据删除后依次移除 discard、lock、owner 和目录；discard 已移除而 owner / 目录尚在的中断窗口，也未证明重开不会被当作可 prepare 的目标。这两项是代码审阅发现，未新增故障运行证据；目录缺失 / discard 仍在的现有拒绝测试不能覆盖它们。

owner / discard 原子发布复用已有文件原语，但尚未逐 IO 覆盖 mkdir 至 owner 发布、临时发布文件残留、最终定位材料删除 / 目录同步失败的所有中断。遇到缺 owner、未知临时文件或不一致定位材料时停止并保留；本切片不承诺自动清理这些现场。文件逐点真实 IO / 掉电、容量预留、平台保护 / 备份排除、真机 KDF / 峰值 / UI 和暂存钥跨设备保护仍缺证据。完整 E17–E20、E-RESTORE、M0-E 与 M0 不因此关闭。

### 4.2 业务身份与同步身份

在新本机容器 / 新安全域恢复时保留业务对象与修订之间的稳定关系和原来源，所有引用采用一致映射。若目标模型需要重编码身份，必须给出完整、无碰撞、可追溯的映射并验证，不以随机新 ID 把同一事实多次导入。业务 ID 相同不代表两个域可以互读或自动合并。

已导入来源 / 行与业务事实的绑定随这一映射保留，恢复后重选原文件仍能识别已处理范围；不能因新建本机容器而清空防重证据。原导入任务的未完成部分只作待确认历史，不把旧任务的运行权限一起迁入。

归档恢复不接续旧服务的运行权限：新 Device DB Key、新安全域与恢复材料按初始化流程建立；原域 token、cursor、幂等回执、已发送 envelope 不成为可执行状态。恢复默认本地可用；用户另行启用同步时，在明确的新空域中对验证快照建立新操作身份 / 当前前置条件和新密文。历史修订、删除和候选作为快照语义导入，不能顺序重放所有历史编辑造成重复计账。

未确认与已确认事实按原域 / 对象 / 修订 / 内容关系去重，原确认只作历史证据；同身份异内容或缺必要 parent 的情况停止核对，不能择一丢弃。恢复到新域的完整快照如何成为可读取基线、如何保留候选而只投影一个选择，仍需 D / E 的版本化契约；此契约未冻结前，不声称已支持新域自动 bootstrap 上传。

## 5. 服务器迁移

第一版只支持空目标账库，不自动合并两个服务器已有数据。改地址是连接操作，迁移是单独确认的数据事务。

正常流程：

1. 源端同步并处理冲突；提示其他设备可能存在未同步修改。
2. 保存独立归档，申请源域只读冻结并得到确认，拉取到冻结后的稳定上界。
3. 基于最终校验快照准备目标，目标端重新认证并创建新域、新根钥 / 账簿钥。
4. 对业务数据重新加密上传，核对事实、余额、类别、删除和候选。
5. 确认后切换本机活动端点，其他设备显式重新连接。
6. 源端在目标确认前不删除；源域冻结状态和后续删除分别处理。

源域只读冻结是服务端能力，不只是本机停止发送，避免其他在线设备继续写入导致遗漏。冻结的提交顺序、固定上界、条件撤销和代次失效见[同步规格](sync-protocol.md#72-迁移冻结与撤销)；具体接口、恢复清单及暂存格式仍待冻结，不能以本机停发替代服务端确认。

迁移未完成可恢复目标上传或撤销源冻结返回原域；一旦目标开始新的日常写入，返回源端需要再次迁移 / 对账，不提供会丢新记录的一键回滚。

旧设备离线事实需导出核对后显式进入新域，不能自动向源和目标双写。目标非空、身份漂移或校验差异都应停止切换。

### 5.1 最终快照与目标发布

冻结前的独立归档只保护准备时状态。源冻结确认后，客户端必须核对冻结身份、完整作用域和 restoreGeneration，完整应用到固定 U，处理结果未定提交与候选，再形成最终一致快照 / 归档；不能直接拿冻结前副本当作 U 的完整内容。冻结不阻止离线设备继续本地记账，也不能据此声称所有设备均已纳入。

本机捕获到切换仍使用第 4.1 节的核对点与条件发布边界。若又产生未同步事实，保留数据并暂停旧计划，重新核对范围；不能将其冒称 U 中的已同步事实或静默丢弃。最终快照 / 上传内容一旦绑定任务就不可变；需要纳入新事实时，先处理原任务的停止 / 未定结果，再建立新计划，不覆盖已发布身份。

迁移任务绑定源 S、冻结身份 / U、最终快照身份、目标实例 / 账号 / 新安全域以及本次迁移身份。目标空状态必须由服务端条件检查并保留本次独占导入归属；“预览时为空”不能替代发布时验证。新目标根钥 / 账簿钥在客户端生成；旧密文跨域不能改标签复用。

有界上传可分批，但目标处于明确的未发布导入状态，不开放日常写入或把半个快照作为完整账库返回。上传身份 / 完整内容固定，超时重试原片段而不重复造对象；服务只能确认密文和外层完整性，客户端须重新读取并认证核对声明集合、关系、删除、候选与投影。之后以同一迁移身份条件完成目标发布，再切换本机 runtime；目标发布记录和活动选择持久化分别取证，不用“两边都返回 200”冒充分布式原子性。

| 中断位置 | 可继续的动作与停止线 |
| --- | --- |
| 源冻结结果未定 | 查询原冻结身份，保留源 / 本地数据；没有可核对 U 不进入目标发布 |
| 目标上传中断 / 空间不足 / 校验差异 | 保留本次目标暂存和源冻结；恢复原任务或明确放弃。仅清理本次拥有的目标，不覆盖已有账库 |
| 目标发布响应丢失 | 查询同一迁移身份与快照 / 域绑定，保持结果未定；不新建另一目标、不直接解冻源 |
| 目标已发布、本机未切换 | 重新核对目标状态及原冻结，继续同一次本机切换；不会向两个域发送日常修改 |
| 放弃并回源 | 必须确认目标已停止接收本任务日常写入且未发生新日常提交，再按原冻结身份条件撤销；目标失联或状态未知则停止，不能只解冻源后宣告安全回滚 |
| 已切换或目标发生新日常写入 | 源保持只读 / 保留；回源需新的迁移 / 对账，不能恢复旧快照抹去目标新增事实 |

账号 / 实例 / 恢复代次变化、冻结身份失效、目标被其他写者占用都会使原发布条件失效，保留证据后重新核对。其他设备通过显式授权接入目标，先保全旧域离线修改；旧回调和旧发送队列不得跨域落库。目标导入状态、完成 / 停止身份与发布能力由后续服务契约验证，不把 D-DB 的冻结实验当作已有迁移服务。

## 6. 源服务不可用时

可从可信且完整的本机快照或独立归档迁出。显示最后成功同步时间、快照范围及可能遗漏的其他设备事实，不把未知完整性的副本写成“全部迁移”。

如果只有服务器运维备份而没有账库解锁材料，管理员不能恢复明文。若只有恢复秘密但没有任何数据副本，同样无法恢复交易。

离线迁出是新域的显式分支，无法取得源冻结时不声称源端已停写或两端完整一致。默认不自动双写；必须展示源恢复后可能存在分叉、其他设备需保全旧事实再核对。本地快照也须通过第 3–4 节的完整性与暂存检查，不能以“来自本机”为由跳过候选 / 删除 / 来源验证。

### 6.1 运维恢复的历史来源接口

运维恢复仍属于原安全域，通常只改变 restoreGeneration；用户归档恢复 / 跨实例迁移则建立新的安全域与密钥。不能把两条路径合并为“游标清零重新上传”。域与代次含义见[同步恢复屏障](sync-protocol.md#71-恢复屏障与对账)。

恢复清单至少区分以下信息，这是语义要求，不是冻结的 JSON schema：

- 原始来源：实例 / 账号 / 账库 / vaultGeneration、旧 restoreGeneration、原 operation / revision / envelope 及它们原先的绑定；原字节不可改标签。
- 当前读取上下文：新 restoreGeneration、恢复入口 / 屏障身份、备份切点、继承集合的当前读取基线及后续增量起点；不假造继承项已在新代次重新提交的回执。
- 完整性与未知范围：密文备份中的集合 / 缺口、独立删除控制已重应用的状态、客户端已知旧检查点；服务端清单本身不替代客户端 AEAD / 业务校验，也不能证明恶意服务未隐瞒历史。
- 本地差异：原本未确认、旧代次曾确认但恢复库缺失、仍继承存在、删除或候选不一致；服务器缺失不等于用户删除。

候选对账规则：原绑定及完整内容一致的继承修订只计一次；本地独有事实保留原业务意图，待确定新前置条件后建立新操作；同身份异内容、缺失 parent 或删除证据冲突不能自动选择 / 复活。当前读取 cursor 只有在完整继承集合认证并原子应用后才可进入对应基线，旧确认位置不能直接赋给新 cursor。

映射需要明确认证覆盖、继承批次与新流如何衔接、是否重加密及谁能验证完整性，并与 D-ENVELOPE / D-RECOVERY 一起实证。未冻结前，仅支持规格中的停止与保全要求，不编造可自动续接的示例字节或成功恢复脚本。账号 / 账库删除控制必须在重新开放前应用；旧归档中存在的账号身份不赋予访问已删除远端域的权限。

## 7. 数据删除与离开产品

退出登录、清本机、删远端账库和注销账号分别展示作用范围。检查待同步事实、冲突和备份，提供先导出入口；有丢失可能的动作明确确认。

远端删除撤销访问并进入公开的备份淘汰生命周期。删除身份用于防止旧备份重新开放账号，不含交易内容。已离线下载的副本与用户导出的旧归档无法由服务器远程擦除。

软件升级、卸载说明和本机清理不能把用户数据默认为可以丢弃的缓存。

## 8. 验收

T16–T18 和 T21 覆盖交换、恢复、迁移与删除。至少一次从空白设备恢复、一次从独立服务器恢复，并与[合成账务基线](domain-model.md)逐项比较；仅能解开文件或启动服务不算通过。

独立案例与实施边界见 [E01–E24](validation/portability-cases.md)。数值、选中修订、候选与删除期望复用既有账务 JSON；CSV 交换只验证其声明的投影范围，不能用它的有损结果替代归档保真验收。没有输入材料 / 平台条件的场景标为待执行，不建立默认成功检查。
