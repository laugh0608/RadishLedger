## 2026-10-19 宿主 DB pager 与临时文件边界

### 范围与实现

按项目所有者授权继续 DB pager 短写 / fsync 和临时文件边界，优先不依赖真机 / 认证的宿主工作；沿用工具链，不改锁屏，收口后本地提交且不 push。起点为干净 `dev`，HEAD `8083d1f`、相对本地 `origin/dev` ahead 2；未 fetch。没有启动设备、adb、SDK 或长驻服务，没有改依赖、lockfile、系统设置或生产接口。

新增 `store_pager_tests.rs` 和 `store_test_vfs.rs`，仅由 Unix 宿主的 `cfg(test)` 模块接入。VFS 按锁定 SQLite FFI 契约由本项目编写，原 VFS 仍执行实际磁盘 IO / 锁 / SHM / mmap，所有默认 VFS 注册只发生在独占测试子进程；父进程恢复走普通 `Store::open`。没有复制第三方代码、接入新库或将故障开关暴露给 App。随机合成 key 通过 stdin 传入，报告只存 IO 元数据、计数、版本和合成审计。

pager 先对同一 A11 副本记录成功序列，再按每个实际写入 / 同步调用的序号、类别、长度及偏移注入。部分写入严格少于原请求，原 VFS 实际写入 2–7 bytes 后返回 `SQLITE_IOERR_WRITE`；同步分别在调用前拒绝、原同步成功后返回 `SQLITE_IOERR_FSYNC`。操作返回后不正常关闭连接，由父进程 SIGKILL，验证实际信号并等待退出；父进程重新打开后比较人工账务预期、完整摘要 / 审计和数据库完整性，再用原操作身份重试及重放。

临时工作负载使用 8192 行合成数据、小页面缓存及每阶段明确观测，覆盖 TEMP 表、排序、自动索引、物化查询、大批更新的 UNIQUE / ABORT 回滚、索引创建、VACUUM，以及独立加密附加库的 DELETE 多库提交。附加库只用于 super-journal 证据，不成为生产能力。xClose 前扫描真实打开文件，包含已 unlink 的匿名文件；SHM 另记录实际映射并扫描 sidecar。原 MEMORY 与强制 FILE 对照运行在不同子进程，各自核对完整 A11 保全。
