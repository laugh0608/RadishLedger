## 2026-10-12 协作与仓库治理基线

### 目标与参考

承接正式规划，按项目所有者要求参考 Radish、RadishMind、RadishCatalyst、RadishFlow、RadishAxiom 的根协作、分支 ADR、Ruleset 说明及相关专题 / workflow，提炼通用规则并结合账簿边界重新编写。参考取舍进入 [ADR 0002](../adr/0002-repository-governance.md)；没有复制业务实现、历史卫生预算、平台脚本或将兄弟项目设为运行依赖。

### 完成内容

- 形成协作与仓库治理专题，明确授权持续有效、工作区保护、证据层级、跨仓库只读和文档归位。
- 明确单维护者 `dev` 直接开发、`master` PR 晋级、merge / rebase 合并和禁用 squash，晋级后先快进、否则普通 merge 回流；自动删 head branch 关闭以保留长期 `dev`。
- 补充 `.gitattributes`、忽略规则、行为规范、安全报告、结构化 Issue、PR 影响与回流模板、仓库目标设置和 master Ruleset。
- 重写无第三方依赖的 Python 仓库检查与三个 Shell 入口，覆盖未跟踪文件、文本 / JSON、文档链接、配置契约、忽略产物强制跟踪拒绝、PR 范围和检查器回归。
- 建立只响应 PR / 手动调度的 workflow，`Repo Hygiene -> Candidate Quality` 严格汇总。`.github/` YAML 使用 JSON-compatible YAML 以便标准库完整解析；checkout 固定经官方核对的完整 commit。
- 根入口保持简短且全文一致，README / docs 索引、开发规范、贡献指南与 current 接入治理来源。原 LICENSE、版本及产品 / 技术规格保持不变。

## 2026-10-12 移动端 UI 规范与私人参考保护

### 范围与来源

按项目所有者要求，只在授权范围内观察私人记账界面的布局与交互；整体视觉采用 RadishX family-ui `v26.7.3`。阅读颜色、字体、间距、动效、组件、平台、品牌资产与质量自检，以及相关内部视觉参考和机器 tokens。

私人金融内容、原图、文件清单、原目录路径、指纹或回溯索引不进入项目记录。本轮不分析个人财务，不导入真实账单，不将私人素材上传或用于生图；本文只记一般规则和验证范围。

### 最终规则

- 重写 UI 规格与 ADR 0003，明确快速录入、按日流水、账户选择、月统计下钻以及页面失败状态；产品仍按既有单人 / 单账簿 / CNY 范围。
- 采用暖纸 Workbench、墨字、灰玉品牌与墨蓝操作，财务辅助使用赭石；金融金额与成功 / 危险状态分离，退款、负余额和负净支出不被视觉改写。
- 定义移动端主题、字号 / 数字对齐、间距、圆角、线性图标、触控命中区、单层选择面板、响应式与减少动效。工作面不引入截图封面、金融标识、小票锯齿、条码或纹理图片。
- 基础对比核算发现暗色提亮主操作底不能沿用白字，因此在 Ledger 本地明确深墨前景；可读占位和状态说明采用次文本，不以弱文本掩盖信息。未修改 RadishX。
- 根协作入口、协作专题与 UI 规格明确原图及裁剪 / 打码 / OCR 等衍生材料不进 Git、不公开交付、不上外部服务；后续原型及示例重新使用合成数据。
- 加入私有参考目录的 Git 忽略及源码归档排除，作为误操作保护；素材保持仓库外，规则不构成导入授权。不使用宽泛业务目录忽略隐藏未来实现。
