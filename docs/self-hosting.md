# 自部署与官方托管方案

自部署是需要完整验收的产品交付：安装、连接、备份、升级、故障定位和迁出。本文是交付规格，不是已有可执行安装指南；实施后的命令和资产必须经过真实新实例验证再写入 runbook。

## 1. 部署基线

| 项目 | 第一版目标 |
| --- | --- |
| 组成 | 一个 Go 服务、一个 PostgreSQL，配可信 HTTPS 反向代理 |
| 包装 | 固定版本 Docker 镜像与 Compose 模板，amd64 / arm64 分别构建与验证 |
| 用户模型 | 服务支持账号 / 账库隔离，自部署默认关闭公开注册 |
| 资源起点 | 2 vCPU、2 GiB RAM 作为试验配置，压测后公布实际要求 |
| 网络 | 一个 HTTPS 基地址；数据库只在私有网络，不暴露公网 |
| 持久化 | 明确 DB、实例身份、服务配置和独立备份位置 |
| 依赖 | 无强制官方账号、许可激活、SMTP、Redis、对象存储或推送 |
| 管理 | 受控命令与最小健康检查，不建设可读账务明文的管理后台 |

内网 / NAS 使用同样的 HTTPS 验证边界。私有 CA 可按系统信任机制部署，但客户端不提供忽略证书错误开关；具体设备、证书与网络步骤要分别验收。

服务端资源指标只在固定配置实测后成为支持承诺。amd64 / arm64 支持不代表所有 NAS 型号或所有 Docker 环境已经支持。

## 2. 首次安装流程

1. 检查目标系统、CPU、端口、存储、时间和备份位置。
2. 固定服务 / PostgreSQL 版本，准备最小权限配置与秘密。
3. 建立持久化目录，启动 DB、迁移与 Go 服务，验证 readiness。
4. 用一次性初始化机制创建管理员并关闭 bootstrap。
5. 设置可信 HTTPS，关闭未需要的注册与管理暴露面。
6. 创建个人用户或邀请，在同一官方安装包内选择自部署地址。
7. 完成两端记账同步与一次独立备份恢复。

数据库初始密码、邀请、bootstrap token 和运维凭据不通过普通健康端点返回，不写日志。每步应提供明确失败原因、可恢复状态和重试方式。

部署脚本不能下载并执行不固定的远端脚本，不使用 `latest` 作为升级策略。镜像、依赖 notices 和发行版本需可追踪。

## 3. 发现、身份与兼容

无凭据发现返回实例身份、服务版本、支持协议 / 能力和注册状态，并有长度 / 超时限制，不暴露账号列表、配置秘密或账务。

账号注册、邀请与认证都是实例本地能力，不把官方手机号、账号或外部 OIDC 作为自部署前提。邮箱发送可选；无 SMTP 环境可通过受控管理员操作恢复访问身份，仍无法解密账务。

登录、每个密文请求、变更流、备份管理、删除和设备操作都校验资源归属。只测试单用户正常流程不足以交付官方服务。

支持客户端 / 服务版本的兼容表随发行维护。关键能力缺失、旧 epoch 或格式不兼容时拒绝远端写入，本地继续可用。

## 4. 运维备份与灾难恢复

运维备份包含一致的 DB 密文、身份 / 配置与格式版本、恢复所需服务秘密和校验清单；它不是用户明文归档。备份文件和认证哈希同样需要严格访问控制。

提供停止写入的一致快照或经验证的数据库备份流程。备份至少一份位于另一故障域；同盘复制不防磁盘故障。

官方初始目标为每日备份、保留 30 天并定期独立恢复演练。仅每日快照意味着最近一天服务器变更可能丢失；不能据本机副本宣称零 RPO。RTO 通过实际恢复耗时确定。

恢复流程在独立目标验证备份完整性、版本、配置和迁移，创建新 restore generation，失效旧会话 / 确认身份，然后开放客户端恢复对账。直接还原 DB 文件并继续接受旧队列不算恢复完成。

账号 / 账库删除要求保存在独立的受控删除记录中，恢复旧备份后重新应用，再开放访问。该控制记录只保留执行删除所需的最小身份和时间，不保留账务内容。

## 5. 升级与回退

升级前检查兼容窗口、用户通知、持久化位置和已验证备份；可阻止新写入以取得一致状态。

升级后验证 migration、健康、协议能力、账号隔离及两端提交，结果与新版本关联。不能仅以容器启动证明升级成功。

如果 DB 迁移不可逆，回退必须使用匹配的旧服务版本、备份和恢复代次，不只替换镜像。保留客户端未同步修改，并提供新代次对账路径。

首版不承诺零停机升级或多节点 HA。配置 / 状态迁移需可解释，遇到未知版本不自动重建空 DB。

## 6. 官方服务

官方和自部署使用相同核心服务与协议。官方可增加邀请、运维和配额管理，但不能提供改变密文语义的私有功能分支，也不能接触解锁口令或私钥。

邀请制首版需要单独验收：

- 多账号 / 多账库权限隔离及异常请求；
- 防暴力认证、会话轮换、配额、请求大小和资源限值；
- 备份、恢复、删除控制记录、证书更新和安全升级；
- 状态公告、故障说明与用户导出 / 迁出支持；
- 隐私说明、数据保留期和运营责任。

不在文档中预先把任何域名写成已上线端点。域名、注册方式、实际托管配置与容量随运营任务冻结。

## 7. 可观测性与数据保留

只记录版本、健康、DB 连接、错误码、延迟、资源量和必要审计。禁止记录解锁材料、token、请求密文正文和业务明文。

目标初始保留：业务恢复备份 30 天、常规运维日志最多 14 天、安全 / 删除控制记录按用途单独制定。具体值在 M3 隐私与运营评审冻结，自部署可按公开边界配置。

健康检查不承担业务修复。磁盘不足、DB 不可用、配额超限和证书问题要区分；不能返回成功后再丢弃密文。

## 8. 交付清单

实际发行需包含安装、HTTPS / 内网、邀请与身份恢复、备份 / 独立恢复、升级 / 回退、迁出、故障诊断和支持版本文档，并完成 T13、T15、T19–T22 的相应目标验证。

部署、长期服务、系统配置和真实用户数据操作需有对应任务授权；规划文档本身不授权启动服务或操作生产实例。
