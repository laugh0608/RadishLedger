# 能力专题与实施验收地图

整体范围与 R01–R12 定义以[产品规划](product-scope.md#4-第一版公开-mvp)为准；M0–M3 顺序、出口及 T01–T23 发布验收以[MVP 路线图](mvp-roadmap.md)为准。本页仅登记能力归属和阅读链，不重定义需求、复制共同案例或建立第二份任务状态表。

## 层级与进度来源

- 整体规划描述用户目标、范围、阶段依赖与出口。
- 大专题是跨阶段能力；下表为每个 R 编号指定一个主要归属，其余关系通过协同表达。
- 子专题复用现有正式文档或稳定章节。M0-A–M0-E 是风险验证工作包，D-* / E-* 是实施任务，A / B / C / S / E / T 编号继续表示各自案例或验收，不重新编号为另一套专题。
- current 维护阶段判断、跨专题接续顺位与阻塞；任务的详细范围、局部实施结果与案例分别留在原矩阵 / 案例章节，历史运行证据留在 devlog。地图只链接来源，不同步数值或逐项执行状态。

任务可分期交付，但“规格可评审”“宿主实验通过”“设备验收完成”和“生产交付”不能互相替代；M0 工作包取得部分证据不等于 M0 退出。当前阅读从 [current](status/current.md#接下来的事项)进入子专题，了解全局则从产品范围、路线图进入本页。

## 大专题与需求归属

| 大专题 | 主要需求 | 能力边界与权威设计 | 阶段 / 协同 | 目标范围完成条件 |
| --- | --- | --- | --- | --- |
| 账务核心与本地可靠性 | R03、R04、R05、R06 | [领域模型](domain-model.md)、[本地事务](architecture.md#3-本地事务与生命周期)：金额、日期、有效修订、账户分类、统计与本地事实保全 | M0-A / M1，后续同步与迁移复用同一账务语义 | 原数值案例、原子性与重启恢复成立；余额派生，不能靠同步成功代替本地提交 |
| 移动端体验与核心接入 | R01 | [移动体验](design/mobile-experience.md)、[分层架构](architecture.md#1-分层与数据路径)：双端主流程、桥接与生命周期 | M0-A 的 UX、M0-B、M1 Android / M2 iOS；协同所有业务主线 | 两端真实发行构建和主路径各有证据；模拟器、宿主与真机分列 |
| 隐私、密钥与恢复保护 | R08 | [威胁模型](privacy-threat-model.md)：本地加密、E2EE、解锁、系统保护、独立恢复材料与安全重建 | M0-C 至 M3；同步与归档共享经评审的身份 / 密钥边界 | 错误、取消、密钥不可取与独立恢复通过，真实硬件 / 生命周期未验不能冻结支持面 |
| 连接与多端同步 | R02、R07 | [同步方案](sync-protocol.md)：连接域、CAS、幂等、冲突、删除与恢复代次 | M0-D / M2 / M3；账务、隐私、可迁移与运维协同 | 客户端、envelope、真实事务与双端闭环分别成立；D-DB 不代替生产同步 |
| 数据交换、归档与迁移 | R09、R10 | [可迁移性](data-portability.md)：CSV、受限撤销、完整快照、认证容器、暂存恢复与空目标迁移 | M0-E / M1 / M3；依赖账务独立预期、隐私与 D 的恢复接口 | 原 E 案例及对应 T 验收覆盖预览、失败、中断与保真；CSV 不能冒充完整归档 |
| 服务交付与运维生命周期 | R11、R12 | [自部署](self-hosting.md)、[离开产品](data-portability.md#7-数据删除与离开产品)：服务授权、兼容、升级、运维恢复与删除控制 | M2 自部署 / M3 官方及公开交付；协同同步、隐私与迁移 | 实际端点、干净安装 / 独立恢复、版本失败与删除重应用分别验收，不预建未授权服务 |

R01–R12 的原定义保持唯一来源；本表是归属映射，不改变 MVP 范围。治理、许可和依赖审查是各主线共同约束，沿用原专题，不新增产品能力。

## 近期任务的读取链

接续顺位以 current 为准，以下仅说明归属与关闭依据。

| 接续项 | 牵头 / 协同 | 标准与证据入口 |
| --- | --- | --- |
| E-CSV 受限撤销 E07 | 数据交换、归档与迁移；账务、隐私协同 | [E 案例](validation/portability-cases.md#2-csv-输入批次与导出)、[局部验证入口](validation/portability-cases.md#53-e-csv-受限撤销候选)及[current](status/current.md#接下来的事项)：原修订重检、备注编辑竞争、取消 / 强杀恢复、重复撤销与重导防复活；尚不能判定的依赖保持阻塞 |
| E-SNAPSHOT 最小一致快照 | 数据交换、归档与迁移；账务 / 同步协同 | [只读候选](validation/portability-cases.md#54-e-snapshot-最小一致逻辑快照候选)、原 E 任务表与 current；保全事实、修订、候选、删除、来源、原意图及导入 / 撤销任务，不把摘要或原 DB 文件当归档 |
| Android 人工流程补验 | 移动端体验与核心接入；隐私主线协同 | current 第 3 项与设备操作单；ADB 信任条件恢复后按精确授权取证，iOS / 宿主结果不替代 |
| 两端真机 release | 隐私、密钥与恢复保护牵头；移动主线协同 | current 第 4 项、B / C 矩阵和设备操作单；保留真实认证、保护、重启与资源缺口 |
| M0 选型与退出评审 | 移动端体验与核心接入牵头整合，六条主线协同 | current 第 5 项及路线图 M0 出口；真实证据齐备后冻结对应 ADR，再安排 M1，不从文档整理宣布退出 |

任务执行结果仍写回对应原任务 / 案例与 devlog，由 current 引用。金额 JSON、S / E 案例与冻结边界仍由原来源维护；本页只维护读取关系。
